# 七关节直接遥操作 + 左扳机比例夹爪

独立入口 `run_arm7_direct_gripper.sh`，共用原七关节状态机。
原 `run_arm7_direct.sh` 和记录入口不会启用夹爪。
新入口沿用两次确认、限位/速度保护、无碰撞检查、互斥锁和默认 +104ms 时钟补偿。

## 运行

`--seconds` 支持1～600秒，默认30秒；从首次进入慢速对齐开始计时，暂停也计入。

先只读检查（不向机械臂或夹爪发送运动指令）：

```bash
bash teleoperation/run_arm7_direct_gripper.sh --seconds 120 \
  --start-control left-button --align-speed-rad-s 0.4
```

现场运动验证：

```bash
bash teleoperation/run_arm7_direct_gripper.sh --execute --seconds 120 \
  --start-control left-button --align-speed-rad-s 0.4
```

1. READY 后按左固定键进入慢速对齐，此时夹爪不响应扳机。
2. 全部误差 <3° 后，再按左固定键进入 FOLLOWING。
3. 松开左扳机（axes[3] ≥0.66），看到“左夹爪已就绪”。如果已松开，会自动完成此步；只解锁不立即发指令，之后开始趋向张开目标。
4. 按得越深夹爪越闭合，松开逐渐张开。启动时一直扣住扳机不会闭合，必须先松开。
5. 再按左固定键暂停：机械臂停止，夹爪尝试保持当前开度。重新启动需重新走两次确认，并再次松开扳机。

只读模式显示扳机数值和真实夹爪开度；需要真实主从差 <3° 才能进入 FOLLOWING，不能靠只读模式自动对齐。
日志写入 `lerobot_runs/arm7_direct_gripper_*.jsonl`，包含配置、原始扳机、夹爪反馈、目标、RPC结果及保持结果。
旧版真机日志已确认SDK接受指令并有开度变化；本次直接开度目标策略仅完成离线验证，跟手性、夹持力及停止效果仍待现场验证。

## 映射与参数

本项目辨识证据：`GP001_IDENTIFICATION_20260910.md`，左扳机 `action_list.axes[3]`，释放0.7、按到底0。
比例 = clamp((axes[3] − 0.04) / (0.66 − 0.04), 0, 1)。
目标开度 = closed + (open − closed) × 比例。
读数≤0.04对应完全闭合，≥0.66对应完全张开，0.35仍对应半开；端点死区覆盖实测扣到底约0.031的读数。

| 参数 | 默认 | 本实验允许范围 |
|---|---:|---|
| --gripper-open-m | 0.10m | closed < open ≤0.12m |
| --gripper-closed-m | 0m | 0 ≤ closed < open |
| --gripper-speed-m-s | 0.02m/s | (0,0.05]m/s |
| --gripper-effort | 5 | SDK effort 参数，(0,5] |
| --g1-clock-offset-ms | +104ms（shell入口） | 人工测得的 G1系统时间−PC系统时间 |

每50ms最多更新一个夹爪目标，直接发送映射出的最终开度，由SDK速度参数控制运动速度。
已移除每步1mm及目标领先反馈1mm的限制；保持相同扳机位置不重复发送，小于0.2mm的目标变化过滤，端点变化仍精确发送。
默认速度仍为20mm/s，100mm全行程理论上至少5秒，并非瞬时到位；实际速度受硬件和负载影响。
指令使用 SDK `set_gripper_command('left_gripper', width, speed, effort, False)`，不等待到位。
以SDK接口声明为准，不把 effort 数值等同于已经测得的指尖夹持力；本地示例和类型存根的单位表述存在差异。
不设置右夹爪，不把扳机动作码转换为额外开关指令。

## 异常和停止行为

扳机缺失、非有限或超出[0,0.7]，夹爪反馈缺失/非法/过期/倒退/300ms未推进，或指令返回失败，均结束本轮并进入停止清理。
夹爪反馈使用与机械臂相同的固定时钟补偿，年龄要求[-100,+300]ms；提交前再次检查。
GP断流、固定键停止、软件急停、Ctrl+C和时限结束后，不再发送正常夹爪跟随目标。

SDK未提供独立 `stop_gripper` 接口。清理时仅在夹爪反馈有效的情况下，发送一次“当前实测开度”保持请求；
即使保持失败，也仍尝试机械臂停止。日志 `gripper_hold_acknowledged` 只代表SDK接受，**不代表夹爪已确认停稳**。
若反馈失效则不根据旧位置发保持指令；之前发出的最终开度目标可能继续执行（包括完整闭合/张开），不再只有1mm余量。保持失败时应现场使用物理急停，软件流程不能代替硬件急停。

现场先检查空载小范围开合、半按映射、固定键暂停及急停。确认无误后再验证夹物；当前脚本仍无碰撞检查。

## 主臂越界与二次确认（2026-09-21）

已经启动的 ALIGNING、ALIGN_READY、FOLLOWING 阶段，主臂映射目标越界时，按每关节保守限位截断目标，继续遥操作。
例如 J7 主臂达到60°，有效目标保持45°；回到40°后有效目标恢复40°，仍受原速度限制，不积累越界位移。
终端显示有效目标，并单独列出“原始目标 → 限幅目标”；日志保留 raw_target、target 和 clamped_joints。
启动前仍要求主从都在范围内、误差<15°。从臂实测越界保护（沿用原0.02rad容差）、超速、15°轨迹偏差、断流和时间戳保护保留。
该行为也应用于共用控制循环的 arm7_direct 和 arm7_record 入口，碰撞版入口不变。

在 ALIGN_READY 收到有效二次确认，但SDK本轮只返回重复帧时，最多等待该按键发生后300ms内的新反馈再提速。
等待期间仍须保持全部有效目标与实测差<3°；误差变大、确认过期或反馈异常时不会提速。
提前于就绪的点击不会被缓存；固定键需松开至少30ms才识别下一次按压。

2026-09-22：共享夹爪参数校验上限更新为SDK声明的0.2m/s；本入口默认速度不变。单次确认双臂入口默认0.16m/s。
