## Combined navigation CLI

`s1_navigation_cli.py` provides two guarded subcommands for the managed S1 host
SDK environment:

```bash
/home/galbot/ie_lab/bin/s1-python s1_navigation_cli.py pose

/home/galbot/ie_lab/bin/s1-python s1_navigation_cli.py \
  diagnose-localization --timeout 10 --interval 1

/home/galbot/ie_lab/bin/s1-python s1_navigation_cli.py relocalize \
  --x 0.2 --y -0.2 --yaw -0.5 --observe 10 --interval 1 --execute

/home/galbot/ie_lab/bin/s1-python s1_navigation_cli.py probe-relative \
  --direction forward --checks 3

/home/galbot/ie_lab/bin/s1-python s1_navigation_cli.py payload-status-4317

/home/galbot/ie_lab/bin/s1-python s1_navigation_cli.py \
  payload-register-4317 --execute

/home/galbot/ie_lab/bin/s1-python s1_navigation_cli.py navigate \
  --x 1.0 --y -1.0 --yaw -1.0 --omni-plan true --execute

/home/galbot/ie_lab/bin/s1-python s1_navigation_cli.py relative \
  --x 1.0 --y 0.0 --yaw 0.0 --omni-plan false --execute

/home/galbot/ie_lab/bin/s1-python s1_navigation_cli.py relative \
  --x 1.0 --y 0.0 --yaw 0.0 --omni-plan false \
  --add-bounding-box --attach-box-to-link --execute

/home/galbot/ie_lab/bin/s1-python s1_navigation_cli.py \
  payload-remove-4317 --execute
```

The CLI acquires `/home/galbot/ie_lab/control.lock` itself.  Navigation always
uses `navigate_to_goal_v2`, v2 collision checking, three stable static-path
checks, and a maximum-distance guard.  `navigate` uses
`pose_frame="map"`; `relative` uses `pose_frame="base_link"`.  Both accept
`--omni-plan true|false` (default `true`) and deliberately expose no option for
disabling collision checks.

Both motion commands submit with `is_blocking=false`, then poll pose,
`get_navigation_status()`, and `check_goal_arrival()` every 0.20 s in Python.
They emit a compact progress event approximately once per second.  SIGINT
(`Ctrl+C`) and SIGTERM are handled in the polling loop: the first signal calls
`stop_navigation()`, ignores repeated signals during cleanup, and waits up to
5 s for navigation status to leave `RUNNING`.  Timeout follows the same bounded
stop-and-confirm path.  The SDK-session cleanup retains a second stop attempt
if termination was not confirmed.

The CLI contains no runtime `input()` prompt.  Every command that changes
fusion/PNS/localization state or can cause physical motion must include
`--execute` in the original invocation.  Omitting it fails closed before SDK
initialization.  Read-only `pose`, `diagnose-localization`,
`payload-status-4317`, and `probe-relative` do not accept or require the flag.

The three `payload-*-4317` commands use profile
`4317_left_mount_20260831_193312_191`, derived from the successfully executed
lift target in that run and the current S1 GE103v1 mount-to-TCP geometry.  The
fusion filter is `0.60 x 0.50 x 0.375 m`, while the PNS collision body keeps
the measured `0.40 x 0.30 x 0.175 m` physical envelope.  Both use tag `4317`
and the same pose relative to `left_arm_end_effector_mount_link`:

```text
[0.088464545899, -0.209262726967, -0.158900000000,
 0.011116385395, -0.000386121234, 0.697301150147, 0.716691972112]
```

The left-mount parent makes the registered box follow base, torso, and arm TF
updates while the recorded crate-to-left-mount transform remains rigid.  It is
not valid after slip, release, regrasp, or a changed grasp geometry.

`payload-register-4317 --execute` first verifies that the parent frame exists and that a
finite `base_link <- left_arm_end_effector_mount_link` transform is available.
It then calls `add_bounding_box()`, verifies tag `4317` through
`get_bounding_box()`, and
compares the returned size, position, orientation, and parent link against the
expected profile before calling `attach_box_to_link()`. If verification or
attachment fails with a status other than `WAIT_INITIALIZED`, it immediately
attempts to roll back the fusion filter. `WAIT_INITIALIZED` is treated as the
documented transient PNS-readiness state: the CLI retries every 0.25 s for at
most 5 s. If PNS still is not ready, it removes the filter and verifies through
`get_bounding_box()` that tag `4317` disappeared. The structured result records
every attach attempt, the final return, and whether rollback was verified.
Registration is intentionally retained while the crate is physically held. After navigation
has stopped and the payload no longer needs navigation modeling,
`payload-remove-4317 --execute` calls both
`detach_box_from_link()` and `remove_bounding_box()` and verifies that the
fusion filter disappeared. These commands do not switch a controller or send
base, arm, gripper, or lift motion; they do change fusion/PNS navigation state.
The current public SDK can query registered fusion filters but does not expose
an equivalent attached-object list, so attachment is verified only from the
SDK call result.

`navigate` and `relative` also accept the explicit paired switches
`--add-bounding-box` and `--attach-box-to-link`. Neither is enabled by default,
and supplying only one fails before SDK initialization. Supplying both requires
tag `4317` to be absent at command start; an existing tag fails closed even if
its fusion profile matches, because the public SDK cannot prove that the PNS
attachment still exists. With an absent tag, the same locked SDK session checks
localization and evaluates the distance guard before changing payload state. It
then checks navigation idle state and the left-mount TF, adds and fully
verifies the fusion filter, attaches the collision box, runs the three
reachability checks, and only then submits non-blocking navigation. The
registration remains active after success, failure, timeout, or operator stop
until `payload-remove-4317 --execute` is run.

The pre-readiness-retry CLI is preserved as
`s1_navigation_cli.py.before_pns_attach_ready_retry_20260902`; its SHA-256 is
`7bc3cc5631955c2977a747eb219baceb495d7504e22bdce879917d977d07e4fa`.
The backup is local only and has not been deployed or executed on S1 by this
update.

`diagnose-localization` stays in one SDK session and samples localization,
map pose (only while localized), and navigation status for a bounded period.
It does not switch controllers, call `relocalize()`/`stop_navigation()`, or send
any navigation command. `query_ok` reports whether observation completed;
`navigation_ready` separately reports whether the final sample has a valid map
pose.

`relocalize` is a guarded localization-state change, not a motion command. It
refuses to run while navigation reports `RUNNING` or `OCCUPIED`, previews the
exact map-frame estimate, requires `--execute` in the original invocation,
calls `relocalize()` once, and then performs bounded read-only observation. A
successful SDK return is not enough: the command reports success only when the
final sample is localized with a finite map pose. An approximate pose must not
be treated as ground truth for subsequent navigation without physical/map
validation.

`probe-relative` is query-only. It transforms a bounded set of relative
`base_link` offsets into map goals and repeatedly calls
`check_path_reachability()` without switching controllers, prompting for
motion, changing bounding boxes/attachments, or submitting navigation. The
default scan covers forward distances from 0.10 to 1.20 m and classifies each
target as stably reachable, stably unreachable, or mixed.
