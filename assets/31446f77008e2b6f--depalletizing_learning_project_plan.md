# S1 拆垛学习与项目计划

制定日期：2026-08-20
适用对象：机器人基础接近零，希望在已有 S1 工程上逐步参与开发
当前目标物：4317 箱体，H4 层，Mode 00 双臂抓取

## 1. 总目标与边界

目标不是从头重写拆垛系统，而是：

1. 能说明现有链路每个模块的输入、输出和坐标系；
2. 能安全地复现离线感知、目标生成和轨迹规划；
3. 能读懂一次真实运行的产物并判断失败发生在哪一层；
4. 在充分验证后，参与补齐当前未完成的 `put/down` 放置阶段；
5. 最终形成可重复、可追踪、能安全失败的单箱闭环。

当前 S1 文档记录的主链路是：

```text
左右腕 RGB-D
  -> Thor SAM3 分割
  -> LingBot-Depth
  -> 4317 ROI / H4 目标选择
  -> 工作站 FoundationPose++
  -> 左右 TCP 抓取目标
  -> IMC 规划
  -> Galbot SDK 执行
  -> 合爪、抬升、携箱导航、释放、返回
```

当前不是从“如何让机械臂随便动一下”开始，也不直接运行一键流程。学习顺序是：

```text
读状态 -> 懂坐标 -> 离线计算 -> 只规划 -> 审查轨迹 -> 分步实机
```

## 2. 安全等级

### L0：文档与源码阅读

- 不连接机器人；
- 不启动容器或服务；
- 不运行项目脚本；
- 可以阅读代码、配置、日志和历史结果。

### L1：离线计算

- 使用已有文件作为输入；
- 可运行不导入控制接口的解析、几何、可视化和测试；
- 输出只能是报告、图像、目标或轨迹文件；
- 不连接 SDK、DDS、ROS 控制器。

### L2：实时只读

- 读取机器人状态、相机、定位或服务状态；
- 不设置模式，不附加工具，不规划执行，不控制夹爪；
- 每次远端访问仍需当前任务明确授权。

### L3：规划但不执行

- 可以基于当前状态生成 FK、IK、碰撞和轨迹报告；
- 必须确认 `direct_execute=false` 或等效保护；
- 轨迹需人工检查关节限位、碰撞、TCP 路径和目标语义。

### L4：真实运动

- 每一个动作都需要新鲜、逐步确认；
- 确认具体设备、目标、方向、速度、工作空间、碰撞风险和急停；
- 一次批准不延续到下一动作；
- 优先单设备、低速、小范围、可立即停止的实验。

## 3. 十个里程碑

### M0：建立项目地图

学习：

- S1 本体、Thor、FoundationPose++ 工作站分别运行什么；
- `s1_sjtu_0806`、IMC、Galbot SDK、数据目录之间的关系；
- 配置、运行快照、日志、结果文件的区别。

实践：

- 画一张部署图；
- 给每个模块写出输入、输出、运行主机和是否可能触发运动；
- 找出 Mode 00 主入口和 `--dry-run`/`--execute` 分界。

验收：能在不看提示的情况下讲清一次抓箱的数据流和控制流。

### M1：Python、Linux 和日志阅读基础

学习：

- Python 函数、类、列表、字典、异常和命令行参数；
- YAML、JSON、CSV；
- 绝对路径、环境变量、退出码、标准输出和日志；
- Git 的提交、工作树和 SHA 概念。

实践：

- 解析一份 `RESULT.txt` 和一个 JSON 运行产物；
- 写一个只读脚本，汇总 run 的阶段状态；
- 不接触机器人接口。

验收：能区分“程序成功退出”“规划成功”“命令执行成功”和“任务语义成功”。

### M2：SDK 状态与设备模型

学习：

- 左臂、右臂、GE103、躯干升降、底盘和腕部相机；
- 关节名称、自由度、位置、速度、力/反馈；
- SDK 初始化、状态读取、生命周期；
- 为什么 `zero`、`home`、初始姿态和安全姿态不是同一概念。

实践：

- 阅读 `sdk.py` 的被动 RGB-D/状态采集；
- 标出每一个 SDK 调用，分类为读取、配置或可能运动；
- 为未来只读检查建立 API 白名单。

验收：看到一段 SDK 代码时，能判断它是否可能引发实体动作。

### M3：机械臂几何与坐标系

学习：

- 关节空间与笛卡尔空间；
- 位姿、旋转矩阵、四元数和齐次变换；
- `base_link`、相机、箱体、`left_TCP_link`、`right_TCP_link`；
- FK、IK、TCP、工具偏移、关节限位和奇异位形。

实践：

- 用纸笔和小型 Python 示例完成坐标变换；
- 读取一个历史捕获中的 `base_from_camera`；
- 离线复算“相机中的箱体点 -> base_link 中的目标点”；
- 运行或复核同位姿 FK/IK，不执行运动。

验收：能解释 FoundationPose++ 输出为什么不能未经变换直接发送给机械臂。

### M4：RGB-D 与三维感知

学习：

- RGB、深度、内参、外参、点云；
- mask、ROI、深度缺失和有效点；
- SAM3、LingBot-Depth、FoundationPose++ 的职责边界；
- 6D 位姿、mesh 尺度、置信度和失败模式。

实践：

- 选择一份历史 run；
- 依次查看原图、深度、mask、ROI、FDP 输入输出；
- 将箱体坐标轴投影回图像或点云；
- 故意检查错误 mask、深度空洞和尺度错误会造成什么结果。

验收：能判断一次感知结果是“看错箱子”“深度错误”“位姿轴错误”还是“坐标变换错误”。

### M5：从物体位姿到双臂抓取目标

学习：

- Mode 00 抓取几何；
- 左右 TCP 的接近方向和对称关系；
- 预抓、内收 100 mm、合爪、抬升 100 mm；
- 历史操作员修正为什么不是通用绝对位姿。

实践：

- 从历史 FDP 输出离线生成左右预抓目标；
- 将目标可视化；
- 检查左右臂间距、箱体尺寸和接近方向；
- 比较 fresh perception 与记录校准量的组合方式。

验收：能逐字段解释一个双臂 target JSON，并发现明显的轴、单位或左右手错误。

### M6：IMC、轨迹与碰撞检查

学习：

- FK/IK、PTP、LIN 和轨迹采样；
- IMC 计算模块与真实 executor 的边界；
- 机器人模型、GE103 工具体积、环境碰撞和自碰撞；
- `check_collision=false` 为什么不构成安全证明。

实践：

- 读取一份历史 IMC plan；
- 绘制关节随时间变化；
- 检查首点与当前状态衔接、关节限位、最大步长和终点误差；
- 形成一个“轨迹人工审查清单”。

验收：能够签字式回答“这是一条数学上有解的轨迹，还是一条具备执行安全证据的轨迹”。

### M7：抓取事务与失败恢复

学习：

- 开爪、预抓、内收、合爪、确认接触、抬升；
- 每个阶段的前置条件和后置条件；
- 超时、空抓、滑落、左右夹爪不一致；
- 为什么 SDK `SUCCESS` 不等于抓取语义成功。

实践：

- 从历史日志构造阶段状态机；
- 列出每一步失败后的安全停止状态；
- 暂不把 `effort=1000` 解释为物理夹持力；
- 设计 GE103 静态标定实验方案，但不执行。

验收：任何一步失败时，都能明确“禁止继续什么、允许读取什么、需要谁确认什么”。

### M8：放置 `put/down` 专项

这是当前工程主缺口，不应直接从实机试错开始。

学习与设计：

- 卸货平台表面高度如何测量和记录；
- 箱底、TCP、夹爪接触面的几何关系；
- 预放置、下降、接触/高度门、开爪、撤臂；
- 负载状态下的碰撞体和双臂同步；
- 放置失败时箱子可能处于哪些危险状态。

实践顺序：

1. 静态几何计算；
2. 历史数据上的目标生成；
3. 可视化与碰撞检查；
4. 空载、无执行的规划；
5. 现场测量与人工复核；
6. 获得逐步确认后，才设计低速分段实机验证。

验收：放置目标来自测量和模型，不来自“猜一个高度”；所有阶段都有停止门和恢复策略。

### M9：单箱闭环与工程化

目标：不是偶然成功一次，而是可复现。

需要完成：

- 感知、抓取、运输、放置、撤臂、返回完整闭环；
- 运行源码和镜像对应到可解析 Git SHA；
- 每次实验保存配置、输入、输出、日志、操作者和结果；
- 连续多次测试成功率和失败分类；
- 明确禁止自动恢复的状态。

验收建议：先定义小规模验收，例如连续 5 次受监督单箱任务，所有成功或失败均可解释、可安全停止，再讨论多箱和复杂货垛。

## 5. 第一周具体安排

### 第 1 天：系统地图

- 阅读本地知识库和 S1 交接文档摘要；
- 画出 S1、Thor、FDP 工作站和服务端口；
- 标注数据流与控制流。

### 第 2 天：主工程地图

- 认识 `src/`、`scripts/`、`tools/`、`config/`、`docs/`；
- 标记哪些文件只计算，哪些文件可能执行；
- 找到 Mode 00 主入口。

### 第 3 天：读一次历史运行

- 从 `RESULT.txt` 开始；
- 找到对应运行目录；
- 按时间顺序列出感知、目标、规划、执行产物；
- 解释 `put_executed=false`。

### 第 4 天：Python/JSON 小练习

- 本地写一个 run 汇总器；
- 只读取文件；
- 输出每阶段是否存在、状态和关键路径。

### 第 5 天：SDK 被动采集代码

- 阅读 `PassiveSensorProbe` 和 `PassiveRGBDCapture`；
- 标出读取的相机、关节状态、内参和变换；
- 确认没有目标或执行调用。

### 第 6 天：坐标系入门

- 学习三维点、旋转矩阵和 4x4 变换；
- 用一个简单二维/三维例子手算；
- 再对应 `base_from_camera`。

### 第 7 天：复盘

- 用自己的话讲完整链路；
- 写下仍不理解的十个问题；
- 共同确定第二周重点。

## 7. 当前明确禁止的捷径

- 不直接运行 Mode 00 一键真实流程来“看看会发生什么”；
- 不把历史绝对位姿当成当前箱体目标；
- 不以 `torso=0`、`home` 或旧快照猜测恢复位置；
- 不把无碰撞检查的 IMC 路径当作安全轨迹；
- 不把夹爪 `effort=1000` 当作已标定物理力；
- 不在运行容器中临时修改生产源码；
- 不在未测量卸货高度时尝试 `put/down`；
- 不让两个程序同时拥有机器人控制权。
