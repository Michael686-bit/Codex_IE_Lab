# 左臂七关节：后台预检与固定键控制

入口：run_arm7_follow_collision.sh → arm7_follow_collision.py → arm7_runtime.py。

## 操作流程

1. 启动后LOCKED（锁定），持续显示GP001/G1七关节角度，并在条件满足时后台查询碰撞。
2. 对齐、限位、静止与碰撞预检通过后READY（就绪），提示“单击左固定键开始”。
3. 单击后STARTING，用最新状态再做一次非阻塞碰撞复核，通过后FOLLOWING（跟随）。不需要回车二次确认。
4. FOLLOWING或STARTING时再次单击，优先取消开始授权、请求停止并确认停稳；锁定后重新预检，绝不自动恢复。
5. 就绪前的点击不排队；长按不重复切换；锁定后要松开按钮再重新单击。
6. 就绪结果过期、状态变化或碰撞时撤销就绪。跟随中拒绝目标则停止锁定；进程退出/超时等不可恢复故障停止并退出。

停止不等待碰撞子进程。锁定只表示停止轨迹并保持原有控制器，不是机械制动或释放关节。

## 左／右急停键（软件急停）

- 官方G1仿真示例定义action_list.buttons中-1为STOP。左右实体急停键只要输出该码，都进入同一软件急停路径；原始button_state索引尚未确认，不猜测索引。
- 输入线程首先读取STOP，再解析固定键和关节数据；首次STOP永久锁存到本轮结束，松开、RESUME=0或固定键都不能清除。CHASSIS_STOP=10不当作急停。
- 急停优先于开始、固定键、碰撞结果及运动发布。取消会话授权与待发目标，执行模式依次调用stop_trajectory_execution()和stop_base()，两项均尝试后才观察停稳。
- 不释放控制器、不发送回零、不关闭关节使能；停止后依靠原控制器保持姿态。软件请求无法保证物理急停效果，仍需现场验收。
- 通过21个关节推进的新鲜反馈确认静止；底盘当前只记录stop_base返回成功，没有独立确认底盘静止，日志明确base_stationary_verified=false。
- 急停后本轮结束，若需恢复必须重新启动脚本、重新预检并手动单击。进程启动时仍有STOP，则不能开始。
- --controls-only或无--execute的只读模式只记录和模拟急停，不向G1发送停止命令。

采集验证：运行上述--controls-only命令后，先松开所有键，再依次单击左急停、松开、单击右急停、松开（各间隔2秒）。
两次都应看到“检测到软件急停 STOP=-1”；日志记录action_buttons、原始18项button_state和emergency_stop。左右实体键响应尚待本次验证。

## 参数

- 左臂J1～J7映射在arm7_collision_profile.json中，当前+1方向、比例1、零偏0是待验收候选。
- 起步每关节差值≤15°；七关节目标斜率限速0.3rad/s，轨迹段100ms。
- J7绝对[-45°,45°]；其余关节URDF内缩3°；限位与碰撞拒绝不受15°阈值放宽影响。
- 全身反馈必须有效；使用推进的新帧确认速度≤0.002rad/s、漂移≤0.05°、持续静止0.5秒。
- GP001输入线程记录取帧单调时间，300ms无新鲜输入拒绝。
- 碰撞结果绑定请求ID、会话代次、全身状态、GP目标、底盘位姿与创建时间；结果有效期不超过300ms。
- 就绪/开始复核期间全身允许变化0.05°、GP目标0.25°、底盘七维位姿各分量0.001；不符合则撤销授权。
- 正在运动时左臂反馈变化使用运行偏差界限，其他关节仍严格检查。参数与完整停止距离尚需真机验证。

## 控件采集

```bash
bash teleoperation/run_arm7_follow_collision.sh --controls-only --seconds 30
```

不连接G1、不执行机器人SSH预检。松开1秒，左固定键单击松开三次（间隔1秒），再长按2秒松开。
候选信号button_state[4]：2松开、3按下；三次单击应计3，长按只增加1。
原始18项按钮、action_list.buttons、设备时间戳、主机取帧时间及点击计数写入JSONL。
这是已有辨识记录的候选信号，需实物重复采集确认。未知值（例如1）不会被当成点击：锁定状态继续预检并记录button_fault；跟随状态收到未知值会先锁定，不继续发送目标。

## 实现与验证范围

- collision_worker.py：spawn独立进程，原生SDK查询无法阻塞主控制循环；300ms查询超时、10秒初始化超时，报错后禁止放行。
- teleop_input.py：独立线程持续取帧；最新关节帧与按钮事件分开保存，已捕获的短点击不会被后续松开帧覆盖。32条按钮积压视为故障。
- 路径检查包含实测→轨迹起点→目标的中间采样，最大单轴采样间隔0.25°。离散采样和状态容差不是连续无碰撞或停止距离的证明。
- 场景清单在子进程初始化后固定；变化即拒绝。同名障碍物的几何改变不能仅靠清单识别，运行中不得由其他客户端修改场景。
- 没有自动加入桌面/墙壁/工具，也未解决之前持续返回碰撞的问题。
- 状态机、无点击不启动、提前点击不排队、单击停止、锁定后重新预检不自动恢复、查询卡住期间停止、输入点击保留均有模拟回归测试。
- 本轮原生子进程验证停在GalbotRobot初始化超时，尚未完成这版硬件闭环验收。按钮不能替代物理急停。
