二、允许使用的技术手段
选手需要在训练时同时满足以下两个标准：
① 数据来源：全部来自 RoboTwin release 资产（clean 演示 + 任务定义/指令池），不经环境渲染或交互产生新数据；
② 学习方法：保持在 BC（模仿学习）框架内，监督信号严格来自 demonstration 本身。

2.1 数据处理类
手段	说明
视觉增广（训练期）	对输入图像施加亮度、颜色等噪声扰动
机器人状态扰动（训练期）	对机器人状态信号施加扰动
训练机制内部噪声	模型训练机制自身噪声（如 diffusion 加噪—去噪），前提是不额外生成 demonstration
演示数据质量过滤	基于 jerk / Z-score 的低质量轨迹剔除，属"改进数据处理方式"
seen 池内指令替换	同一 clean 轨迹的语言指令随机替换为本任务 seen_instructions 池中其它指令——指令为 release 资产、零环境调用、（指令,轨迹）配对数不变、学习方法仍为 BC
按数据统计量重加权	以轨迹时长、jerk、平滑度、能量等数据自身统计量作为样本权重或过滤阈值（BC 框架内）
样本权重与过滤阈值的计算，以 demonstration 数据本身的统计量为限；

2.2 模型结构类
大幅度结构改造	允许，唯一要求为主干自 LingBot-VLA 2.0 初始化；无必须保留模块清单，无参数比例要求；
公开预训练模块	允许引入其它公开 vision encoder、depth/segmentation encoder 等模块与权重；须在 README 注明来源及使用方式；公开预训练模块以公开社区资产为限，官方点名禁用之资产不适用本项；
LoRA 微调	允许上传 LoRA 合并回基座的全量权重；须在 Config/README 说明。
2.3 训练策略类
优化器与学习率策略、归一化统计方式、动作表示、损失函数、训练期 EMA（最终权重平均，产出仍为一份权重）等，均属"训练参数/训练策略"范畴。基座自蒸馏，及以参赛方自训权重为教师之蒸馏，监督信号未引入 clean demonstration 以外之信息，属本项允许范围。

2.4 推理策略类（单一权重内）
在"单一权重、不依赖任务信息路由"前提下的推理参数与策略调整，属"推理策略"范畴。允许范围包括：

动作 chunk 执行长度调整，及执行部分 chunk 后于 rollout 内重新推理（replanning
动作序列平滑处理（action smoothing）
推理精度调整（bf16/fp32）
计算图编译开关及其它不引入额外权重、不改变监督来源的推理时参数调整
时间维输出平均（temporal ensemble），及基于模型自身输出统计的置信度门控（confidence gating），在同时满足"单一权重、不依赖任务信息路由、不与环境交互"条件下是符合规则的
采用上述推理策略的，应当在 Config/README 中如实披露实施细节。"失败检测后重置 episode 重新执行"不属于本项允许范围，是否允许适用，以主办方书面答复为准。

三、禁止使用的技术手段
四条禁止轴（总则）：
① 数据来源轴（5.1）：数据不经 release 资产，或经环境渲染/交互产生；
② 模型起点轴（5.2）：训练起点不是 lingbot-VLA-v2-6b；
③ 推理形态轴（5.3）：推理超出单一权重，或依赖任务信息路由；
④ 学习方法轴（5.4）：学习方法超出 BC 框架（价值/优势/bootstrapping 类自构造监督）。

3.1 训练数据类禁止情形
禁止情形	说明
randomized 数据参与训练	任何比例、任何形式
使用外部数据	含真机自采、第三方数据集
自建 randomization	改变光照、桌面高度等外观后重新生成 observation
simulator 额外 rollout 训练	所有训练监督必须严格来自 clean demonstration；智能体自生成数据即使标注为 clean 亦不得使用
环境调用类	reward/价值标注需运行环境、以环境打分做数据筛选或加权
unseen_instructions 任何形式进训练	直接出现、改写后出现、或以任何筛选/加权方式引入
LLM 生成新指令文本	改写/扩写/筛选生成 release 中不存在的指令并绑定轨迹
HER 伪目标重标注	以轨迹自身后续状态作为伪目标，制造成败对比，并构造 release 中不存在的（目标/指令, 轨迹段）配对；"seen 池内替换"之界线在于：替换不新增配对，重标注新增配对
以官方 robotwin 后训练权重为教师进行知识蒸馏	蒸馏监督来自教师输出而非 clean demonstration，且教师含 randomized 数据信息，构成 randomized 数据之间接使用（基座自蒸馏及以参赛方自训权重为教师的蒸馏不在此列）
3.2 模型起点类禁止情形
禁止情形	说明
以官方 robotwin 后训练权重作为训练起点	该权重为 clean+randomized 混合训练产物；参赛起点统一为 lingbot-VLA-v2-6b。本条禁止及于以该权重为教师进行知识蒸馏等变相信息引。
3.3 推理阶段禁止情形
禁止情形	说明
task-specific 路由	按任务 ID 进行路由的 LoRA / adapter / head / checkpoint（官方认定在 instruction following 层面不公平）
确定性路由类推理增强	基于任务 ID、instruction 等题目相关信息的确定性路由
多 checkpoint / 多 model ensemble	—
多 seed 投票、test time adaption	多 seed 投票为测试时适应的一种形式
推理阶段使用多于一份权重	包括以单独训练的辅助模型进行置信度门控而于推理时加载第二份权重之情形
失败检测触发重置 episode 重新执行	—
3.4 学习方法框架
本节不按方法名称（RL / BC / 蒸馏等）划分禁界，一律以监督信号的获取方式判定。

禁止情形	说明
在线 RL	训练过程中与仿真环境交互采样（含少量交互）——监督之产生依赖环境调用，违反 3.1 数据来源轴
允许（澄清）：训练全程零环境调用、且监督信号（含 reward、标签、样本权重）全部可自 RoboTwin release 数据内部获得或推导的学习方法，不因方法框架本身受限，包括但不限于 offline RL（IQL / CQL / AWAC 等）、价值或优势加权、advantage-weighted BC。此类方法之合规性统一按 3.1 判定：凡 reward / 标签 / 权重之取得需运行环境（渲染观测、交互采样、调用 check_success() 判分、以环境打分筛选）者，依 3.1 禁止。

两点边界：

以官方 robotwin 后训练权重为教师之蒸馏（含作为 reward / 判据模型使用），无论在线离线，依 3.2 禁止；
官方 LingBot-VLA 2.0 训练配方自带之双教师蒸馏（LingBot-Depth / DINO-Video，即 robotwin.yaml 之 align_params）属允许之公开预训练表征教师，选手复现官方配方不触犯本规则。
判别标准（三问）：① 训练全程是否零环境调用？② reward / 标签 / 权重是否全部可自 release 数据内部获得或推导？③ 教师或起点是否涉及官方 robotwin 权重？——三问皆过即合规。

四、其它规则细则
4.1 专家数据采集配额
配额为五次，按采集发起次数计算，与 seed 无关；

达到五次上限后，该场景不得再发起专家采集；
策略评估不受配额限制影响：应继续完成 policy 测试并如实记录成绩。

六、附录（术语解读）
（A）数据与评测类
术语	定义
A.1 clean 数据	RoboTwin 2.0 中 Aloha-AgileX 机型 50 个任务的标准演示数据，每个任务 50 条轨迹。本赛事中 clean 数据是唯一允许参与训练监督的数据来源。
A.2 randomized 数据	经官方随机化（场景外观、物体布局、光照等）生成的数据。本赛事中 randomized 数据仅可用于测试，不得以任何形式参与训练。
A.3 release 资产	官方发布之 RoboTwin 2.0 数据与任务定义资源，含 clean 演示数据、任务定义、seen_instructions 指令池等；为合规数据来源之唯一范围。
A.4 seen / unseen 指令	seen 指令：训练任务指令池（seen_instructions）内、与训练数据同分布之语言指令；unseen 指令：未在训练数据中出现之指令，clean2random 设定使用
A.5 评测设定（setting）	clean2clean：训练使用 clean 数据，测试环境为 clean 设定，语言指令为 seen；clean2random：训练使用 clean 数据，测试环境为 randomized 设定，语言指令为 unseen。
A.6 check_success()	RoboTwin 评测环境内置之任务成功判据函数；成绩认定以其代码返回值为准，不人工复核。
（B）模型与权重类
术语	定义
A.1 基座模型（lingbot-VLA-v2-6b）	主办方指定的统一训练起点权重。全体参赛队伍的模型主干必须自该权重初始化；官方发布的 RoboTwin 后训练权重（lingbot-vla-v2-6b-robotwin）不得作为训练起点
A.2 单一权重（一份权重）	推理阶段加载的、由训练过程产出的唯一模型权重文件。允许的形态包括全量微调权重，以及 LoRA 训练后合并回基座的全量权重
A.3 cotrain（联合训练）	在全部 50 个任务上混合训练同一份权重，而非按任务分别训练、推理时切换
（三）训练方法与监督类
术语	定义
A.1 BC（模仿学习，Behavior Cloning）	以 demonstration 之状态-动作对为监督、直接学习专家动作之训练范式；
A.2 强化学习（RL，含在线与离线）	以奖励信号为目标、通过策略改进学习行为之方法族。在线 RL：训练过程中与环境交互采样；离线 RL：仅使用已收集数据后训练。
A.3 价值函数 / 优势函数（value / advantage）	价值函数：预期累计奖励之估计；优势函数：动作相对当前策略优劣之估计。
A.4 bootstrapping（自举）	以学习算法自身生成之估计量（如 Q 目标、优势估计）作为监督来源之方法；
A.5 知识蒸馏	以已训练模型之输出作为监督信号训练另一模型之方法。
A.6 环境调用	训练或数据处理过程中运行仿真环境，以渲染观测、交互采样或获取 reward / 成功判分之行为；
