# 左臂七关节长时记录实验

新入口 `run_arm7_record.sh` 复用 `arm7_direct.py` 的控制循环，增加完整记录。
原入口 `run_arm7_direct.sh` 仍默认 30 秒、最大 120 秒；新入口默认 600 秒、允许 1～1800 秒。
本实验沿用原来的无碰撞检查模式、两次按键确认、限位和速度保护、断流和反馈时效检查。

## 运行

在项目根目录、现场交互终端中运行：

```bash
bash teleoperation/run_arm7_record.sh --execute --seconds 1800 \
  --start-control left-button --align-speed-rad-s 0.4
```

第一次按键进入慢速对齐时开始计时，等待首次启动不计时；后续对齐、跟随、锁定均计时，重新启动不重置计时。
全部关节对齐后再次按键进入正式跟随；正式跟随中按键停止并锁定。
Ctrl+C 结束整个实验并走现有停止确认流程。到时停止后也会保存记录并尝试绘图。
不带 `--execute` 时仍会连接主从设备读取状态，但不发布运动指令。
`--help` 完全离线，不访问凭据、SSH、Docker 或设备。

自动生成 `lerobot_runs/arm7_record_YYYYMMDD_HHMMSS_PID/`，终端显示目录。
可以用 `--output-dir lerobot_runs/my_trial` 指定目录，必须不存在，以免混入旧实验。
Docker 中路径应位于 `/workspace`（项目挂载目录）下，避免退出后丢失。
Shell 入口默认传入 `--g1-clock-offset-ms 104`；用户同名参数可覆盖。直接运行 Python 模块默认 0。

## 文件

- `metadata.json`：schema 版本、运行参数、关节顺序、弧度单位、完整映射配置、解析后的速度与源文件 SHA-256。
- `samples.jsonl`：每条记录含 `event`、PC `wall_ns` 和 `monotonic_ns`。
  - `master_frame`：输入线程取出的每帧主臂原始位置/速度、关节名称、原始设备时间戳、PC 接收单调时间。设备时间戳单位和时钟域尚未确认，不用于直接对齐。
  - `sample`：控制循环使用的主臂原始位置、映射目标 `target`、从臂实测 `current`、速度、G1 原始关节时间戳、读取时 PC 双时钟、阶段和循环间隔。
  - `master_repeated` 标识重复主臂快照；`feedback_fresh` 区分新反馈和重复读取。
  - `command_attempt`：command_id、轨迹段起点/终点、速度、周期和指令头时间戳。
  - `command`：同一 command_id 的发送结果、是否成功及 publish 调用前后单调时间。调用异常时可以只有 attempt；不会当成成功指令分析。
- `events.jsonl`：启动配置、阶段切换、停止、异常、结束等事件。
- `recording_status.json`：写入数量、丢弃数量、待写数量、队列峰值和记录错误；缺失表示退出可能不完整。
- `tracking.png`：七关节位置与误差对比汇总图。
- `metrics.json`：各关节按对齐/跟随阶段统计的 MAE、RMSE、最大绝对误差、有效样本数、辅助延迟估计及数据质量。

记录使用 8192 条有界队列；控制线程复制数据入队，后台序列化、批量写盘，每 0.25 秒 flush。
队列溢出或写入失败会锁存错误，控制循环在下一次检查时停止实验。记录函数本身不抛出异常，避免日志故障阻断停止请求。
正常退出会排空队列；强杀、断电和磁盘故障不能保证全部数据保存，flush 也不等于断电持久化。
主臂记录覆盖输入线程实际收到的帧，不能证明串口/厂商队列上游没有丢帧。

## 时间对齐和分析口径

1. 保留所有原始时间戳。G1 时间减去配置的时钟偏差，再用读取时 PC 系统/单调时钟对应关系转换为实验时间。
2. 主臂以 PC 收到帧的时间为横轴。误差计算使用从臂采样时刻之前最近收到的主臂帧，最大年龄 300 ms。
3. 从臂重复反馈不重复计入误差统计；以校正后从臂采样时间判定所处阶段。
4. 下发端点与“估计线性参考”分别绘制。参考按已成功发送指令的两点线性插值、以 PC publish 开始时刻为起点重建；停止后、超过 300 ms 的指令空档不外推。
5. **SDK 实际执行起始时间没有观测值，因此参考误差属于估计值，不能称为精确的底层执行误差。** 主图不平移反馈以追求重合。
6. 延迟只在连续跟随至少 5 秒、从臂范围超过 5 度时尝试估计；插值主臂序列，在 0～500 ms 内按 10 ms 扫描相关性。峰值模糊、边界峰或相关性不足则返回 null 和原因。它包含接收、映射、限速及执行影响，不等于纯通信延迟。
7. 时间戳补偿值是固定配置，不会自动跟踪时钟漂移。长时间实验的时间精度仍取决于实际时钟偏差。

## 重新绘图（纯离线）

自动绘图在机器人停止、记录关闭后进行。需要 NumPy 和 Matplotlib；如果依赖缺失或数据不足，终端报告原因并保留原始数据。

```bash
python3 -m teleoperation.plot_arm7_tracking lerobot_runs/arm7_record_实际目录
```

允许跳过损坏/未写完的 JSON 行，并在指标中报告数量。没有有效从臂反馈时不生成误导性的跟踪图。
长实验仅对图中曲线抽稀，统计使用全部有效样本。

## 离线验证

```bash
python3 -m unittest discover -s teleoperation/tests -q
bash -n teleoperation/run_arm7_record.sh
```

新增测试覆盖新旧时长边界、计时起点和锁定期间计时、队列溢出、写入失败、退出排空、原始帧回调、时钟转换、线性插值、阶段排除和重复反馈。
本机 5000 条模拟 sample 入队调用测量：中位数约 17 微秒、P95 约 29 微秒、最大约 95 微秒，零丢弃。
这些是本机离线调用开销，不代表真机控制周期；每次实测的循环间隔统计另保存在 metrics.json 中。
