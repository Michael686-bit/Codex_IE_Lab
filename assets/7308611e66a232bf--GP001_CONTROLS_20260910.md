## 识别会话排查

后续纠正：旧版监视循环把 `time.monotonic()` 的秒值与纳秒起点比较，导致周期状态行
始终不打印；接收年龄的计算也混用了单位。此前“脚本没有问题”的判断不准确。
当前已修复，并增加实际运行主循环的状态输出回归测试。历史日志中的原始帧不受此显示问题影响。
日志没有 marker 或轴变化只能说明“未记录到”，不能据此断言操作者没有输入或操作。

随后运行的 `gp001_controls_identification.jsonl` 包含 6462 个有效帧、0 个无效帧，
持续约 67.9 秒，接收频率约 95.2 Hz，设备时间戳没有回退。该次运行的 `markers`
为 0，原因是运行期间没有在终端输入文字 marker；这不是采集失败。GP001 控件变化
仍会自动保存在 `sample.action_list` 和 `control_events` 中。

该日志中按钮列表只有启动初期的 `[10]`，随后为空；10 个轴在全程保持
`[0, 0, 0, 0.7, 0.7, 0, 0, 0, 0, 0]`，没有检测到轴变化。双臂各关节变化范围约
`0.0005–0.0008 rad`，符合静止噪声量级。因此这次只完成了链路和静止基线验证，尚未
完成实体按钮、扳机、摇杆和关节的辨识。

## 记录格式

每个 `frame` 的 `sample` 保留驱动返回的完整公开字段，包括：

- `timestamp`、`skew`
- `joint_states.left_arm/right_arm`，含 `header`、`name`、`position`、`velocity`、`effort`
- `action_list.header`、`action_list.axes`、`action_list.buttons`
- `button_state`

工具同时生成 `control_events`，只表示相邻帧之间的按钮按下/释放和轴变化；原始
`sample` 不会被这些派生字段替换或裁剪。

## 官方示例中的待核对定义

SynthNova 的 G1 仿真示例给出了以下动作码：

| 动作码 | 示例定义 |
|---:|---|
| `-1` | STOP |
| `0` | RESUME |
| `1` / `2` | 左夹爪关闭 / 打开 |
| `5` / `6` | 右夹爪关闭 / 打开 |
| `9` / `10` | 底盘移动 / 停止 |
| `21` / `22` / `23` | 腿部高度 / 前后 / 偏航增量 |

示例还使用 `axes[3]`、`axes[4]` 作为左右扳机，释放值为 `0.7`、按下值趋近
`0.0`；`axes[0:2]` 和 `axes[2]` 用于右摇杆底盘速度，`axes[5:7]` 用于腿部
控制。`axes[8:10]` 在该示例中没有使用，仍需现场辨识。

## 下一次现场操作顺序

1. 保持双臂和控件静止 5 秒，确认中立值和默认动作码。
2. 每个实体按钮短按、长按、释放各 3 次，给记录写入人工 marker。
3. 左右扳机分别执行释放、半按、到底、释放，记录轴范围和回程。
4. 左右摇杆逐方向活动并回中，确认 10 个轴的物理含义和死区。
5. 双臂每次只动一个关节，核对关节顺序、方向和单位。
