# 选择性深度补全：前三步小样本试验

目标：保留所有原始有效测量，只给受原始邻域支撑且通过一致性检查的小空洞添加 LingBot 预测；验证可追溯性、几何一致性和连续帧变化。这里不生成正式全量 B，不训练模型，不访问机器人。

## 执行命令

```bash
cd '/home/lsy03/文档/ChatGPT/VLA G1 项目'
set -o pipefail

# CPU规则测试：含之前瓶身10.9cm跳变的已保存真实训练样本
bash lingbot_depth/selective_fill.sh self-test

# 可选：只读检查A和打印选择方案，不写试验目录，不运行GPU
bash lingbot_depth/selective_fill.sh inspect

# 1. 固定A身份、训练/验证划分、试验样本、规则和本地权重
# 用不同目录名开启另一组规则；不要覆盖已存在目录
RUN_DIR="$PWD/reports/selective_depth_pilot_v1"
bash lingbot_depth/selective_fill.sh plan --output "$RUN_DIR"

# 2～3. 本地GPU推理、规则筛选、连续帧诊断、对比图与报告
# 前台运行，终端逐帧打印 eligible/accepted/coverage 和进度
bash lingbot_depth/selective_fill.sh run "$RUN_DIR" 2>&1 | tee "$RUN_DIR/run.log"

# 如中断，复用并校验已有完成帧；未完成帧重新处理
bash lingbot_depth/selective_fill.sh run "$RUN_DIR" --resume 2>&1 | tee -a "$RUN_DIR/run.log"

# 修改rois.json、人工确认阶段后，仅CPU重新生成报告
bash lingbot_depth/selective_fill.sh review "$RUN_DIR"
```

`run` 与 `--resume` 二选一执行，无需连续运行两次。`self-test` 不调用GPU，也不重新运行LingBot，只使用合成数据和上一轮已保存的预测。需要在终端拥有本机GPU访问权限；不启动HTTP服务，不联网下载依赖。独立环境沿用`lingbot_depth/.venv`，本地权重为`models/model.pt`。可选Triton后端缺setuptools的提示不妨碍已验证的模型推理；如出现真正异常脚本会以非零状态退出。

## 第一步：固定A/B身份

- A为`/mnt/data/VLA_data/smolvla_runs/multimodal_data/raw_depth_force_v1`。检查缓存哈希、源数据集30个交付文件哈希，记录当前manifest；不得修改A。
- 当前A共32条训练/7条验证示教、3581/713窗口；脚本从实际manifest读取，不重新划分、筛选或更改RGB/腕力/动作。
- B正式名称暂定`selective_depth_force_v1`，本脚本只产生独立pilot结果。128×224样本文件是格式验证，不是完整B缓存，也不能直接交给原训练脚本。
- 默认每批2条训练示教、每条3个候选阶段，每阶段5帧原始15Hz连续片段。额外加入已知反例的5帧片段；唯一帧数以计划打印为准，最多95帧。三批均覆盖，验证示教处理数为0。
- 阶段候选根据夹爪闭合/重新打开事件提出，回退方案是时间分位点。**夹爪事件不能证明抓到瓶子；必须查看RGB确认接近/夹持/移动放置阶段。** 原始连续帧用于质检，可能包含不作为训练窗口起点的帧，A的样本集合不受影响。
- `plan.json`记录样本、流序列、时间戳、负载位置/哈希、原始内参、规则和权重哈希；`src/`保存代码快照。代码或规则变化需要新plan目录，旧结果保留。

## 第二步：固定规则v1

原始深度1280×720，uint16，单位0.1mm，严格除以10000转米。原始码除0、65535之外全部逐码保留（包括当前训练范围之外的原始测量）。补全候选必须满足：

1. 原来是0或65535；LingBot输出mask为真，预测有限且在0.07～1.0m。
2. 原始9×9邻域至少12个0.07～1.0m支撑点，最近支撑点距离不超过3像素。
3. 邻域原始支撑点的深度最大值减最小值不超过20mm，保守拒绝跨深度边缘候选。
4. 预测量化到0.1mm后，与原始支撑均值差不超过`max(10mm, 5%×均值)`。

不递归使用补全点作为支撑；没有近距支撑、大空洞、深度边界或预测不一致时继续无效。该规则只表示与现有局部测量一致，**不证明原始测量或补全值接近真值**。

来源mask编码0=无效/未填，1=原始测量，2=通过规则的预测。来源mask不是置信度、不是独立深度真值。满分辨率筛选后，B深度和来源mask一起最近邻降至128×224，以保留原始码和来源身份。

参数仅能在`plan`时指定，之后冻结。例如调整阈值必须新建目录：

```bash
bash lingbot_depth/selective_fill.sh plan \
  --output "$PWD/reports/selective_depth_pilot_v2" \
  --radius 4 --min-support 12 --max-distance 3 \
  --max-span 0.02 --abs-tolerance 0.01 --relative-tolerance 0.05
```

不根据验证示教调参数。首轮坚持现有0.07～1.0m范围，不同时改变输入范围或模型结构。

## 第三步：检查输出

打开`RUN_DIR/report.html`。包含总览、每段连续片段的六列配对图、逐层接受/拒绝统计、已知反例和连续帧诊断。

- **保真性**：逐码核对原始有效值不变；保留未填的0/65535编码；保存原始与B、来源mask和哈希。
- **反例**：已知`milk_left_20260930/episode_000008/sequence105`像素(675,536)原为空洞，直接补全约0.293m；附近原测量约0.184m。v1必须拒绝该空洞且保留(673,536)原测量，否则结果为`blocked_known_counterexample`，禁止进入后续阶段。
- **目标收益**：自动报告全图范围内覆盖，目标ROI由人工确认，避免将背景或夹爪算成瓶身改善。`rois.json`默认仅给已人工检查的反例提供瓶身框，其余框留空。
- **时序诊断**：以RGB前后向光流和灰度一致性对齐相邻帧，分别报告原测量共同点与涉及补全共同点的深度变化、中位数/P95及来源切换比例。这是2D对齐诊断，不包含完整3D相机运动补偿；轴向运动、遮挡、光流误差可能影响数值，不能直接判定补全误差。
- **阶段确认**：逐片段看RGB，确认或修正候选阶段；标注ROI。固定像素框不随物体移动，检查连续帧时要确认物体仍在框内。

`rois.json`一个条目的示例（坐标必须来自该片段实际图片，不要直接套示例）：

```json
{
  "box_xyxy": [630, 500, 725, 555],
  "label": "瓶身内部，已查看连续帧",
  "phase_confirmed": true
}
```

保留顶层`clips`和全部片段键，仅编辑相应条目，然后执行`review`。人工确认不自动批准全量生成。

## 输出与完成标准

`plan.json`、`A_manifest_snapshot.json`、`src/`：原始身份与固定试验方案。

`frames/FRAME/arrays.npz`：`raw_uint16`、`lingbot_m`、`model_mask`、`B_uint16`、`source_mask`。`cache_128x224.npz`：降采样B/来源。`rgb.png`与`result.json`：原图、来源、哈希、规则与统计。

`contacts/*.jpg`、`overview.jpg`、`report.html`、`summary.json`、`status.json`：图像和机器可读报告。

预期正常完成状态为`completed_pending_manual_review`，**不是“B数据精度已通过”**；`safe_to_train_B`始终为false。已知反例未拒绝时为`blocked_known_counterexample`；其他程序失败为`failed`或`interrupted`。脚本无全量B生成或训练入口。

推进到下一阶段至少需要：原值完全保留、已知反例拒绝、人工确认阶段与目标ROI、接受补全没有明显局部突变/边缘污染、运动背景下的时序变化可以解释。有意义的接受量也应单独评估；零补全不算证明算法有收益。若小样本未通过，保留A，在训练小样本上修订规则并建立新计划，不能自动放宽阈值追求覆盖率。
