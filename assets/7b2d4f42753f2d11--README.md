# S1 本地相机查看器：离线与在线只读实现

日期：2026-09-17。已完成本地离线回放和 S1 核心六路在线只读查看；默认入口仍是
离线回放。在线入口必须显式启动，且不会运行 Mode 00。

## 目标

为后续 S1 相机盘点准备一个本地 ROS 2 边界：每个已配置流发布标准的 RGB、
米制深度、固定色标深度图、CameraInfo 和状态 JSON；订阅端用有界的最新帧
状态组成多画面窗口。离线样例重复同一个源时间戳时，状态会显示
`SRC_REPEAT`，超过停更阈值后显示 `STALE`，因此不会把重复回放误报成真实帧率。

在线阶段仍需另一个经过审查的只读采集器，使用当前 S1 安装版本实际确认过的
getter 和编码。这里没有把历史 SDK 接口直接包装成在线命令。

## 本地审查结论

审查了 `experiments/20260903_fdp_baseline` 的
`fdp_baseline/live_capture.py`、左右腕 `capture_*_rgbd_once.py` 以及
`experiments/20260822_s1_rviz_demo/ros2_ws/src/s1_rviz_demo`。

- 既有腕部采集是一次性 getter-only 工具，调用 RGB、depth、CameraInfo、
  外参/TF 和状态后释放 SDK；它不适合未经改造地承担多路持续订阅。
- 已保存的捕获目录包含 `rgb.png`、`depth_raw_m.npy`、`intrinsics.npy` 和
  `capture_meta.json`。`depth_raw_m.npy` 的合同是米制 `float32`，不是要再除
  1000 的原始毫米数组。
- `right_wrist_20260907_01` 冻结样例为 1280×720、相机类型 `D435I`，RGB 和
  depth 使用 `right_arm_camera_color_optical_frame`，RGB/depth 源时间戳相同，
  有效深度约 86.6%。这些是该冻结文件的本地事实，不代表当前 S1 在线状态。
- 既有 ROS 包的重点是 LiDAR、TSDF/ESDF 和 RViz；本实验单独建立
  `s1_camera_viewer`，避免改变既有导航或 LiDAR 默认行为。LiDAR SSH bridge
  只作为有界队列、stderr 日志和退出清理的实现参考。
- 本机已发现 `/opt/ros/humble`、`rclpy`、`sensor_msgs`、OpenCV、NumPy 和
  PyYAML；未安装或更换依赖。

## 文件

`ros2_ws/src/s1_camera_viewer/s1_camera_viewer/core.py` 是无 ROS/SDK/SSH
依赖的解码边界，支持文档中的 JPEG/PNG RGB、原始 RGB、16 位整数深度、
32 位浮点深度及带真实 PNG 签名的 compressedDepth 前缀。整数深度缺少
`depth_scale` 时会拒绝，深度输出统一为米制 `32FC1`。

`status.py` 提供线程安全的单元素最新帧缓冲和源时间戳进度统计。重复时间戳
不会更新“最后一帧源时间”，旧画面可以进入 stale 状态。

`scripts/offline_camera_publisher.py` 读取冻结目录并发布：

| 数据 | 默认话题后缀 | ROS 类型/编码 |
| --- | --- | --- |
| RGB | `rgb/image_raw` | `sensor_msgs/Image`, `rgb8` |
| 原生深度 | `depth/image_raw` | `sensor_msgs/Image`, `32FC1`，米 |
| 深度显示 | `depth/image_viz` | `sensor_msgs/Image`, `bgr8` |
| 标定 | `camera_info` | `sensor_msgs/CameraInfo` |
| 状态 | `status` | `std_msgs/String`，JSON |

`scripts/camera_grid_viewer.py` 只订阅这些本地话题，同一流显示 RGB 和
depth 两个 tile。交互 GUI 使用 PyQt5；默认以 3 列排列六个 tile（两行横向布局），
窗口初始大小为 1600×900。窗口可以像 rqt 一样拖拽边缘或点击最大化，网格会随窗口
等比缩放；不会把窗口锁在图像原始尺寸。交互 GUI 的离屏检查确认初始尺寸为
1600×900、最小尺寸为 320×240、最大尺寸未锁定。
可用 launch 参数 `grid_columns:=1|2|3...`、`window_width:=...`、`window_height:=...`
调整布局和初始窗口大小。点击 tile 可放大，按 Esc 或鼠标左键返回网格；鼠标悬停
在 tile 上滚轮即可按鼠标位置缩放，`+`/`-` 调整当前 tile，`0` 恢复当前 tile 的
1×视图；缩放范围为 1×–4×，状态栏会显示倍率。深度 tile 移动鼠标时显示像素米制
读数。没有显示服务器时用 `--headless` 写
`grid_latest.png` 和 `status_latest.json`。

```bash

  --capture-dir experiments/20260903_fdp_baseline/captures/right_wrist_20260907_01
```

```bash

```

无图形桌面或只验证通信链路：


```bash

  headless:=true duration_s:=5.0
```

回放只在本机发布，不建立 SSH，不连接 `10.34.216.17`，也不初始化
`galbot_sdk`。停止窗口或按 Ctrl+C 只会销毁本地 ROS 节点。

## 与在线阶段的边界

以下问题必须在用户明确授权当前 S1 只读访问后，由单独步骤核验，本阶段不以
离线样例替代：

- 当前机器人身份、SDK/运行时版本、相机生产者和可用 SensorType 符号；
- 头部左右 RGB、左右腕 RGB-D 和每个实际启用 IR 的 getter 返回格式、尺寸、
  frame、源时间戳和 FPS；
- 原生深度的压缩头、整数单位和 `depth_scale`，以及 RGB-depth 是否同帧/对齐；
- CameraInfo 的 K/D/R/P 是否随真实数据提供；不缺标定时不编造；
- 6 路基线及 IR 扩展的网络字节量、ROS QoS、CPU/RSS、断线重连和 10 分钟
  稳定性；
- 与用户自行运行的 Mode 00 并行时的取图超时和业务耗时增量。

在线阶段应从右腕 RGB+depth、2 FPS 起步，确认 reader 生命周期只影响本进程，
再扩展其他已启用流。不得为了验证查看器启动无参数的
`run_s1_mode00_one_click.py`，不得自动开启 IR，不得获取控制器或发送任何运动、
导航、配置命令。

## 阶段 2：右腕在线最小链路

当前阶段新增 `live_camera_ssh_bridge.py`、`remote_camera_reader.py` 和
`live_viewer.launch.py`。在线桥只接受 `right_wrist_live` 配置，并且本地直接
运行时必须显式给出 `--live --camera-arm right`；没有 `--live` 会在初始化
`rclpy` 或创建 SSH 子进程之前退出。离线 `run_offline_viewer.sh` 和
`offline_viewer.launch.py` 的默认行为没有改变。

`remote_camera_reader.py` 通过 `setup.py` 的 `package_data` 明确打包进
`scripts`，因此普通安装（不依赖 symlink）时本地桥仍能从自身目录读取源码，
再经 stdin 传给远端 `python3 -`。

本地桥使用 `sshpass -f /home/lsy03/.config/galbot-s1/ssh-password` 读取仓库外
的 owner-only 凭据文件，通过严格 host key 校验的短时 SSH 子进程把 reader 源码
写入远端 `python3 -` 的 stdin。它不使用 `scp`，不在 S1 创建临时脚本文件，且
显式设置：

```text
LD_LIBRARY_PATH=/home/galbot/ie_lab/projects/chassis_env/build/sdk_runtime
PYTHONPATH=/home/galbot/ie_lab/projects/chassis_env/build/sdk_runtime
```

远端 reader 的 SDK 调用白名单是：
`GalbotRobot.init({RIGHT_ARM_CAMERA, RIGHT_ARM_DEPTH_CAMERA})`、
`get_rgb_data(RIGHT_ARM_CAMERA)`、`get_depth_data(RIGHT_ARM_DEPTH_CAMERA)`、
`get_camera_intrinsic(RIGHT_ARM_DEPTH_CAMERA)` 和退出时本进程的
`GalbotRobot.destroy()`。它不构造 `GalbotMotion`，不读取状态，不获取控制器，
不访问 IR、LiDAR、导航、配置或感知接口。

在线命令（先用 5 秒 headless 测试）如下；凭据路径只作为参数传给 `sshpass -f`，
不要把密码写入命令行：

```bash
cd '/home/lsy03/文档/ChatGPT/S1/experiments/20260916_s1_camera_viewer/ros2_ws'
set +u
source /opt/ros/humble/setup.bash
source install/setup.bash
set -u
export ROS_DOMAIN_ID=84
export ROS_LOCALHOST_ONLY=1
export ROS_LOG_DIR=/tmp/s1_camera_viewer_logs
ros2 launch s1_camera_viewer live_viewer.launch.py \
  sshpass_file:=/home/lsy03/.config/galbot-s1/ssh-password \
  rate_hz:=2.0 duration_s:=5.0 headless:=true \
  snapshot_dir:=/tmp/s1_camera_viewer_live
```

ROS 会发布与离线阶段相同的右腕 RGB、米制 `32FC1` depth、depth visualization、
CameraInfo 和 status 话题。状态保留源时间戳、原始 `format`、`depth_scale`、
RGB/depth 时间差、原始压缩字节数和传输错误。收到不支持的格式、无时间戳、尺寸
不匹配、缺少整数深度 scale 或超出 8 MiB 帧上限时，桥会拒绝该帧并让查看器进入
stale/error 状态，不把本地时间或默认毫米单位冒充源数据。

在线采集预期只启动 S1 右腕相机数据 getter，不应使手臂、夹爪、升降、头部或
移动底盘运动；仍会初始化 SDK 传感器通信并产生有限读取负载。测试期间不要同时
启动 Mode 00；如用户自行运行 Mode 00，必须另行记录并行影响。Ctrl+C 或 duration
到期只关闭本桥创建的 SSH/reader 子进程，不能关闭共享 ControlMaster。

## 阶段 3：core_rgbd 六路在线查看

阶段 2 的 `live_camera_ssh_bridge` 与单腕配置已废弃：它会在 ROS/SSH 前拒绝并
提示使用 `live_core_rgbd_viewer.launch.py`，避免把未 materialize 的旧 reader
模板发送到 S1。保留的 `live_viewer.launch.py` 只是兼容别名，实际转发到 core
六路 launch；新的命令和配置应直接使用 core 入口。

当前 S1 1.9.0 的有效目标集合收窄为 6 路：头部左右 RGB-only、左腕 RGB 与
原生 depth、右腕 RGB 与原生 depth。`core_rgbd_live.yaml` 只配置这 6 个
SensorType；`camera_inventory_20260916.yaml` 另行保留四个 generic/G1-only
surround 枚举为 `enabled=false`、`status=unsupported`。它们曾逐个
`init_ok=false`，也不进入 `GalbotRobot.init`，不能据枚举名宣称 S1 存在对应
物理相机。当前 1.9.0 没有 IR 枚举，本阶段不启用 IR。

直接启动 core_rgbd 六路查看器（需要当前任务已有的只读访问授权）：

```bash
cd '/home/lsy03/文档/ChatGPT/S1/experiments/20260916_s1_camera_viewer/ros2_ws'
set +u
source /opt/ros/humble/setup.bash
source install/setup.bash
set -u
export ROS_DOMAIN_ID=84
export ROS_LOCALHOST_ONLY=1
export ROS_LOG_DIR=/tmp/s1_camera_viewer_core_rgbd_logs
ros2 launch s1_camera_viewer live_core_rgbd_viewer.launch.py \
  sshpass_file:=/home/lsy03/.config/galbot-s1/ssh-password \
  rate_hz:=1.0 duration_s:=0.0 headless:=false
```

如果之前的窗口已经在运行，需要先关闭旧窗口再重新启动，让新的 Qt 窗口实现生效。

默认网格为 3 列×2 行；若屏幕较窄，可将 `grid_columns:=2` 或
`tile_width:=480` 传给 `live_core_rgbd_viewer.launch.py`。
六路冻结回放的横向布局检查输出为 `1920x928`（3 列×2 行）。

`live_viewer.launch.py` 仅为旧命令保留的兼容别名；新运行应直接使用上面的
`live_core_rgbd_viewer.launch.py`。bridge 和远端 reader 都会拒绝六个已验证
SensorType 之外的配置，generic/G1 surround 不会因 inventory 误改而被初始化。

多流 reader 将配置序列化进 stdin 源码，只调用：
`GalbotRobot.init(6 sensors)`、每个 RGB 流的 `get_rgb_data`、每个 depth 流的
`get_depth_data`、每个流的 `get_camera_intrinsic`，以及退出时 `destroy`。
RGB-only 流不会订阅或发布 depth；viewer 根据 `kind` 动态生成 4 个 RGB tile
和 2 个 depth tile，不把头部 RGB 误报成深度。

本地 bridge 的 SSH/sshpass 使用 `start_new_session=True`，退出对自身进程组发送
SIGTERM，超时再 SIGKILL；不触碰共享 ControlMaster。远端 writer 通过
`os.write + select` 非阻塞分块写，每帧最多 8 MiB、整体写超时约 2 s，断管或
超时进入 `destroy`，避免大帧阻塞在远端留下 `python3 -`。

主线程用 8–20 秒低频 core_rgbd launch 复测成功，六路画面和状态均到达：

| --- | --- |
| `HEAD_LEFT_CAMERA` | `online`，RGB `1280x960`，`format=rgb8` |
| `HEAD_RIGHT_CAMERA` | `online`，RGB `1280x960`，`format=rgb8` |
| `LEFT_ARM_CAMERA` | `online`，RGB `1280x720`，`format=rgb8` |
| `LEFT_ARM_DEPTH_CAMERA` | `online`，`1280x720`，`format=16UC1`，`depth_scale=1000` |
| `RIGHT_ARM_CAMERA` | `online`，RGB `1280x720`，`format=rgb8` |
| `RIGHT_ARM_DEPTH_CAMERA` | `online`，`1280x720`，`format=16UC1`，`depth_scale=1000` |
