# π0.5 独立 Docker 环境

镜像：`lerobot-pi05:0.4.4-cu128`。继承项目现有 CUDA/PyTorch 镜像的只读层，在新镜像中安装 π0.5 官方兼容 Transformers 分支和 PEFT。原 ACT、SmolVLA、LingBot 与 RoboTwin 镜像不变。

使用独立镜像的原因是 π0.5 需要 `fix/lerobot_openpi` 分支中的 AdaRMS 等兼容修改，而 ACT/SmolVLA 基线使用通用 Transformers 4.57.1。仅能导入 π0.5 模块不足以证明模型可运行。

2026-10-08离线验收通过：严格加载官方基础权重，三路RGB与8维合成状态输入，输出`[1,50,8]`。RTX 4090上预热后完整动作块推理平均120.5ms，PyTorch分配显存峰值7292.6MiB，未使用torch.compile。rank=8 LoRA构建与前向推理通过；没有执行训练或真机控制。完整范围见`reports/部署验收报告.md`。

## 使用

在项目根目录执行：

```bash
# 环境与 CUDA 检查
bash pi05_deploy/scripts/pi05.sh check

# 严格加载官方基础权重，进行三路 RGB + 8维状态的合成推理
bash pi05_deploy/scripts/pi05.sh infer

# 额外构建 rank=8 LoRA 并做一次前向推理；不执行训练
bash pi05_deploy/scripts/pi05.sh infer --verify-peft

# 查看镜像与 GPU
bash pi05_deploy/scripts/pi05.sh status
```

镜像不是常驻服务。每次命令启动一个临时容器，命令完成后自动释放 GPU；没有开放端口。缓存、权重、输出和报告保存在宿主机，容器删除后仍保留。

目录：

- `runtime/models/pi05_base/`：锁定版本的官方基础权重与原始配置。
- `runtime/tokenizer/`：官方 OpenPI 使用的公开 Google SentencePiece 文件及本地 HF tokenizer。
- `runtime/cache/`：该环境独立缓存。
- `runtime/outputs/`：合成动作输出；不代表可执行的 G1 动作。
- `reports/environment.json`、`requirements-lock.txt`：环境与完整依赖版本。
- `reports/tokenizer.json`：HF tokenizer 与 OpenPI SentencePiece 的编码一致性检查。
- `reports/inference.json`：严格加载、推理延迟、显存和可选 PEFT 前向检查。
- `manifests/`：源码、镜像 ID、模型版本及 SHA-256。

## 重建与下载

```bash
bash pi05_deploy/scripts/pi05.sh build
bash pi05_deploy/scripts/pi05.sh download
bash pi05_deploy/scripts/pi05.sh tokenizer
bash pi05_deploy/scripts/pi05.sh check
bash pi05_deploy/scripts/pi05.sh infer --verify-peft
```

基础镜像 ID 与 Transformers 源码 SHA-256 均锁定。源码包位于 `vendor/transformers-dcddb970.tar.gz`；若缺失，可从 `https://codeload.github.com/huggingface/transformers/tar.gz/dcddb970176382c0fcf4521b0c0e6fc15894dfe0` 下载。官方权重文件约14.47GB，下载阶段支持分块续传并核对上游 SHA-256。`PI05_DOWNLOAD_WORKERS` 可调整并发数，默认24。

若官方站点传输较慢，可使用已校验内容一致的国内镜像。脚本先验证镜像清单中的大小、SHA-256与官方固定值一致，下载结束后再次核对完整文件哈希；仍使用官方锁定版本的配置。以下设置只影响本次下载进程，不修改系统代理：

```bash
PI05_DOWNLOAD_SOURCE=modelscope PI05_DOWNLOAD_DIRECT=1 PI05_DOWNLOAD_WORKERS=16 \
  bash pi05_deploy/scripts/pi05.sh download
```

默认数据目录是项目内的 `pi05_deploy/runtime`。可设置 `PI05_DATA_DIR=/绝对路径`，迁移时完整复制目录；容器内统一映射为 `/runtime`。

推理容器禁用网络、使用普通用户、只读根文件系统和只读权重挂载。仅该环境的缓存、输出、报告可写。构建与下载阶段需要网络。

## 验证范围与后续微调

基础模型来自 `lerobot/pi05_base`，不是 G1 任务微调模型。合成验收采用三路224×224 RGB、8维状态/动作、batch=1、50步动作块、10步 flow matching、BF16、不开启 `torch.compile`。状态/动作归一化使用合成单位分位数，不能用于实机。

验收直接读取 safetensors、执行官方键名映射并调用 `load_state_dict(strict=True)`。safetensors省略的共享权重别名，仅在模型实际共用同一个Parameter时从已存在的对应权重补齐，并在报告中记录映射。其余缺失、多余或形状不匹配的权重都导致失败。上游 `from_pretrained` 会捕获部分加载错误并返回模型，本入口让这些错误直接导致失败，以免把未加载权重的模型当作成功。

PEFT 已安装，可选验收仅验证 LoRA 构建与前向推理。没有执行优化器更新、反向传播或显存训练验收。4090上的微调建议先验证小batch的动作专家微调或LoRA；完整全参数微调按官方 OpenPI 参考需要超过70GB显存。

正式 G1 微调仍需单独配置数据质量筛选、按episode划分训练/验证、仅训练集的分位数归一化、相机键名与左臂7关节（rad）+夹爪（m）的8维动作语义。原有SmolVLA训练脚本的输入尺度、预处理和优化器参数不能原样当作π0.5配置。

本次部署没有启动训练、上传数据或控制机器人。合成推理与LoRA前向通过均不代表G1任务成功率或实机闭环验收通过。

参考：[LeRobot v0.4.4 π0.5 文档](https://github.com/huggingface/lerobot/blob/v0.4.4/docs/source/pi05.mdx)、[OpenPI](https://github.com/Physical-Intelligence/openpi)、[官方基础模型](https://huggingface.co/lerobot/pi05_base)。
