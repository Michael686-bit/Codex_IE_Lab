# 2026-10-09 时钟映射异常原因检查

## 实际表现

14:41批次第2组，录制后9.166～10.176秒的锚点区间：PC单调时钟经过1009.806184ms，G1系统时间经过1003.651349ms，G1单调时钟经过1003.651785ms。两机相对变化−6.154835ms，超过当前ClockMap约4.033901ms的工程界限（两端RTT＋1000ppm漂移包络＋2ms）。映射偏移从约73.165345ms变为67.010599ms，故标clock_rate_or_offset_change。

G1 wall与MONOTONIC各自没有大幅相互跳变，但两者都可受到系统调速影响。CLOCK_MONOTONIC_RAW用于对照，不拿其未标定绝对值直接替换传感器时间戳。

相邻锚点约1秒的区间被拒收，不等于图像真的错位1秒；该区间约10个10Hz候选点不能按原映射直接宣称同步可靠。异常并不直接表示原文件损坏或整条没有用。

## 异常发生时的服务日志

只读取回14:30:45～14:46:25共1880条日志。在9条success候选的拒收区间附近（起点前1秒至终点后2秒），phc2sys报告系统时间相对PHC的偏差绝对值最高约8.308～8.706ms，而ptp4l报告PHC相对PTP主时钟的偏差最高仅0.099～0.211μs。相关性指向CLOCK_REALTIME与网卡PHC之间这一层；未把邻近窗口峰值说成区间内每个时刻的误差。

当前服务配置：

- systemd-timesyncd active，以192.168.1.99（PC）作为NTP源，32秒轮询。
- ptp4l active，eth0、hardware timestamp、slaveOnly=1、domainNumber=11。
- phc2sys active，执行`phc2sys -s eth0 -c CLOCK_REALTIME -O 0 -S 1`，明确把系统时钟作为被调整对象。

两条同步路径同时涉及系统时间，竞争调时是最有证据的配置线索。已定位到G1系统时钟的动态调速；尚未通过停用其中一个调时器的受控实验隔离最终因果，不称已唯一确认所有SDK间隔或夹爪超时的根因。

## 最终验证与处理方向

机器人静止、无其它控制/采集任务时，保存服务状态，安排独立自动恢复；短时停止NTP调时，保持现有PTP链路，观察收敛后持续采样至少两个原NTP轮询周期，再恢复NTP并对比。若映射拒收与RAW对照的周期波动消失、恢复NTP后又复现，则进一步确认竞争调时。

本次仅查询时间与日志，没有修改服务、相机参数、保护阈值、时间戳或原数据；没有调用机器人运动接口。未执行上述服务变更对照。
