- PC/G1 的 wall−monotonic 首尾变化分别约 0.0076/0.0012 ms，没有观察到大的净偏移突变；首尾比较不能排除中间短时异常。本次各流表观年龄均为非负，但不能由此推断控制器/相机时钟完全统一。

## 字段定义的确认程度

| 字段 | 可确认内容 | 仍需确认/使用限制 |
|---|---|---|
| 头、腿、左右臂的 21 个关节 | 实际 URDF 为旋转关节；SDK C++ 明确 position rad、velocity rad/s、acceleration rad/s²、effort N·m、current A | 文档单位不等于测量通道已校准；此前手臂 effort 为 0，不能宣称真实力矩可用 |
| chassis_joint1–4 | 默认配置使用 GalbotChassisInterface，SDK 将其归为被动底盘状态组 | 具体代表轮子/虚拟状态及物理单位仍无明确证据；不将通用 JointState 的 rad 注释直接套用到这些字段 |
| 六维腕力 | SDK 1.9.0 C++ 明确 force N、torque N·m、时间戳为 epoch 纳秒 | ForceData 无 frame_id、归零或重力补偿状态字段，无法从读数本身确认 |
| 腕力坐标系候选 | 默认 G1 v2.2 配置 left/right_effort 的 tip_link 是 left/right_arm_force_sensor_link | 默认配置不等于已验证的当前运行配置；不能据此认定 SDK 返回的力一定在此坐标系表达 |
| 夹爪开度与速度 | m、m/s；C++ 注释速度正方向为张开 | 静止只读检查不验证动作方向 |
| 夹爪 effort | C++ 头文件写 N，Python stub 写 N·m | 文档冲突，原样保存，暂不按物理夹持力/力矩归一化 |
| 图像 Header/状态时间戳 | SDK 声明 epoch 纳秒 | 未说明各硬件时钟映射细节、曝光起点/中点/输出时刻，不以字段名证明硬件同步 |

证据已保存为 sdk_semantics_evidence.txt、semantics_config_detail.txt、semantics_remote_evidence.txt。没有在资料不足时用零偏或静止读数倒推单位/坐标系，也没有做未经请求的归零、加载或运动试验。

## 本阶段决定

**原始数据的设计约定已足够具体，可据此开发 P1 原始记录器；P0 的全部训练语义与时间验收尚未完成。** 未降低此前定义的正式验收标准。

原始记录器应保存所有原始字段，另附 SDK 声明的单位、未知项、原始时钟域和 QC 标记。未知项不阻止原始保存，但阻止未经处理的物理解释、归一化和训练导出。数据格式仍标为草案，正式记录可靠性尚未验收。

当前明确不允许：

- 将底盘 4 个字段默认视为弧度，或将夹爪 effort 当作已标定牛顿值。
- 将腕力原值称为已经去除工具重力的接触力。
- 给全部传感器直接填同一个读取时间戳，或使用固定 104 ms 历史校正。
- 把本次离线映射残差当成真实曝光/受力采样同步精度。
- 只因所有通道有数据就启动批量正式采集。
