# S1 头部 RGB、双目深度与 LiDAR 点云融合评估

日期：2026-09-03

## 结论

方向现实，但要区分两种不同方案：

1. **头部 RGB + 头部 LiDAR 点云投影**：可生成彩色点云和稀疏 RGB-D，适合
   导航、建图、大障碍物和箱体粗定位；单帧不能等同于逐像素稠密深度相机。
2. **头部左右 RGB 双目 + 立体深度模型**：可生成稠密或半稠密深度，更接近
   被动双目深度相机。S1 官方 SDK 1.9.1 已提供 `FOUNDATION_STEREO`，因此路线
   已获得官方接口支持；仍需验证当前实机部署、标定、延迟和误差。

推荐系统为：

```text
头部左右 RGB -> 双目稠密深度/置信度 ----+
                                      +-> 头部 RGB-D/点云 -> 场景与粗定位
头部 3D LiDAR -> 稀疏公制深度/远距锚点 --+

左右腕部原生 RGB-D ------------------------> 近距离精定位与最终抓取
```

对当前拆垛任务，头部融合适合“发现、粗定位、规划观察位”；最终抓取仍应保留
腕部 RGB-D 和 FoundationPose++ 等近距离链路。

## 已确认事实与缺失参数

本评估没有连接 S1、初始化 SDK、创建传感器 reader 或发送控制命令。

- `VERIFIED (official product pages)`：S1 头部配置“双目相机 ×1、3D 激光雷达
  ×1”，左右腕部/胸部配置深度相机 ×2；计算平台是 NVIDIA AGX Orin 64 GB、
  275 TOPS。
- `VERIFIED (official local SDK release)`：本地官方 `GalbotSDK` 提交
  `a625328c3530204cb8c0da8251bd29e9b736fb81`（V1.9.1）包含
  `HEAD_LEFT_CAMERA`、`HEAD_RIGHT_CAMERA` 和高精度双目深度模块
  `FOUNDATION_STEREO`；`LIGHT_STEREO` 在该版本标注为不支持。
- `VERIFIED (official SDK API)`：SDK 能读取相机 `height/width/D/K`、传感器
  外参和带时间戳 RGB；C++ `CameraInfo` 还定义了双目 `R/P`，右目基线可由
  `B = abs(P[3] / P[0])` 得到。
- `VERIFIED (official SDK API/example)`：`FOUNDATION_STEREO` 经
  `run_once()`/`wait_for_new_result()` 返回 `DetectionResult`，官方示例把深度
  数组放在 `instance_mask`。公开示例没有声明深度单位、量程、分辨率、FPS 或
  误差。
- `VERIFIED (previous authorized S1 observation, 2026-08-31)`：S1 三路 Livox
  原始点云均约 10 Hz、19,968 点/帧、约 519 KB/帧；头部点云 frame 为
  `head_lidar_base_link`，存在经头部关节到 `base_link` 的动态 TF 链。
- `VERIFIED (previous authorized S1 inspection)`：当前导航 fusion 使用三路
  LiDAR，深度相机融合关闭；局部 nvblox TSDF/ESDF 体素为 0.05 m。5 cm 体素
  地图适合导航碰撞场，不是精细抓取的逐像素深度图。

以下仍为 **待验证**：头部相机分辨率/FPS/FOV、实际双目基线、左右帧硬同步、
`FOUNDATION_STEREO` 输出单位/置信度/帧率/延迟、当前 1.9.0 实机是否部署该
模块、头部 LiDAR 精确型号和相机-LiDAR 标定值。

## 方案能力对比

| 方案 | 深度密度 | 公制尺度 | 优点 | 主要缺点 |
| --- | --- | --- | --- | --- |
| RGB + 单目深度网络 | 稠密 | 可能漂移 | 单相机、语义边界较好 | 绝对尺度与跨场景一致性弱 |
| RGB + LiDAR 投影 | 稀疏 | 强 | 量程大、尺度可靠 | 点稀疏、遮挡和时间同步困难 |
| 左右 RGB 双目 | 稠密/半稠密 | 标定后公制 | 与 RGB 像素天然对应 | 纹理弱、反光、重复纹理易失败 |
| 主动 RGB-D | 稠密 | 强 | 近距稳定、集成同步 | 阳光、反射和透明物体仍可能失败 |
| 双目 + LiDAR + 腕部 RGB-D | 多尺度 | 强 | 兼顾密度、量程和近距精度 | 标定和置信度融合较复杂 |

## 腕部与头部的精度比较

当前项目已经验证使用右腕对齐 RGB-D 完成粗选和精感知；头部
`FOUNDATION_STEREO` 目前只有官方 API/示例证据，尚无当前实机误差数据。
因此现阶段证据等级是“腕部链路已用、头部能力已文档化但性能待测”，不能把
`high-precision` 名称直接转换成比腕部更高的毫米级结论。

| 维度 | 腕部 RGB-D | 头部双目/双目+LiDAR |
| --- | --- | --- |
| 观察距离 | 可主动靠近目标，通常更短 | 通常在远中距看全局 |
| 目标像素数 | 多，边缘和局部细节更清楚 | 距离远时明显下降 |
| 深度随机误差 | 近距离通常更小 | 双目误差随距离近似按 `Z²` 增长 |
| RGB-depth 对齐 | 原生同模组，SDK 使用同 optical frame | 左右目需校正；LiDAR 还需跨传感器标定 |
| 坐标变换 | 依赖手眼标定、腕部/TCP 和臂关节时刻状态 | 依赖头部相机、LiDAR、颈部/升降 TF |
| 遮挡 | 可选近距观察姿态，但可能被夹爪遮挡 | 视野大，但抓取时可能被双臂/箱体遮挡 |
| 最佳职责 | 最终 6D 位姿和抓取复核 | 全局发现、粗位姿、观察位和远距几何 |

距离通常比“头部基线可能更大”更影响抓取精度。作为条件示例，假设两者像素
焦距相近、头部基线是腕部的 2 倍：腕部在 0.6 m、头部在 1.5 m 时，按双目
理论式计算，头部深度随机误差仍约为腕部的 `3.1 倍`；头部在 2.0 m 时约为
`5.6 倍`。这不是本机实测，但说明近距离腕部视角通常更适合精抓。

同样假设 `f=700 px`、箱体可见宽度 0.4 m，箱体横向像素宽度约为：

| 观察距离 | 箱体宽度 |
| ---: | ---: |
| 0.6 m | 467 px |
| 0.8 m | 350 px |
| 1.5 m | 187 px |
| 2.0 m | 140 px |

像素数减少会同时影响 mask 边缘、角点、姿态轴和遮挡判断。实际数值应换成
本机 `K[0]` 与真实观察距离。

还必须区分四层误差：原始深度、RGB-depth 对齐、物体 6D 位姿、最终 TCP
目标。当前生产目标不是纯相机输出，而是在 FoundationPose 结果后叠加左右 TCP
`[-35,-50,0] mm`/`[-35,+50,0] mm` 操作员标定，并强制目标 RPY 为零。因此
成功抓取是整条系统有效的证据，不是腕部深度相机绝对精度的直接测量。

## RGB + LiDAR 的实际上限

标定并同步后，可把 LiDAR 点变换并投影到 RGB：

```text
p_camera = R_camera_lidar * p_lidar + t_camera_lidar
u = fx * X/Z + cx
v = fy * Y/Z + cy
```

同一像素有多个点时要做 z-buffer/遮挡处理，保存相机光轴方向的 `Z`，不能把
LiDAR 射线距离直接当作图像深度。

以已观测的 19,968 点/帧为起点，如果 LiDAR 水平覆盖约 360°、相机水平 FOV
约 90°，暂按方位均匀估算，画面每帧直接命中约 5,000 点，相当于：

- `640x480` 图像约 1.6% 像素；
- `1280x720` 图像约 0.54% 像素。

这是条件估算而非 S1 画面实测，Livox 扫描也不是规则像素栅格。多帧累积和
引导插值能提高覆盖，但插值像素不是新的直接测量；机器人或物体运动时还必须
逐点做时间补偿。因此它能实现优质彩色点云或稀疏 RGB-D，不能仅靠插值宣称
与单帧稠密硬件深度相机等价。

## 双目深度误差估算

校正双目满足：

```text
Z = f * B / d
sigma_Z ~= Z^2 * sigma_d / (f * B)
```

`f` 是像素焦距、`B` 是基线、`d` 是视差。误差随距离近似按 `Z²` 增长。
下表假设 `f=700 px`、视差误差 `sigma_d=0.5 px`，不含标定、纹理、遮挡、
滚动快门和模型系统误差：

| 距离 Z | B=60 mm | B=100 mm | B=150 mm |
| ---: | ---: | ---: | ---: |
| 0.5 m | 3.0 mm | 1.8 mm | 1.2 mm |
| 1.0 m | 11.9 mm | 7.1 mm | 4.8 mm |
| 2.0 m | 47.6 mm | 28.6 mm | 19.0 mm |
| 3.0 m | 107 mm | 64 mm | 43 mm |
| 5.0 m | 298 mm | 179 mm | 119 mm |

若达到 `0.25 px` 亚像素误差，数值减半；若实际约 `1 px`，则加倍。没有实际
`f/B/sigma_d` 前，不能宣称 S1 头部具有固定厘米级精度。拿到左右
`CameraInfo.P` 后即可替换假设，得到本机理论曲线。

作为“深度相机效果”的参考类别（不是推断 S1 腕部相机型号），Orbbec Gemini 2
官方参数为主动双目 IR、50 mm 基线、`1280x800@30 fps` 深度、`0.15--10 m`
范围，在 2 m/指定 ROI 与高反射率平面条件下深度精度不超过 2%。S1 官方没有
公开头部双目的对应数字，因此现在只能确认它具备高精度双目接口，不能确认已
达到这些指标。

## 分任务结论

| 任务 | 结论 |
| --- | --- |
| 彩色点云/RViz | RGB+LiDAR 足够，可实现 |
| 导航、建图、大障碍 | LiDAR/TSDF 为主，双目补充 |
| 0.8--2 m 货箱粗位姿 | 双目+LiDAR 可行，必须输出置信度 |
| 逐像素语义 RGB-D | 用 `FOUNDATION_STEREO`；LiDAR 作公制锚点 |
| 小零件、薄杆、精确边缘 | 头部 LiDAR 易漏点，双目也会在遮挡边缘失真 |
| 最终双臂抓取对准 | 不建议只靠头部；保留腕部 RGB-D 近距离复核 |
| 透明、镜面、纯黑、无纹理物体 | 各方案都有失败模式，需失败检测和多视角 |

## 推荐实现与验收门槛

1. 左右头部 RGB 经 `FOUNDATION_STEREO` 生成深度和有效掩码。
2. 头部 LiDAR 点按时间补偿后投影到左目校正图像，作为公制尺度和远距锚点。
3. 单目/LingBot 类深度只用于补洞或先验，尺度由双目/LiDAR 约束；保留
   `lidar/stereo/inferred` 来源和置信度，避免无条件覆盖物体边缘。
4. 输出时间戳、frame、内参、深度单位、有效掩码和置信度，而非只有伪彩图。
5. 到观察位后用腕部 RGB-D 重新估计箱体 6D 位姿，再进入抓取规划。

以下为建议工程门槛，不是 S1 已验证指标：

| 项目 | 建议值 |
| --- | --- |
| 双目标定重投影 RMS | `<=0.5--1.0 px` |
| LiDAR-RGB 边缘重投影 | 中位数 `<=2 px`，P95 `<=5 px` |
| 时间差 | 静态 `<=20 ms`；运动融合目标 `<=5 ms` |
| 0.8 m 平面中位绝对误差 | `<=10 mm` |
| 1.5 m 平面中位绝对误差 | `<=20 mm` |
| 2.0 m 参考级指标 | `<=2%`，并报告 P95 和有效像素率 |
| 纹理良好箱体 ROI 有效率 | `>=90%` |
| 粗箱体 6D 位姿 | 平移 RMSE `<=20 mm`，姿态 RMSE `<=2°` |
| 最终抓取前腕部复核 | 平移目标建议 `<=10--15 mm`，按夹爪容差实测 |

测试至少覆盖 `0.5/0.8/1/1.5/2/3/5 m`、白墙、纸箱、黑色表面、反光膜、
货架遮挡边缘、静止和运动；逐项报告 bias、MAE、RMSE、P95、有效率、延迟和
帧间抖动，不能只凭伪彩深度图观感验收。

## 后续最小验证

得到新的实机访问授权后，依次只读/被动核验：

1. 当前 GBS/SDK 版本和 `FOUNDATION_STEREO` 是否存在；
2. 左右头部相机一帧 header、分辨率、格式与时间戳差；
3. 左右 `K/D/R/P`，计算实际 `fB` 与基线；
4. 相机与 `head_lidar_base_link` 的时刻一致 TF；
5. 一帧 stereo 原始数组的 shape、dtype、单位、有效范围和耗时；
6. 静态平面上的双目、LiDAR 与测距真值对照。

文件检查不会产生物理运动；实际采集会新增 reader 和少量系统负载，仍需另行
明确授权并限时执行。
