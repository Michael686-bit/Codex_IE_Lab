# 17路任务采集：先遥操，后按键录制（自动预热）

```bash
bash teleoperation/run_capture_pilot.sh --execute --seconds 1800 --target-episodes 5 \
  --speed-rad-s 1.0 --gripper-speed-m-s 0.16 \
  --task "将展开的毛巾对折并叠整齐"
```

命令配置检查：追加`--dry-run`，不会连接设备或发送运动命令。

## 操作顺序（自动预热，先遥操后录制）

1. 启动脚本时自动预热17路采集连接，等待“启动完成”。这一步不创建episode，不录制演示，不发送运动指令。
2. 对齐需要操作的主从臂至READY，按本侧固定键开启遥操作。左右独立，可以只开启左臂，右臂保持LOCKED。
3. 遥操已正常后，第一次按记录键：设置正式开始时间，进入RECORDING。
4. 再次按记录键：结束本条，FINALIZING落盘，完成后回ARMED（采集待命）。遥操继续。
5. 下一条仍是记录键开始、再次结束，不重新初始化SDK。

首次先做10–15秒短动作。启动时等待自动预热即可，不再需要手动按一次准备键。1800秒是首次跟随后的会话上限（30分钟），包含段间操作；接近上限时完成当前条目后退出另开会话。

## 取消与停止

- RECORDING时按取消键：结束本条并标失败，保存后回ARMED，遥操继续。
- ARMED时按取消键：提示当前没有录制，保持连接和遥操，不关闭SDK。
- FINALIZING期间重复按键不排队执行。
- 暂停某臂使用本侧固定键；任一STOP=-1仍全局急停，Ctrl+C走原退出清理。
- 自动预热失败时不进入遥操循环，显示错误；不能在已经跟随时重新初始化SDK。
- 结束录制不等于暂停机械臂。原300ms目标更新、速度和限位保护保留。

记录键：左索引1或右索引10；取消键：左8或右17。左右任选其一。按键辨识使用`bash teleoperation/run_dual_arm_capture.sh --controls-only --seconds 30`。

## 参数与文件

关节默认1.0rad/s，瞬时速度保护1.2倍，持续速度保护1.1倍超过150ms；夹爪默认0.16m/s。启动测时只用于控制补偿，不代表多传感器物理同步。没有双臂互碰或环境避障，保持工作区和急停条件。

全部17路原件：6RGB＋2深度＋5组关节＋2腕力＋2夹爪；PC控制日志另存实际接受的目标和下发时间。未操作通道不会伪造action。

PC会话：`lerobot_runs/dual_arm_capture_日期_时间_PID/`。G1原件：`/home/galbot/vla_capture/data/capture_sessions/<session_id>/episode_******/`。每条单独分片与清单，取消准备不会生成空演示。

退出后按终端实际目录取回：

```bash
python3 -B -m acquisition.lerobot_capture.fetch lerobot_runs/dual_arm_capture_实际目录
```

G1仍保留20GiB磁盘空闲下限；文件校验通过不代表时序或任务成功。原始数据保留training_ready=false，仍需动作导出和物理时序验收。

v0.3使用独立部署目录capture-v030-20260923；原始单次传感器检查仍使用v0.2.1。新增状态机和持久SDK采集需现场验证，不将离线测试等同真机动态验收。

## 五组采集进度

`--target-episodes`默认5，试采入口`--seconds`默认1800、最大1800秒。终端每0.5秒显示本次会话已完成/目标组数、取消/失败组数、已发起组数、当前组时长、完成组累计时长及已落盘原始记录总数。条数在每组落盘后更新，同时打印17路各自条数；包含原始录制尾部缓冲，不是10Hz LeRobot帧数。

只有按记录键正常结束（操作者标成功）且收到原始落盘完成结果，才计入完成组数。按取消键结束的组保留文件但不计入五组目标；FINALIZING期间不提前计数。达到五组只提示，遥操仍在继续：用各侧固定键暂停双臂，再Ctrl+C退出。完成数不代表时间对齐或任务质量已验收。

计数只覆盖本次启动的会话，重新启动从0开始。故障或退出时被中断的组不计入完成目标；最终状态以各组manifest为准。1800秒包含段间复位时间；到会话时限仍沿用原有停止和收尾逻辑，不会因录制未完成而延长控制。
