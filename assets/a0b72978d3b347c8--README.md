# G1 牛奶任务 SmolVLA 初步训练

从项目根目录运行。使用已有 `lerobot-act-smolvla:0.4.4-cu128` 镜像和缓存的 SmolVLA 基础权重；无联网、上传或机器人控制。三批原件及数据集只读，输出在 `/mnt/data/VLA_data/smolvla_runs/` 的独立目录。

```bash
# 20步短训练，等待结束；用于检查反向传播和保存
bash lerobot_deploy/scripts/train_milk_smolvla.sh smoke

# 后台启动2000步初步微调，打印RUN_DIR
bash lerobot_deploy/scripts/train_milk_smolvla.sh start

# 自定义步数等；每次创建新实验，不覆盖旧结果
bash lerobot_deploy/scripts/train_milk_smolvla.sh start --steps 2000 --batch-size 1 --lr 0.0001

# 查看进度 / 跟随控制台日志；将RUN_DIR换成启动时的完整路径
bash lerobot_deploy/scripts/train_milk_smolvla.sh status RUN_DIR
bash lerobot_deploy/scripts/train_milk_smolvla.sh logs RUN_DIR
```

## 下一轮20k入口（由用户手动启动）

```bash
# 仅查看最终命令，不启动训练
bash lerobot_deploy/scripts/train_milk_smolvla_20k.sh --dry-run

# 从缓存基础权重重新开始，最多训练20,000步
bash lerobot_deploy/scripts/train_milk_smolvla_20k.sh
```

20k指这个新实验的优化器更新步数，起点为基础预训练权重，不是接着2k再训练20k。之前2k的优化器已完成自己的衰减周期，当前脚本没有无缝续训实现。

新入口使用batch=1、lr=1e-4、1000步warmup，每500步验证、每1000步及验证改进时保存。没有自动早停；最终选择`best_checkpoint.json`指向的模型，不能把最后一步自动当作最好。验证仍是7条留出示教上的56个固定起点，三批32/7划分和质量规则不变。仍然没有LoRA，因此rank不适用。

根据2k实验约8分钟的实测，20k可先预留约1～1.5小时；这只是估计，受GPU负载、读盘和保存速度影响。此脚本的`--help`、`--dry-run`均不启动Docker或训练。启动后会打印独立RUN_DIR，使用通用入口的`status`或`logs`查看进度。

## 数据与模型

固定读取14:21、14:58、15:44三批已校验v3数据集，合计39条。每批按固定seed分层留出，合计32条训练、7条验证，示教身份使用会话+episode。源文件哈希在每次启动时核对；第1/17误触和失败排除已经体现在源导出中。程序不合并或改写v3元数据。

只选择当前观测通过 `quality.temporal_match_valid` 且动作有效的起点，并要求未来50步动作都有效、完整且位于同一个原始episode。保留时间轴，不删帧拼接；也不依赖SmolVLA当前版本对动作尾部padding字段的处理。50步在10Hz下对应5秒的训练目标；这不构成实机5秒开环执行建议。

状态/动作各8维，顺序为左臂J1～J7（rad）+夹爪（m）。三路RGB直接声明为头左、左腕、右前环视，模型内部按512像素边框缩放填充。沿用SmolVLA基础权重的视觉冻结/动作专家训练配置和官方flow-matching损失，模型内部padding维度保持32。

归一化仅使用训练episodes：状态使用时序检查通过的帧，动作使用有效SDK已接受目标。验证集不会参与统计。验证loss使用固定、按验证episode分层的样本和固定随机噪声种子；保存的是离线flow-matching loss，不是抓取成功率。

默认batch=1、2000步、学习率1e-4、前100步warmup后余弦衰减。每100步验证，每250步保存；验证改进时也保存检查点。内置优化器为官方AdamW预设。自定义循环用于显式多批次采样和离线验证，不是未经修改的官方CLI训练入口。

## 输出

- `status.json`：实时步骤、验证结果、显存及失败原因。
- `metrics.jsonl`：训练/验证损失和检查点事件。
- `split_and_sampling.json`：源文件哈希、整组划分、原始帧索引、归一化统计。
- `validation_anchors.json`：固定验证样本与噪声种子。
- `checkpoints/step_xxxxxx/pretrained_model/`：官方格式权重、8维配置、预处理/后处理与统计量。
- `optimizer_state.pt`：优化器、调度器及部分RNG状态，供调试；当前脚本不提供精确续训命令（未保存DataLoader当前排列/游标），不要声称可无缝resume。
- `latest_checkpoint.json`、`best_checkpoint.json`：最新/最佳已训练权重。若训练没有优于基础权重，best文件可能不存在，`status.json`会保留best_step=0。
- `src/`：本次执行脚本快照。

`/output`是容器内的本次RUN_DIR；检查点指针中的路径映射到对应宿主机RUN_DIR。实验结束后容器保留以便查看日志。

## 已知限制

质量筛选没有标定相机曝光时间，也没有解决环视约0.39秒表观时间差与在线因果对应。数据仍是单任务、有限场景示教。所有模型均标记为未验收实机部署，必须单独验证真实闭环表现；训练loss下降不能替代实机任务成功率。

生成损失曲线（系统Python需有matplotlib）：

```bash
python3 lerobot_deploy/scripts/milk_training/plot_metrics.py RUN_DIR
```

## 从2k备份继续一个低学习率阶段（仅用户执行）

备份在 `/mnt/data/VLA_data/smolvla_runs/backups/milk_2k_20261008`，包含2k权重、优化器、划分及统计量、原执行脚本和哈希清单。同盘独立副本可防误覆盖，不提供磁盘硬件故障冗余。

```bash
bash lerobot_deploy/scripts/continue_milk_smolvla_2k.sh --dry-run
bash lerobot_deploy/scripts/continue_milk_smolvla_2k.sh
```

加载备份的2k权重，额外最多2000步（累计最多4000步）。采用新的AdamW优化器及新学习率计划，lr=1e-5、100步warmup，验证每100步、保存每250步，连续5次验证未改善则提前停止。同样冻结VLM、训练动作专家及投影层，不使用LoRA。

这是权重续训的新实验分支，不是恢复旧2k运行的优化器/采样器游标。新日志`step`表示本阶段更新数，`cumulative_step`表示累计数。原2k模型继续保留为基线；若新分支没有改善，使用`baseline_checkpoint.json`指向的初始模型。初始化时严格核对数据划分和归一化一致性。

可由用户执行 `--verify-init-only` 只重载并评估初始化权重、执行0次优化器更新。此新入口尚未实际运行训练验证；已完成语法、dry-run及数据隔离检查，实际初始化结果会写入新RUN_DIR的`status.json`。所有训练启动、续训和短训练均由用户手动执行。

## 实时控制台和暂停含义

续训入口默认启动后台容器并立即跟随日志，输出`[TRAIN]`、`[VAL]`、`[SAVE]`。每10步显示本阶段进度、累计步数、train_loss、最新一次val_loss及其验证步数、学习率、梯度、耗时和ETA；验证仍每100步执行。`metrics.jsonl`保持机器可读JSON。

`--dry-run`仅打印命令，执行0步，不创建训练容器。`--background`启动后直接返回终端。默认跟随日志时，Ctrl+C仅退出日志查看，后台训练继续。

内存暂停用`docker pause 容器名`，原进程仍存在时用`docker unpause 容器名`继续。该方式不支持关机/重启后恢复；关机前需确认检查点完成并停止容器。当前脚本没有自动重启或精确resume功能，不要用`docker start`旧容器恢复（原输出目录会触发防覆盖检查）。关机后只能基于已落盘检查点另开权重续训阶段；优化器、调度器及采样游标的精确恢复仍需要单独实现。
