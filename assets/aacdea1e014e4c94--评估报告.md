# G1 摄像头、腕力与 LeRobot 数据集实测评估

检查时间：2026-09-18T10:03:51.195333+08:00 起。

结论：当前暴露的 8 路 RGB、2 路腕部深度及左右腕六维力/力矩均有持续更新的可读数据。支持构建 LeRobot 数据集，已完成本地实际写入、回读验证。相机精密标定、力传感器绝对精度及长期连续采集未验证；现有采集适配器尚未实现完整多模态演示录制，不能直接判为训练就绪。

## 范围与方法

- 真机：银河通用 G1，galbot-echo / 10.34.216.136，硬件 2.2，固件 GBS_1.17.0.0.rc7。
- 采用机器上现有 SDK 的只读客户端读取；没有发送运动命令，没有归零或标定传感器，没有启停机器人服务或修改配置。两个客户端均正常清理退出。
- 第一轮：预热 3 秒后约 20 秒轮询全部 10 路图像流和 2 路腕力；保存逐帧时间戳、负载哈希、大小及抽样解码统计。
- 第二轮：约 5 秒专门高频读取腕力；约 10 秒检查 SDK get_synced_observation，取得 94 组不同锚点的同步观测。
- 8 张 RGB 预览均人工查看：场景可辨，没有全黑、全白、花屏或明显镜头遮挡；腕部画面可见夹爪和地面。环视画面有鱼眼/去畸变效果，未验证几何精度。
- 原始来源见 results.json、sync_results.json；统计见 summary.json、sync_summary.json；可复现脚本见 probe.py、sync_probe.py。

## 各相机结果

8 台彩色相机；两路深度属于腕部 RGB-D 相机的额外输出，不是另外两台相机。

|---|---|---:|---:|---:|---|
| 头部左目 | 1280×960 | 295 | 14.68 | 78.3 ms | 连续数据可用 |
| 头部右目 | 1280×960 | 292 | 14.58 | 81.4 ms | 连续数据可用 |
| 左腕 RGB | 1280×720 | 293 | 14.65 | 44.3 ms | 连续数据可用 |
| 右腕 RGB | 1280×720 | 295 | 14.75 | 51.3 ms | 连续数据可用 |
| 左腕深度 | 1280×720 | 292 | 14.65 | 48.0 ms | 连续数据可用 |
| 右腕深度 | 1280×720 | 294 | 14.75 | 59.5 ms | 连续数据可用 |
| 左前环视 | 1280×960 | 197 | 9.85 | 142.5 ms | 连续数据可用 |
| 右前环视 | 1280×960 | 198 | 9.95 | 146.2 ms | 连续数据可用 |
| 左后环视 | 1280×960 | 198 | 9.95 | 153.6 ms | 连续数据可用 |
| 右后环视 | 1280×960 | 198 | 9.95 | 165.2 ms | 连续数据可用 |

所有通道均未读到空数据、未出现时间戳倒退；每路不同时间戳对应的负载哈希均不同，没有发现冻结帧。RGB 共抽检 68 帧、深度共抽检 20 帧，抽检解码全部成功。未对所有 RGB 帧逐帧解码。

头部/腕部中位帧周期约 68/66.7 ms，环视约 100 ms。轮询中最大观测间隔 133–332 ms；由于本脚本同时读取、哈希并抽样解码多路图像，漏取最新缓存帧也会造成间隔，不能把这些间隔全部归为相机驱动丢帧。正式录制需分路缓存并长时间压测。

深度为 1280×720 uint16，SDK 格式 16UC1，depth_scale=10000，按厂商示例以 raw/10000 换算米。左腕有效像素占比 91.62%–92.19%，右腕 88.90%–89.65%（排除 0 与 65535）；这是当前场景可用像素比例，不是深度精度。未做已知距离标定。

当前真机 SDK SensorType 暴露上述 10 路图像流，没有暴露腕部红外或头部深度枚举，不能据此宣称这些额外通道可采集。

所有 10 路均能查询内参。腕部 CameraInfo.T 为全零，不能作为有效刚体外参；通过 get_sensor_extrinsic 已读到头左/左右腕相机相对 base_link 的有效形状变换。未校验这些外参的测量精度，动态腕部外参需随关节时间戳保存。

## 腕力与其他力相关字段

左右腕均返回 timestamp_ns、force.xyz（N）、torque.xyz（N·m）。第一轮每侧 874 个新样本；专门高频轮询每侧 579 个新样本，观测更新约 115.14 Hz，中位时间戳步长约 8.04 ms，最大间隔 36.13 ms，无时间戳倒退。115 Hz 是此次 SDK 读到的更新率，不是对传感器硬件标称采样率的证明。

| 传感器 | 平均 Fx / Fy / Fz（N） | 平均 Tx / Ty / Tz（N·m） | 力各轴标准差（N） |
|---|---|---|---|
| 左腕 | 2.193 / -13.471 / 49.496 | -0.802 / -0.099 / 0.435 | 0.117 / 0.122 / 0.110 |
| 右腕 | 16.666 / 23.191 / 16.120 | -0.541 / -0.495 / 1.140 | 0.116 / 0.127 / 0.161 |

力矩各轴标准差约 0.002–0.006 N·m；第一轮读数时间年龄 P95 约 20 ms。数据有限、持续变化且波动较小，支持“通信与静态输出正常”的结论。

**左腕合力约 51.34 N，右腕约 32.79 N。** 本次未施加已知载荷、未归零、未确认工具重力补偿状态，因此不能把这些数值直接认作接触力，也不能证明零偏、增益、符号、串扰与量程精度合格。后续接触学习应记录传感器坐标系、工具质量/质心、零偏及补偿方式，并进行已知方向/已知载荷检查。

双臂 14 个关节在首尾快照中 effort 全为 0，不能将该字段当作已验证的真实关节力矩。左右夹爪 effort 均为 100，语义与标定未确认，也不能替代六维腕力。夹爪 width=0.05 m、反馈时间戳可读；本次没有实际开合验证。

## 同步结论

以左腕 RGB 为锚点，SDK 同步接口取得 94 组：

| 数据 | 相对左腕 RGB 的偏差中位数 | 绝对偏差 P95 |
|---|---:|---:|
| 右腕 RGB | -33.04 ms | 33.15 ms |
| 头左 RGB | -13.41 ms | 77.61 ms |
| 关节状态 | 0.40 ms | 7.63 ms |
| 直接读取的最新左腕力 | 43.33 ms | 75.89 ms |
| 直接读取的最新右腕力 | 43.33 ms | 75.89 ms |

SDK 的同步接口提供相机与关节最近时间戳匹配，不代表硬件同一时刻曝光。腕力是本脚本另外读取的最新值，不属于本次同步接口结果；直接拼接会引入约 43 ms 中位偏差。环视在第一轮源时间戳到读取时刻中位约 131 ms，若与最新关节直接拼接也会错位。时间年龄包含采集、传输、SDK缓存和轮询等待，不能单独认作网络延迟。

正式采集应保存每路源时间戳与接收时间戳，在 G1 本机独立缓存图像、关节、腕力与动作指令，按统一锚点配对或对低维状态插值；超过任务允许误差时标记/丢弃，禁止静默补造同步。对齐阈值应按操作速度和接触任务决定。

## LeRobot 实证验证与缺口

本地已安装 LeRobot 0.4.4。本次建立 lerobot_observation_smoke/，使用真实只读观测完成：

- 1 个诊断 episode、20 帧，3 路 320×240 RGB H.264 视频。
- 14 维双臂关节位置、12 维左右腕 force/torque、6 个 int64 原始来源时间戳。
- 保存为 LeRobot v3.0 格式并重新加载，全部 20 帧×3 路视频可解码，低维数值和原始时间戳回读完全一致。
- 该样本仅验证格式：图像经过缩放，时间重新编号为 10 FPS，腕力未重新对齐，**没有 action 字段，不是训练演示数据**。没有上传 Hub。验证日志与结论见 lerobot_validation.log/json、verify_lerobot.py。

当前项目 lerobot_robot_galbot_g1/device.py 的 cameras={}，只提供 joint7 预览及反馈；teleoperation/arm7_recorder.py 的记录器主要保存遥操、命令和反馈 JSONL，尚未录入图像和腕力。因此“硬件可读、LeRobot 可存”已通过，但完整 recorder 仍需实现。

建议正式 schema：observation.images.head/left_wrist/right_wrist；observation.state 保存实际双臂位置和夹爪开度；observation.wrist_wrench 保存左右 6D 测量；action 保存实际发出的有单位、有时间戳的目标命令；另外保存任务、episode、传感器标定与有效性字段。力数据可存为自定义 float32 特征，若需模型消费该字段，仍要配置策略输入/处理器，不能默认任意模型会自动使用。

当前速率适合先做头部＋双腕 15 FPS 采集；如果四路环视也要求每个样本都有独立新帧，可先评估 10 FPS 统一采样。此为基于本次实测的工程建议，并未承诺持续无掉帧；当前配置不支持声称所有视角都是原生 30 FPS。

深度本次只验证读取和解析，未纳入 LeRobot 视频回读测试。不要转成 8-bit RGB 有损视频后宣称保留深度精度；应保留 uint16 无损数据和 depth_scale，并针对本地版本验证深度存储/加载或采用独立无损深度文件及索引。

第一轮 SDK 负载估算：全部图像约 74.65 MB/s，其中两路未压缩深度约 53.95 MB/s。此为按本次收到的字节数估算的应用数据量，不是跨机实测网络吞吐。正式方案宜在 G1 本机缓冲/编码后写盘，再异步传输；需要验证磁盘容量、CPU负载及长时间完整性。

尚需验收的事项：持续录制压测；相机与动作/腕力时间对齐；已知载荷腕力检查；按实际任务验证视野、深度/外参精度；完整带 action 的演示 episode 写入与训练读取。

官方格式依据：[LeRobotDataset v3.0 文档](https://huggingface.co/docs/lerobot/v0.4.4/lerobot-dataset-v3)。本报告以真机采样和本地 0.4.4 实测为主。
