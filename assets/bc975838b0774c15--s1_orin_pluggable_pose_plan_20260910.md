# S1 Orin 可插拔箱体定位：首版目标与实施计划

日期：2026-09-11。状态：P0/P1 接口与本地回放、P2 Orin 部署、P3 首轮实时联调已完成；P4 重复性测试待执行。

## 已确定目标

用户遥控机器人到 FDP 观测位并保持静止，手动触发一次程序：Orin 采集腕部
RGB-D、调用现有远端 SAM3/LingBot、完成目标确认与本地位姿计算，输出
`base_link` 下的箱体几何中心、姿态、可视化及可回放数据。
数据接口保持稳定，算法通过配置替换；首个后端为 `v5_2_v5_3b`。

左右腕均由配置选择，首轮暂默认 left，可依据实际画面切换。每次只用一侧；
不将两侧不同时间的图像混成一帧。左右腕需各自匹配 RGB/depth/K/TF，
相同接口不保证相同观测质量。优先选择目标完整、箱沿与相邻侧壁清楚的视角。

用户说明箱体可能实际倾斜。现有后端只优化 x/y/z/yaw，roll/pitch 来自
base_link 中的直立先验；不能据此报告倾斜角已经测得或中心精度已经验证。
首版是工程闭环及算法比较工具。支持倾斜的后端作为后续独立阶段，不通过
修改旧版本名称或放宽门限冒充已支持。当前不承诺精度、实时性或抓取可用性。

## 架构与接口合同（拟实施）

数据源（实时/文件回放）→ 前处理（远端服务、ROI、人工目标确认）→
统一 Observation → 可插拔 Backend → 结果校验、展示、存档。

- 数据源仅负责获取图像、标定与状态；算法不得调用 SDK 或控制接口。
- 前处理适配现有服务，保存返回数据。算法回放直接加载确认后的 Observation，
  不重新调用服务；需要重做前处理时另建运行记录，防止比较输入混淆。
- 后端接口为 `estimate(observation, model, config) -> result`，用简单模块注册表
  按名称选择。模型加载可在初始化时缓存，不要求先引入独立进程或插件平台。
- 首版接入现有 `estimate_v5_2_visibility()`，审计并冻结传递依赖、配置、模型
  与源码哈希；已有实验实现与生产代码分开，不修改 third_party。
- 配置分为采集、服务、模型、后端和输出五部分。服务凭据引用仓库外配置，
  不写入结果、源码快照或日志。配置快照仅保存非敏感值。

### Observation v1

包含 schema 版本、run/frame ID、相机侧别及 optical frame、RGB、raw 深度、
选用的处理后深度、最终确认 mask、K、`T_base_link_from_camera`、各自时间戳、
单位、目标选择记录、来源与文件哈希。深度约定为光学 Z、单位米；图像通道
顺序、分辨率与对齐关系显式声明并验证。模型/尺寸不混入观测测量值。

校验侧别与帧名、数组尺寸、有效深度、变换刚体质量、RGB/depth 与 TF 时间差。
已有时间差门限不能替代图像新鲜度：实现时核实 SDK 时钟域，采用同域年龄
检查或证明为触发后新帧的机制；时钟不明确时拒绝宣称新鲜度已验证。
采集后读取的关节状态仅作参考，点云使用图像时间对应 TF。

### Result v1

- 分开记录运行完成、拟合通过、场景适用性（适用/不适用/未知）。
- 主几何：`center_base_m` 和 `T_base_link_from_box`；中心必须等于矩阵平移列。
  箱体原点为模型合同定义的几何中心，+X/+Y/+Z 为长/宽/高，右手系、米制。
  原 mesh 原点到语义中心的变换需显式记录，不把点云质心当成箱体中心。
- 保存估计自由度、固定先验、180° 方向歧义、模型/源码/配置标识及耗时。
- 拒绝时正式中心/矩阵为空，诊断候选单独保存；对已知倾斜使用直立后端时
  标注不适用，仅输出诊断。倾斜未知不等于已证明水平，首版不承诺自动识别倾斜。
- 质量指标按后端命名保存，不跨算法直接比较分数。保持
  `accuracy_validated=false`、`grasp_ready=false`，直到有独立验证依据。
- 可选扩展为箱口中心、四角和短边点，注明模型推导或直接观测，不称为 TCP。

## 阶段、交付与完成标准

| 阶段 | 工作和交付 | 完成标准 |
|---|---|---|
| P0 接口与版本冻结 | schema、配置示例、模型坐标合同、V5 源码/依赖清单 | 输入输出语义可核验；倾斜限制与未知信息显式记录 |
| P1 本地封装与回放 | 文件数据源、V5 适配器、统一结果、诊断图、使用说明 | 同一冻结输入与原后端在记录的数值容差内一致，接受/拒绝及先验保持一致；另一测试适配器可经配置替换以验证接口，不冒充新算法 |
| P2 Orin 环境与部署 | 当前访问授权下核对架构/Python/SDK/依赖/服务入口，部署独立实验目录 | 在 Orin 回放同一数据成功；差异可解释；记录设备配置、后端耗时和内存，保留失败记录 |
| P3 单次现场闭环 | 摆位后采集、候选图确认目标、V5 计算、输出与存档 | 一次触发完成完整链路；未经确认不自动选箱；服务失败、无候选、拒绝均有明确状态且不复用旧结果 |
| P4 稳定性与左右腕对照 | 同一目标/固定机器人状态，建议每侧连续独立触发 5 次，记录场景与相机 | 报告重复性、拒绝原因、分阶段与总耗时；人工确认等待单列。少样本不宣称稳定 p95；不同目标或底盘位置不混算抖动 |
| P5 倾斜后端独立研究 | 保持相同 Observation，接入支持 roll/pitch 的新后端，与冻结 V5 对照 | 有独立中心/角度参考后评估误差、错误接受与失败；不以 FDP 差异或残差代替真值；最终算法据证据选择 |

P0～P3 为首版工程交付范围；P4 为首轮评估；P5 需单独确定算法方案后实施。
P1 测试覆盖坐标和单位错误、左右腕误配、未确认目标、拒绝/异常结果、输入
不可变及回放一致性。P2 先文件回放，P3 才执行实时采集。
相机切换通过离线测试不等于另一侧已经完成现场验证。

每次运行新建目录，保存 capture、确认前处理输入、模型/版本清单、result、
诊断图、时间统计及状态日志。运行完成不等于定位成功；不得用历史成功结果
填充本次失败。大体积资产按现有仓库规则留在版本控制外，保存索引和哈希。

## 验收边界与待补信息

首版验收关注可复现数据链路、可替换后端、坐标一致性、明确失败与实际 Orin
运行证据。暂不设未经确认的毫米/角度/秒级承诺。需在相应阶段补齐：

1. 部署前核对 Orin 当前环境、安装目录及既有服务配置；此计划不构成 SSH 或部署执行。
2. 实物型号/实测尺寸与冻结 mesh 对应待验证；未确认时所有几何结果标明模型假设。
3. 现场记录水平/倾斜/未知、目标物理身份及机器人和箱体是否移动。
4. 精度阶段确定允许误差、时间预算及独立测量参考；重复性不能替代绝对精度。

首版程序不发送机械臂、夹爪、升降或底盘运动命令。现场摆位由用户完成；
未来任何程序运动均依 AGENTS.md 另行逐步确认。

  包、脚本、schemas、tests、部署清单与历史说明。这是现有基线实验工作区。

  固定右腕；本地版本支持左右腕。V5 自身不应套用 FDP mesh 轴变换。
- 远端 README 开头仍称无实时采集，后文及现有文件已包含采集功能，属于文档
  历史残留；旧环境版本记录未在本次重新验证。不得把该目录当成本地最新完整部署。

建议新工程部署至同级 `/home/galbot/Lsy03/box_pose_pipeline/`（本次未创建），
内含版本固定的 src/configs/models/runs，旧 fdp_baseline 数据通过配置路径只读
回放。新程序复用经核验的采集/前处理逻辑及固定版本依赖，不直接依赖远端旧包
随时变化的 PYTHONPATH。SDK 采集与算法计算可沿用不同 Python 进程，以冻结
文件/Observation 为边界；实际 Python/SciPy 等兼容性在部署阶段确认。

在旧目录新建隔离子目录从权限和容量看也可行，但同级独立项目命名更符合多
后端定位，减少包名冲突和误覆盖旧实验。该选择是建议，尚未实际部署。
检查不阻塞本地接口/回放封装；落实时增加旧 case 到 Observation 的适配器，
