# 双臂与双夹爪独立遥操作实验

入口：`run_dual_arm_direct.sh`；模块：`dual_arm_direct.py`；配置：`dual_arm_direct_profile.json`。
原左臂脚本保留。双臂共用SDK实例、GP数据源、全身反馈和统一100ms轨迹更新节拍，双侧有新轨迹时合并到一次publish_target。
左右独立状态机；单侧暂停使用对应group的实测位姿保持目标，不调用全局停止接口，不切换控制器。
该保持目标的物理停止效果、双臂并行响应尚待现场验证。

## 先只读比对

```bash
bash teleoperation/run_dual_arm_direct.sh --seconds 60
```

不加 `--execute` 不发送机械臂、夹爪或底盘运动/停止命令；只读模式从进程进入循环起计时。
分别观察左右表格，缓慢逐轴移动GP右臂，核对关节顺序、角度符号和零点，再进行执行验证。
右臂映射采用明示的实验性绝对同角度映射（方向+1、比例1、零偏0），不是已完成的真机标定。
必要的方向、比例、零点可在独立双臂配置中修改。右臂限位读取右臂自己的两份URDF交集，不复制左臂限位。

## 现场执行

```bash
bash teleoperation/run_dual_arm_direct.sh --execute --seconds 600 \
  --speed-rad-s 1.0 --align-speed-rad-s 0.4
```

正式速度默认1.0rad/s，对齐默认0.4rad/s（各轴不超过正式速度），最长600秒。
执行模式从任意一臂首次进入ALIGNING开始计时，另一臂启动及暂停时间均包括在内。
`--speed-rad-s` 同时设置双臂速度，受配置上限和URDF上限限制。

| 操作 | 左侧 | 右侧 |
|---|---|---|
| 固定键 | button_state[4] | button_state[13] |
| 第一次确认 | 本臂误差<15°且静止0.5秒后慢速对齐 | 同左 |
| 第二次确认 | 本臂ALIGN_READY且误差<3°，进入FOLLOWING | 同左 |
| FOLLOWING中再按固定键 | 仅暂停左臂和保持左夹爪 | 仅暂停右臂和保持右夹爪 |
| 扳机 | axes[3]→左夹爪 | axes[4]→右夹爪 |
| 任一急停/故障/Ctrl+C/到时 | 全局停止双臂轨迹、请求底盘停止，并尝试保持双夹爪 | 同左 |

不必同时启动双臂。每侧重新开始均重新走两次确认；二次确认重复帧等待最多300ms。
固定键释放值2，活动值1/3，同一次按压只计一次，松开至少30ms后才能再次按压。
右固定键索引13有项目辨识证据；右侧完整按压释放状态机仍需现场确认。

各夹爪仅在本侧FOLLOWING后、扳机读数≥0.66时解锁；启动时一直扣住不会闭合。
0.04以下→0mm，0.35→50mm，0.66以上→100mm，SDK速度默认50mm/s，effort参数5。
本入口 `--gripper-speed-m-s` 同时控制双侧夹爪速度，不设置底盘跟随。

## 保护与日志

运行中目标越界按每侧保守限位截断，回到范围自动恢复；J7额外限制±45°。
实测越界、速度异常、15°轨迹偏差、反馈过期/倒退/断流、任何侧按钮异常、发布失败均停止双侧。
仅将腿/头部作为共同非臂监测；未启用的手臂也监测异常移动。另一臂合法运动不会触发原单臂的“非左臂运动”保护。
shell入口沿用+104ms时钟补偿，可用`--g1-clock-offset-ms`覆盖；该值并非重新测量结果。

日志：`lerobot_runs/dual_arm_direct_*.jsonl`，按arm区分状态、按键、限幅、夹爪目标和反馈，并记录组合下发结果。
全局停止后检查21关节反馈确认静止；底盘和夹爪保持请求成功不能等同于其物理停稳。
夹爪无独立stop接口，保持失败时之前的完整开合目标可能继续执行。

**没有双臂自碰撞、互碰或环境避障检查。** 首次执行应先单独验证右臂低速方向和单侧暂停，再验证双臂并行及急停。
本次实现只经过离线测试，未启动真机，不能据此宣称右臂已完成验收。

双臂默认速度已对齐左臂版：对齐0.4rad/s、正式1.0rad/s；瞬时实测超速阈值仍为对应速度的1.2倍（0.48/1.2rad/s），持续超速判据仍为1.1倍持续0.15秒。

2026-09-22：双夹爪默认速度提高为0.05m/s（50mm/s），较此前20mm/s为2.5倍；SDK声明最大0.2m/s，但本实验仍限制最大0.05m/s。
左右任一急停输出STOP=-1均进入同一全局停止路径，日志明确记录scope=global，双臂状态锁存ESTOP。本侧固定键暂停与急停是不同操作。

## 高频反馈及精确下发时间记录

默认开启，无需额外参数；原运行命令不变。控制轨迹仍为100ms段，终端仍每0.5秒刷新。
反馈采样跟随控制循环（循环含10ms休眠和SDK读写耗时），不承诺固定100Hz，更不把重复反馈当成新的设备测量。

每轮生成四个同前缀文件：

- `dual_arm_direct_日期_时间_PID.jsonl`：低频状态、按键、夹爪指令、暂停/急停等事件。
- `dual_arm_direct_日期_时间_PID.samples.jsonl`：高频反馈、主臂/目标、机械臂下发尝试和返回。
- `dual_arm_direct_日期_时间_PID.metadata.json`：关节顺序、参数、时钟解释、代码及配置哈希。
- `dual_arm_direct_日期_时间_PID.recording_status.json`：写入数量、丢失数量、未写入数量及记录错误。

`motion_feedback` 每次成功读取全身反馈记录一次，含21轴 `position_rad`、`velocity_rad_s`、`timestamps_ns`。
顺序在metadata的joint_names中明确：腿5轴、头2轴、左臂7轴、右臂7轴。
`feedback_fresh` 标明设备时间戳是否推进；分析时按设备时间戳去重，不能把主机重复轮询当成更高采样率。
`feedback_read_begin/end_monotonic_ns` 和 `feedback_read_begin/end_wall_ns` 包围SDK反馈读取及校验；
`loop_interval_ns` 反映包含终端输出、SDK调用等在内的循环间隔。

每侧 `sample` 与全身反馈共享 `sample_id`，含原始主臂角度/速度、映射后、限幅前目标raw_target、有效目标target、
从臂位置/速度/时间戳、上一条已尝试下发指令ID、上一轨迹目标和本侧状态。
`gp_received_monotonic_ns` 是该GP帧在PC输入线程的接收时间；`gp_timestamp_raw` 保留设备原值，不能假设与G1时间戳同域。

机械臂 `command_attempt` / `command` 共享 `command_id`，并引用反馈 `sample_id`。
前者记录左右轨迹起终点、速度参数、100ms段时长以及SDK目标header时间戳；后者记录：

- `publish_begin/end_monotonic_ns`：紧贴SDK调用前后的PC单调时钟。
- `publish_begin/end_wall_ns`：对应PC系统时间。
- `publish_duration_ns`：调用耗时。
- `publish_interval_ns`：相邻组合下发调用开始时间的间隔（单侧间隔需按arms过滤后重算）。
- SDK状态、accepted、error；SDK抛异常也保存调用结束时间。

夹爪正常下发与保持请求也记录调用前后时间、耗时和每侧gripper_command_id，位于事件文件。
这些是**SDK调用时间，不是硬件执行开始/结束时间**。固定时钟补偿只提供跨主机时钟近似对齐，不会消除通信和执行延迟。

采用有界后台写入队列，数据入队时复制快照，避免后续目标修改污染旧记录。
退出时尝试排空队列；记录故障在控制检查点触发停止，停止路径不会因为记录调用抛异常而被阻断。
采集后确认recording_status中 `dropped=0`、`pending=0`、`error=null`；异常记录不能当成完整训练数据。

2026-09-22 持续超速判据修正：每轮反馈校验分别维护各关节的超速计时，任一关节恢复阈值内立即清除该关节计时。
不再只在100ms轨迹更新时检查，也不把不同关节的短暂超速拼接成连续超速。阈值仍为该阶段速度的1.1倍持续150ms，瞬时1.2倍阈值不变。
