## 本版范围

独立只读 SDK 客户端记录 17 个必采流：头左右目、左右腕 RGB/深度、前方两路环视、左右腕力、chassis/head/left_arm/right_arm/leg 五组关节、左右夹爪。

这是 **observation 原始记录器**。不连接 GP001、不发送运动命令、不自动录入其他遥操进程的动作，不生成 LeRobot 数据集。`action_present=false`、`training_ready=false` 永远显式记录；完整动作事件接入、时钟映射和训练转换仍是后续工作，不能把这次试录当作训练演示。

只使用 Python 3.8+ 标准库与 G1 现有 SDK；PC 校验与恢复工具不需要 SDK。没有新增全局 Python 依赖。

## 目录与格式

每次必须指定全新目录，已有目录拒绝覆盖。

- `manifest.json`：设备/固件/SDK、运行配置、相机内参、关节顺序、URDF哈希、代码哈希、数据契约与时钟限制。
- `chunk_000000.g1raw`：已完成、fsync 的分片。记录自身带 JSON 元数据与原始负载。
- `chunk_000000.partial`：尚未关闭或中断的分片，不应直接上传为已完成数据。
- `chunks.json`：已完成分片名称、字节数、记录数、SHA256，原子更新。
- `summary.json`：complete/failed/interrupted、异常、记录数、各流计数、去重数、最大观测时间间隔、队列峰值、wall/monotonic对应样本。

v0.1.1 将预热到正式录制的间隔单列为 `warmup_to_capture_source_gap_ns`；`max_observed_source_gap_ns` 只统计正式保存记录间隔。旧 v0.1 的 10 秒样本保留原始 summary，没有改写；其正确帧间隔由 PC 全量解析报告重新统计。

二进制格式：8 字节 `G1RAW001`；之后每条记录为大端 uint32 JSON 长度＋大端 uint64 负载长度＋UTF-8 JSON＋原始负载。`payload_ref` 为 `inline_after_record_header` 与长度，文件位置由解析器确定，无需在采集线程另建外部索引。RGB 为 SDK JPEG 字节；深度为 SDK 原始 uint16，保存尺寸、depth_scale、SDK格式与机器人字节序；低维数据在 JSON 中，负载为空。每条记录及每个完成分片均有校验和。

时间戳为整数纳秒。SDK 源时间、接收 wall/monotonic、原始时钟域分别保存；`clock_segment_id=unmapped`，不使用历史固定 104 ms 偏移。底盘/夹爪 effort/腕力补偿等未确定语义原样保留，不能据此自动归一化。

## 可靠性行为

- 预热最多 25 秒，全部必采流必须至少产生两个不同时间戳；SDK进程存在但缺流不算就绪。
- 默认队列上限 128 MiB、8192 条记录；排队和正在写入的负载均计入字节上限。提交不等待慢磁盘，越界直接失败。
- 默认分片约 128 MiB；每片结束 fsync、重命名，再原子保存校验清单。
- 默认保留至少 20 GiB 空闲磁盘；不足即失败。不是持续写盘吞吐或断电耐久性认证。
- 重复源时间戳去重；源时间倒退停止。任一必采流超过 2 秒没有新数据即失败。这个超时是完整性保护，不是合格训练时间对齐阈值。
- SIGINT/SIGTERM 停止采样并尽量排空队列，标记 interrupted。写入线程最多等待 30 秒，无法排空时标记 failed，保留未完成分片。SDK清理失败也标记 failed。
- 外部杀进程/断电可能留下 partial 或缺失 summary；恢复工具只报告完整记录前缀，不会伪造完成状态。
- 与控制器完全独立；本程序不会主动停止另一个控制进程。正式联合遥操前，还需将数采故障通知接入会话管理，进行安全测试。

## G1 启动

部署到全新版本目录后，从项目根目录运行：

```bash
bash acquisition/raw_recorder/run_g1.sh \
  --contract acquisition/p0_20260920/capture_contract.v1.json \
  --output /home/galbot/vla_capture/data/唯一会话名称 \
  --seconds 10
```

短试默认约几百 MB；磁盘预算参考约 70 MB/s，但真实吞吐待验。脚本仅对子进程设置 SDK 路径、`PYTHONNOUSERSITE=1` 等环境，不改 `.bashrc` 或系统环境。最长单次 duration 参数为 3600 秒，不代表已通过一小时录制验收。

## 校验与恢复

可在 PC 或 G1 执行，不加载 SDK：

```bash
python3 -B -m acquisition.raw_recorder.verify /path/to/session
python3 -B -m acquisition.raw_recorder.recover /path/to/incomplete_session
```

`verify` 全量检查负载/分片哈希、字节数、逐流序号及时间戳、深度长度、17 流覆盖和 summary；完整录制成功才返回 0。它不负责 JPEG 视觉质量、传感器标定或训练适用性判定。

`recover` 不修改任何文件，仅统计可以完整读出且逐记录校验通过的前缀。恢复后实际重写/导出需单独工具，不能把前缀计数当作完整 episode。
