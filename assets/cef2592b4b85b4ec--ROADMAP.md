# 项目路线与架构

来源：任务“9_7 周会汇报 制定VLA实验路线方案”。本文件把汇报方案作为工程规划承接；完成状态只在 [CURRENT_STATE](CURRENT_STATE.md) 维护。

## 总体路线

GP001 遥操与 G1 相机/状态 → 原始多模态记录（规划采用 MCAP） → 时间同步、质检、episode 切分 → LeRobot 数据集 → ACT 基线、SmolVLA 主线及后续模型对比 → 工作站策略推理 → G1 安全执行适配 → 真机评测与失败数据回采。

MCAP 是拟采用的原始容器，当前 GP001 测试保存的是 JSONL。训练数据能否使用取决于观测、动作、同步和质量，不以文件扩展名判定。LeRobot 格式及转换工具版本在接入时锁定。

## 阶段门

| 阶段 | 工作 | 进入下一阶段的证据 |
|---|---|---|
| P0 控制与遥操 | 状态读取、关节与夹爪、单关节映射，逐步到单臂 | 动作/反馈一致；限速限位、使能与断流/退出行为验证；形成可复现演示 |
| P1 多模态数据 | 相机、实际机器人状态、下发动作联合录制，按任务逐步接入相机 | 首批 10 条完整 episode 可逐帧回放；时间与方向一致；缺帧/失效有记录 |
| P2 ACT 刚体取放 | 固定场景单臂取放，规划采集 80–150 条演示 | 数据、训练、推理、执行及评测闭环，得到首轮真机成功率 |
| P3 位置与语言变化 | 位置变化、红蓝物体语言选择，ACT 与 SmolVLA 对比 | 相同任务与明确数据划分下比较成功率、接管和延迟 |
| P4 大型 VLA 对比 | π0.5、LingBot 等候选；AstraBrain 厂商 PoC 可独立推进 | 核验资源/接口后，在同任务比较效果、延迟、训练与适配成本 |
| P5 柔性物体 | 方巾角搬运 → 固定初态单折 → 衣物折叠 | 先验证原子技能，再增加双臂协同和任务时长 |

ACT 为工程基线，SmolVLA 为拟定语言 VLA 主线；其余模型是后续候选。不得把模型目录占位描述为已训练或已部署。

固定场景取放 ≥80% 等汇报数字是候选验收目标，不是项目实测预测。具体评测协议需明确独立试验次数（汇报建议 50 次）、成功标准、数据划分、人工接管和失败分类后再冻结。

## 代码边界（随实现创建）

| 模块 | 职责 |
|---|---|
| `teleoperation/` | GP001 输入、网络发送/接收、映射与使能 |
| `robot_g1/` | 官方 SDK 适配、公共执行限制、状态反馈及冒烟测试；供遥操和策略执行共同复用 |
| `data_pipeline/` | 多模态录制、同步、质检、切分、LeRobot 转换 |
| `policies/` | 训练配置、模型适配及版本记录 |
| `deployment/` | 工作站推理服务、进程启动及部署清单；复用机器人适配层 |
| `evaluation/` | 任务协议、成功判定、指标、失败分析 |
| `configs/` / `tests/` | 配置示例和跨模块验证 |
| `experiments/` | 每个实验的输入、运行版本、命令、结果和证据 |

第一版优先建立 teleoperation 与 robot_g1 的实际实现。训练栈与机器人 SDK 分环境，不能假定工作站与 G1 的 Python、架构和依赖兼容。

## 首轮单关节映射边界

拟采用相对映射：`q_target = q_robot_start + scale × (q_master - q_master_start)`。这只减少启动角度不一致，仍需验证方向、单位、范围及重连行为。

首轮候选范围为左臂第 7 关节相对起点 ±2°、速度上限 0.03 rad/s。若以 20 Hz 更新，按此速度每周期位移上限约 **0.086°**；之前对话提出的 0.1–0.2°/周期不能同时被当作该速度限制，实际实现必须按经过时间计算。

200 ms 数据超时为初始设计候选，须通过链路延迟与停止试验确定。机器人端应拒绝过期/积压命令并执行已核验的停止策略；单纯停止发送不是已验证的保持机制。
