# Galbot G1 单臂微动作冒烟测试

这个实验用于验证 G1 Python SDK 的机械臂关节位置控制链路。默认模式初始化 SDK、读取一侧机械臂状态、验证连续递增的反馈时间戳、解析 URDF 限位并显示计划，不调用 `set_joint_positions()`。因此它是“无运动命令模式”，不是完全离线模式。

## 已核对的 G1 环境

- Ubuntu 20.04.6 LTS，aarch64
- `/usr/bin/python3`，Python 3.8.10
- Galbot SDK 1.9.0
- 机器人发布版 Python 模块：`/data/galbot/lib/galbot_sdk`
- SDK 环境脚本：`/opt/galbot/galbot_sdk/linux-aarch64-gcc940/setup.sh`
- 运动规划和机器人状态服务运行于 `/data/galbot/bin/`

请始终通过启动器运行，避免非交互 SSH 环境缺少 `PYTHONPATH`：

```bash
cd /home/galbot/g1_arm_smoke_test_20260904
./run_g1_arm_smoke_test.sh
```

上面是默认 dry-run。它会生成日志并明确打印“未调用 set_joint_positions()”。

## 真机微动作

只有现场人员满足以下条件时才能进入真机测试：

1. 物理急停可立即触达，并清楚其正确操作方式。
2. 机器人周围至少约 2 米无人、无障碍物。
3. 没有其他程序或人员控制机械臂。
4. 已目视确认当前姿态、所选关节和运动方向安全。

建议的首个候选是左臂第 7 关节正向 1 度、最大速度 `0.03 rad/s`：

```bash
./run_g1_arm_smoke_test.sh \
  --execute \
  --arm left \
  --joint-index 7 \
  --delta-deg 1.0 \
  --speed-rad-s 0.03
```

脚本随后显示实际关节名、当前位置、目标和 URDF 限位，并要求准确输入包含实际关节名和带符号增量的确认语句。例如：

```text
MOVE LEFT_ARM_JOINT7 +1.000 DEG
```

输入不匹配、非交互执行、状态不稳定、反馈时间戳未更新或数据年龄超过 1 秒、数据无效、目标靠近限位、SDK/配置不匹配或任一步骤反馈异常时，脚本都会中止。静止状态要求至少 4 个新帧覆盖 0.3 秒，速度不超过 `0.002 rad/s`。默认反馈容差为 `0.2` 度，并且真机模式强制要求容差小于动作幅度的一半。

## 运动顺序

1. 将当前读数作为目标，验证控制链路。
2. 使用显式 `joint_names` 仅向所选关节发送一个很小的相对角度目标，不重发整臂位置。
3. 读取反馈并检查到位误差。
4. 保持结束后重新读取连续新帧并复核当前姿态。
5. 仅在复核成功时自动返回原位，再次检查反馈。

失败后不会自动重试，也不会在状态异常时盲目反向运动。运动流程开始后的异常会尝试调用 SDK 文档定义为“停止当前轨迹并保持当前位置”的 `stop_trajectory_execution()`，随后记录一帧新反馈；该接口仍不能替代物理急停。SDK 清理流程是 `request_shutdown()` → `wait_for_shutdown()` → `destroy()`，清理失败会让程序以非零状态退出。

## 重要限制

- 低速和微小角度不等于绝对安全。
- `set_joint_positions()` 没有文档承诺的环境碰撞检测能力。
- SDK 清理和 `Ctrl+C` 都不能替代物理急停。
- 本脚本不测试底盘、腿部、头部、另一侧机械臂或夹爪。
- 首次真机运动必须由现场人员在 G1 旁执行，不能无人值守运行。
- 左右臂共用一个机器人级进程锁，防止本实验脚本并发运行；它不能检测所有第三方控制程序，因此仍需现场确认。

2026-09-04 的 dry-run 显示当前收拢姿态中两侧第 5/6 关节接近硬限位。脚本会打印警告并且不会向这些轴下发目标；首个候选只使用第 7 关节。每次真机实验前必须重新运行 dry-run，以现场最新状态为准。

查看参数：

```bash
./run_g1_arm_smoke_test.sh --help
```

日志保存在脚本目录下的 `logs/`。
