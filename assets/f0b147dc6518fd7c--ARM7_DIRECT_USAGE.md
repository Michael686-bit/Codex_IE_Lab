# 左臂七关节直接遥操作实验（无碰撞检查）

新入口：run_arm7_direct.sh；程序：arm7_direct.py；独立配置：arm7_direct_profile.json。
本实验按用户要求排除碰撞查询，用于判断跟随链路能否运行。这不证明原碰撞接口有问题。

## 与旧脚本的关系

原run_arm7_follow_collision.sh及其配置、碰撞工作进程保留。
新程序只初始化GalbotRobot，不实例化GalbotMotion，不创建CollisionWorker，不伪造“碰撞通过”结果。
复用原模块中的数值映射、反馈、限位与轨迹构造函数；导入这些函数不执行碰撞查询。
新旧七关节入口共用宿主互斥锁，新入口还检查J7入口锁；禁止多个遥操客户端同时运行。

## 运行

现场先确认机械臂活动空间：这个版本没有自碰撞、桌面、墙壁或工具避障保护。

只读检查：

```bash
cd "/home/lsy03/文档/ChatGPT/VLA G1 项目"
bash teleoperation/run_arm7_direct.sh --seconds 30 --start-control left-button
```

真机实验：

```bash
bash teleoperation/run_arm7_direct.sh --execute --seconds 30 --start-control left-button
```

两次确认启动：READY后按左臂固定键开始慢速对齐；ALIGN_READY后再次按键进入正式跟随；正式跟随中再次按键停止锁定。Ctrl+C退出。停止后重新走两次确认。
默认不加--execute时不会发布目标；只读模式不会模拟从臂真实运动，二次确认仍取决于实测角度差。
首次进入慢速对齐后开始计时（默认30秒），慢速对齐、二次确认等待及暂停均计入；首次按键前的人工对齐等待不计时。

left-button是默认输入方式。若需键盘调试，可改为--start-control keyboard，两次回车执行同样的两阶段流程。
已复核原始标定：button_state[4]完整活动序列为2→1→3→2；1/3计为同一次活动。
1/2/3之外的未知值会锁定。可先使用--controls-only采集固定键，确认一次按压只产生一次单击。

左右急停输出STOP=-1时，在两种控制模式下均优先处理；执行模式请求停止全局关节轨迹和底盘，退出本轮，不自动恢复。
这是软件停止，不能替代硬件急停。关节停稳须有新鲜反馈确认；底盘当前只确认停止请求返回成功。

## 参数及证据边界

- 只发送left_arm_joint1～7；右臂、腿和头部用于状态监测。
- GP驱动角度直接映射，方向+1、比例1、零偏0；配置标记experimental，没有伪称标定验收完成，也不修改旧配置validated门控。
- 启动每关节角度差<15°，全身静止0.5秒；第一次确认进入慢速对齐。
- 七关节默认目标速度1.0rad/s，100ms目标段。独立入口已移除±1°反馈窗口和持续1秒退出；已发目标与实测偏差超过15°立即退出。
- J7绝对[-45°,45°]；J1～J6使用两份URDF交集并内缩3°。
- GP/G1断流、超速、运行偏差、非左臂运动、控制器错误或取消会请求停止；启动反馈可在10秒内等待。
- 独立日志lerobot_runs/arm7_direct_*.jsonl标明collision_check=false。command事件为SDK提交结果，不等于机械运动已验收。

模拟测试覆盖无点击不动、启停和重新启动、每段速度上限、只读不发布、急停优先、断流/未知按键停止、15°及绝对限位拒绝。
入口测试在没有GalbotMotion/CollisionWorker能力的假SDK下运行，确保执行链不依赖碰撞检查。

## 七关节速度配置

配置文件各 joints 条目的 speed_rad_s 为目标速度，顶层 speed_limits_rad_s 为按J1～J7排列的七个允许上限。默认均为1.0rad/s。
命令行 --speed-rad-s 和 --speed-limit-rad-s 分别覆盖这两项；各接受1个统一值或7个关节值，仅对本次运行生效。
要求 0 < 目标速度 ≤ 配置上限 ≤ 两份URDF速度上限的交集，否则拒绝启动。
两份本地URDF的J1～J7均声明1.5rad/s（约85.94°/s），这是模型限制，尚未确认为硬件物理最大速度。

例如将本轮七关节设为0.5rad/s：

```bash
bash teleoperation/run_arm7_direct.sh --execute --seconds 30 --start-control left-button --speed-rad-s 0.5 --speed-limit-rad-s 0.5
```

逐关节设置时，按J1～J7给值，如 --speed-rad-s 0.5 0.5 0.4 0.4 0.3 0.3 0.3 --speed-limit-rad-s 0.5。
启动终端和start日志会列出实际使用值。速度配置控制轨迹段角度增量，并不保证实测速度达到设定值。
实测超速保护仍为：任一关节超过该关节目标速度的1.2倍立即拒绝；超过1.1倍持续0.15秒拒绝。
本次没有增加加速度/jerk限幅器，URDF中的这些字段不代表本脚本已经实施相应限幅。

## 二次对齐启动

- READY：每关节主从差<15°且其他检查通过；第一次按左臂固定键。
- ALIGNING：跟随实时GP目标，默认最高0.4rad/s（--align-speed-rad-s可设置；各轴不超过其正式跟随速度）。主臂尽量保持稳定。
- ALIGN_READY：七关节实测主从差全部<3°，仍维持慢速；必须在提示之后松开再按一次固定键，才进入正式跟随。误差重新达到3°时撤销就绪。
- FOLLOWING：使用正式配置速度（当前每关节1.0rad/s）；再次按键停止锁定。
- 慢速对齐未满足二次确认条件时按键会停止锁定；不会缓存提前按键用于稍后自动提速。
- 急停、断流、限位、实测超速及15°轨迹偏差保护覆盖慢速和正式跟随阶段。
- 固定键沿用button_state[4]：2为松开，1/3为同一次按键活动；松开至少30ms才重新接受按压。实际设备信号仍需现场验证。

## G1 时钟补偿

`run_arm7_direct.sh` 默认传入 `--g1-clock-offset-ms 104`，表示 G1 系统时钟比 PC 快 104ms。
原有命令无需调整；显式追加同名参数可以覆盖该值，例如校时后使用 `--g1-clock-offset-ms 0`。
直接调用 Python 模块时默认补偿为 0。

补偿后反馈年龄 = PC 当前时间 − G1 原始反馈时间戳 + 补偿值。
主循环全身反馈检查、发布前过期检查、停止后的静止确认统一应用此补偿。
原始反馈及目标指令时间戳不改写；补偿值输出到终端并写入 start 日志的 g1_clock_offset_ms。
300ms 过期、300ms 未推进、时间戳倒退及轴间跨度检查保留。
104ms 来自本次人工测量，不会自动跟踪漂移；重新校时、重启或偏差变化后应重新测量并更新参数。

左扳机比例控制左夹爪的独立入口为 `run_arm7_direct_gripper.sh`，见 [夹爪版使用说明](ARM7_DIRECT_GRIPPER_USAGE.md)。原入口仍不启用夹爪。
