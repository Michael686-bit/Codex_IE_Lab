# A0与4090逐阶段对比：定位matmul TF32差异 — 2026-09-24

**确认一个主要原因：本次Orin运行环境的`torch.backends.cuda.matmul.allow_tf32=True`，4090为False。只在Orin独立进程关闭该开关，其他参数和AMP保持不变，原两超限帧中心差从10.764/10.937mm降为1.265/0.159mm。随后28帧验证全部满足10mm及逐轴4°，中心差中位0.165mm。仍有渲染/网络残差，不宣称两端逐位一致或所有因素都已解释。**

## 复现与实验范围

D01、C08 R01…093900（实际左腕）、C09 R01…094033（右腕）用于阶段采集。4090使用生产相同解释器/导入路径/权重的新独立诊断进程；原7876服务代码、配置、PID均不修改，不向其注入或重启。Orin使用固定镜像、无网络只读Docker。

两端先跑各自无插桩基线，再采集同3帧中间量。插桩前后位姿逐矩阵一致；独立4090输出逐矩阵复现历史API响应，原Orin输出逐矩阵复现新A0，因此中间量对比与原问题对应。

采集全部252候选的初始和各轮位姿、网络输出、全候选评分。大型RGB/XYZ张量保存全量哈希与固定8候选切片：0/9/30/72/96/105/126/198；切片误差不冒充全量最大误差。

## 真正未对齐的精度开关

| 开关 | 原Orin | 4090 | 单因素修正后的Orin |
|---|---|---|---|
| `cuda.matmul.allow_tf32` | **True** | **False** | **False** |
| `cudnn.allow_tf32` | True | True | True（不改） |
| 网络AMP | True | True | True（不改） |

输入张量同为float32，不保证矩阵乘法使用相同的数值精度路径。该开关影响网络外的几何矩阵计算/裁剪以及相关float32矩阵运算；本轮不是关闭整个AMP，也不是同时改变所有精度选项。修正语句在FDP初始化与GPU矩阵计算之前执行：

```python
torch.backends.cuda.matmul.allow_tf32 = False
```

## 单项修正的直接证据

关闭该开关后，三帧第一轮真实观测RGB/XYZ分支（network input B）的全部252候选哈希都与4090完全一致。合成渲染分支（A）仍有小幅残差，不能说所有输入都已完全一致。

| D01 | 0.844313 | 0.262638 | 105 | 33 | 33 |
| C08 | 10.764224 | 1.265445 | 96 | 6 | 6 |

C09同一候选198在第一轮后的两端中心差，从约6.059mm降至0.071mm；第三轮从约10.937mm降至0.159mm。单开关干预与阶段输入差异消失共同支持因果作用，而不只是不同版本的相关性。

## 仍需保留的边界

- 关闭TF32后，真实裁剪分支第一轮完全对齐；渲染分支仍有残差。nvdiffrast 0.3.3/0.4.0、Torch/CUDA/cuDNN及GPU实现差异仍存在，不能把所有剩余误差归给某一个库。
- 大型图像张量的数值误差只统计保存的8个候选切片；全量相等结论来自全部252候选的哈希。
- 3帧阶段采集不是完整28帧中间量复核；28帧验证只记录最终输出。
- 既有A0–A4速度/精度表基于旧TF32设置，不能直接套到修正后配置。下一轮应显式固定该开关后重新验收A1–A4，不能据此宣布0.7秒版本已达标。
- 此次只改独立实验进程状态，未部署到生产；4090原服务PID327624、启动时间及监听均保持。
