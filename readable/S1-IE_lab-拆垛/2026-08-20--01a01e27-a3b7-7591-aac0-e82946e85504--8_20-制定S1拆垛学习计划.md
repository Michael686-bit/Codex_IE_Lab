## 4. 助手

是的，**你需要先学会机械臂的基本运动控制，但不需要先成为机器人学专家**。

拆垛不是“识别到箱子，机械臂就自动过去”这么简单，而是一个完整闭环：

```text
相机采集
→ 找到最适合先抓的物体
→ 估计物体位姿
→ 计算抓取位姿
→ 机械臂规划无碰路径
→ 接近并抓取
→ 搬运并放置
→ 检查是否成功
→ 继续下一件
```

你提到的名称很可能是：

- **FoundationPose**：根据图像、深度和物体模型估计物体的 6D 位姿。
- **LingBot-Depth**：估计或优化深度信息。
- **SAM / SAM3**：把目标物体从图像中分割出来。

这些属于“眼睛和空间理解”。机械臂控制、IMC、IRMV_DUAL_ARM 等更接近“手和运动规划”。这些名称目前来自历史项目资料，实际在 S1 上部署了什么版本、接口是否可运行，后续必须从代码或机器人环境验证。

# 从零到 S1 拆垛学习计划

不按死板的周数走，按“能完成的里程碑”推进。每一步都要有一个可运行的小实验。

## 阶段 0：先理解拆垛任务

目标：知道系统到底要解决什么。

需要理解：

- 什么是拆垛、码垛、抓取、放置。
- 规则垛和杂乱垛有什么区别。
- 箱子、袋子、料箱等物体的抓取方式为什么不同。
- 单臂抓取和双臂协作的差别。
- 固定底座和移动底盘作业的差别。
- 为什么必须有失败检测和恢复。

第一个产出：

- 画出 S1 拆垛流程图。
- 明确一个最小任务，例如：
  - 固定位置放一个已知纸箱；
  - 使用单臂；
  - 从上方抓取；
  - 移到旁边固定放置点；
  - 暂时不移动底盘。

这是我们的第一版 MVP。先不要一开始就挑战完整货垛、双臂和移动底盘。

## 阶段 1：认识 S1 和 Galbot SDK

目标：能读懂最小 SDK 示例，知道机器人有哪些可控部件。

学习内容：

- Python 基础：变量、函数、类、列表、异常处理。
- Linux 基础：目录、终端、运行脚本、查看日志。
- SDK 初始化和关闭。
- S1 的设备组成：
  - 左右机械臂；
  - 夹爪；
  - 升降机构；
  - 头部和相机；
  - 移动底盘。
- 读取关节位置、控制状态和错误状态。
- 阻塞与非阻塞命令。
- 关节限位、速度和控制状态的含义。

实践顺序：

1. 本地阅读 SDK 示例。
2. 找出初始化、读状态、发命令和释放资源的代码。
3. 写一个不连接机器人的代码阅读笔记。
4. 获得明确授权后，才连接机器人读取状态。
5. 暂不执行运动。

通过标准：你能够指出一段 SDK 代码会影响机械臂、夹爪、升降机构还是底盘。

## 阶段 2：机械臂运动基础

目标：理解“让机械臂到达哪里”到底是什么意思。

必须掌握的概念：

- 关节空间：直接指定每个关节的角度。
- 笛卡尔空间：指定末端执行器的位置和方向。
- 末端执行器、工具中心点 TCP。
- 位姿：位置 \(x,y,z\) 加方向。
- 弧度、米、毫米以及单位错误。
- 正运动学 FK：关节角 → 末端位姿。
- 逆运动学 IK：末端位姿 → 关节角。
- 坐标系：
  - 世界/地图坐标系；
  - 机器人基座坐标系；
  - 相机坐标系；
  - 机械臂末端坐标系；
  - 物体坐标系。
- 奇异位形、关节限位、自碰撞和环境碰撞。

小实验：

1. 给定一组关节角，观察 FK 结果。
2. 给定一个末端位姿，调用 IK，只计算、不执行。
3. 检查 IK 是否有解、是否超限。
4. 在仿真或离线规划中生成一条轨迹。
5. 最后才考虑真机的单关节微小运动。

通过标准：你能解释“相机说物体在某处”为什么不能直接作为机械臂目标。

## 阶段 3：掌握最小抓取动作

目标：先不使用复杂视觉，完成一个已知目标的抓取动作链。

把一次抓取分解成：

1. 打开夹爪。
2. 到达预抓取位姿。
3. 沿安全方向接近。
4. 闭合夹爪。
5. 判断是否抓住。
6. 垂直抬升。
7. 搬运到放置区域。
8. 下降。
9. 松开夹爪。
10. 安全撤离。

需要学习：

- 预抓取位姿和抓取位姿。
- 接近方向。
- 抓取宽度和夹爪力度。
- 笔直末端运动与普通关节规划的区别。
- 抓取后为何需要先抬升再横向移动。
- 超时、规划失败、夹爪未抓住时怎么办。

通过标准：在仿真中或仅做离线轨迹检查时，完整生成一次 pick-and-place 动作。

## 阶段 4：学习运动规划系统

目标：弄清 Galbot SDK、IMC、IRMV_DUAL_ARM 各自负责什么。

需要验证的工作链可能是：

```text
目标抓取位姿
→ IRMV_DUAL_ARM / 上层接口
→ IMC 运动规划与控制
→ Galbot SDK
→ S1 硬件
```

这一结构目前仍是**待验证**，不能仅凭历史聊天认定。

学习内容：

- 机器人模型和关节组。
- IK 求解。
- 碰撞模型。
- 规划场景。
- 轨迹规划。
- 轨迹时间参数化。
- 规划与执行为什么要分开。
- 单臂与双臂规划的区别。

实践：

1. 从代码找到一个目标位姿的入口。
2. 跟踪它经过哪些模块。
3. 只规划，不执行。
4. 查看轨迹是否超限或发生碰撞。
5. 最后形成一张真实的软件调用关系图。

## 阶段 5：RGB-D 视觉基础

目标：从相机数据得到物体的三维位置。

学习内容：

- RGB 图像、深度图、相机内参。
- 像素坐标如何变成三维点。
- 深度缺失和噪声。
- 点云是什么。
- 平面检测：找到桌面或货垛表面。
- 目标分割：从图像中得到物体 mask。
- 物体包围框、中心和朝向。

推荐实践：

1. 读取一组离线 RGB-D 数据。
2. 查看同一像素的颜色和深度。
3. 把深度图转换成点云。
4. 分割桌面和单个箱子。
5. 得到箱子在相机坐标系中的三维位置。

这一步先使用离线数据，不要求机械臂运动。

## 阶段 6：FoundationPose、LingBot-Depth 等现有方案

目标：搞清 S1 当前到底有什么，而不是重新造一套。

需要调查：

- 相关代码是否真实存在。
- 是部署在 S1 本体、外部工作站还是历史目录。
- 输入是什么：RGB、原始深度、mask、CAD 模型？
- 输出是什么：物体位姿、点云还是抓取位姿？
- FoundationPose 的模型和版本。
- LingBot-Depth 是直接生成深度还是修复深度。
- 坐标系、单位、模型尺度。
- 是否已经连接到 IMC/双臂规划。
- 是否有可复现的离线样例。
- 是否有真实拆垛演示以及对应日志。

实践顺序：

1. 先运行一个离线样例。
2. 保存输入图、mask、深度和位姿结果。
3. 把预测位姿画回图像或点云。
4. 人工判断结果是否正确。
5. 重复测试不同角度、遮挡和光照。
6. 验证输出坐标系后再连接规划器。

重要提醒：如果目标只是规则纸箱，未必一开始就需要 FoundationPose。平面检测、点云包围盒和几何抓取可能更容易建立第一个闭环。FoundationPose 更适合需要物体模型和完整 6D 位姿的情况。

## 阶段 7：手眼标定与坐标变换

目标：把“相机看到的位置”正确转换成“机械臂能到的位置”。

这是拆垛里最关键、也最容易出错的一环。

学习内容：

- 相机外参。
- 手眼标定。
- 齐次变换矩阵。
- 相机坐标系 → 基座坐标系。
- 物体位姿 → 抓取位姿。
- 工具长度和夹爪 TCP 偏移。
- 时间同步以及机器人运动时相机数据滞后。

通过标准：

- 用一个已知位置的静态物体测试变换。
- 只计算目标点，不运动。
- 误差达到任务允许范围后，才进入真实接近实验。

## 阶段 8：完成单物体拆取闭环

目标：让系统自主完成一次最简单的抓取。

第一版条件应尽量简单：

- 固定底盘。
- 单臂。
- 单个已知箱子。
- 无严重遮挡。
- 从上方抓取。
- 固定放置位置。
- 低速运行。
- 每一步都允许人工确认。

成功标准：

- 能稳定检测物体。
- 位姿方向没有明显错误。
- 规划无碰撞。
- 能抓起并放下。
- 每一步有状态和日志。
- 失败时停止，不盲目继续。

## 阶段 9：从单物体升级到真正拆垛

目标：处理多个物体、遮挡和货垛约束。

新增问题：

- 应该先抓哪一个。
- 上层物体是否遮挡下层。
- 抽取一个箱子会不会导致货垛倒塌。
- 机械臂能否安全接近。
- 箱子之间是否贴得太紧。
- 抓取后是否真的离开货垛。
- 识别失败、滑落、空抓时如何重试。
- 是否需要升降机构、双臂或底盘调整位置。

推荐升级顺序：

1. 两个分开的箱子。
2. 两个上下堆叠的箱子。
3. 规则的 2×2 小货垛。
4. 多层规则货垛。
5. 有轻微位置偏差的货垛。
6. 遮挡和混乱场景。
7. 需要升降、双臂或移动底盘的场景。

# 我们的实际学习方式

每一课都采用这个循环：

```text
先讲一个概念
→ 阅读一小段真实代码
→ 预测代码结果
→ 离线或仿真运行
→ 检查输出
→ 记录结论和问题
→ 再决定是否进行真机实验
```

真机阶段不自动连接、不自动运动。每一次真实运动前，都要重新说明：

- 哪个设备会动；
- 运动方向和数值范围；
- 是否涉及左臂、右臂、夹爪、升降机构或底盘；
- 速度；
- 碰撞空间；
- 急停是否可用；
- 停止和恢复方法。

# 建议我们马上开始的第一课

第一课先做：

**“认识 S1 的控制层，并读懂一个只读取机械臂状态的 SDK 程序。”**

这一课不连接机器人、不运动机器人。我们会依次搞明白：

1. S1 有哪些设备组；
2. 一组机械臂关节数据代表什么；
3. SDK 程序如何初始化；
4. 如何读取状态；
5. 哪些语句只是读取，哪些语句会真的触发运动；
6. 如何避免再次把 `zero`、`home` 和“原始姿态”混为一谈。

总的学习主线可以概括为：

> **先会安全地读状态，再会计算运动；先在离线或仿真中规划，再做微小真机动作；先抓一个静止箱子，再做完整货垛。**


这一步只阅读代码，之后如需在 S1 上读取实时状态，也要单独授权远端访问。

验收标准：给你一组左右臂关节值，你能说明它们属于哪个关节组、单位是什么，以及它们不等于末端位置。

### 第二阶段：关节空间控制

学习：

```python
robot.get_joint_names(...)
robot.get_joint_positions(...)
robot.set_joint_positions(...)
```

需要理解：

- 关节组和单独关节的区别；
- 绝对目标与相对偏移；
- 阻塞和非阻塞调用；
- 速度、超时和返回状态；
- 为什么 `ControlStatus.SUCCESS` 只表示命令执行成功；
- 为什么不能默认把“回到零”理解为安全恢复。

现有 `test_left_arm_micro_move.py` 可作为代码阅读材料，但暂时不运行。

它历史上曾执行：

```text
设备：左机械臂
动作：left_arm_joint1 增加 0.1 rad，再返回实测初始值
速度：0.1 rad/s
不涉及：右臂、夹爪、躯干、底盘
```

以后如果重新做真机实验，仍需重新确认现场空间、急停和当前姿态。

### 第三阶段：末端位姿与 FK/IK

这是抓取真正需要的部分。

学习：

- `base_link`；
- `left_TCP_link`、`right_TCP_link`；
- 位置 \(x,y,z\)；
- 旋转矩阵和四元数；
- FK：关节角变成末端位姿；
- IK：末端目标变成关节角；
- IK 多解、无解、关节限位和初始种子。

SDK 中已经有：

```python
motion.get_robot_states()
motion.inverse_kinematics(...)
motion.inverse_kinematics_by_state(...)
```

这一阶段只计算和打印结果，不执行轨迹。

验收标准：给定一个末端目标，你能判断 IK 是否成功，并检查返回的关节角是否合理。

### 第四阶段：运动规划

需要分清：

```text
目标位姿
→ IK
→ 路径规划
→ 碰撞检查
→ 轨迹
→ 执行
```

重点学习：

- PTP：适合从一个姿态移动到另一个姿态；
- LIN：末端沿近似直线接近、内收或抬升；
- 自碰撞；
- 左右臂互相碰撞；
- 夹爪和箱体碰撞模型；
- 起始状态与轨迹首点是否一致；
- `check_collision=false` 为什么不能作为安全结果。

先读取历史 IMC 轨迹并画图，不执行。

### 第五阶段：轨迹执行

这一阶段才研究：

- `execute_joint_trajectory`；
- 批量关节命令；
- 执行状态；
- 超时；
- 软件停止；
- 轨迹中断后机器人实际停在哪里；
- 为什么恢复前必须重新读取完整状态。

真实实验顺序应当是：

```text
离线轨迹
→ 只规划
→ 人工审查
→ 单臂、空载、低速、小范围
→ 验证实际误差
→ 再增加动作距离
```

### 第六阶段：抓取动作

最后把机械臂和夹爪组合起来：

```text
开爪
→ PTP 到预抓位姿
→ LIN 接近
→ 合爪
→ 判断接触
→ LIN 抬升
→ 搬运
→ 放置
→ 开爪
→ 撤离
```

然后升级为 S1 当前的双臂 Mode 00：

```text
左右臂预抓
→ 同步内收 100 mm
→ 双 GE103 合爪
→ 同步抬升 100 mm
```

## 我们现在怎么开始

第一课题目：

> S1 左右机械臂的关节状态是什么，以及哪些 SDK 调用只读取、哪些会运动。

第一课分三步：

1. 逐行阅读 `read_robot_state.py`。
2. 画出 `GalbotRobot.init → get_joint_names/get_joint_states → shutdown` 的调用流程。
3. 建立一张 API 分类表：

| API | 类型 | 是否可能运动 |
|---|---|---|
| `get_joint_names` | 读取 | 否 |
| `get_joint_states` | 读取 | 否 |
| `get_joint_positions` | 读取 | 否 |
| `set_joint_positions` | 控制 | 是 |
| `inverse_kinematics` | 计算 | 通常不直接运动 |
| `execute_joint_trajectory` | 执行 | 是 |

完成第一课后，再做一个完全离线的小练习：把左臂关节弧度转换成角度，并比较运动前后的关节误差。这样我们会从真正理解机械臂开始，而不是先背控制命令。
