## 4. 助手

是的，**你需要先学会机械臂的基本运动控制，但不需要先成为机器人学专家**。

拆垛不是“识别到箱子，机械臂就自动过去”这么简单，而是一个完整闭环：

```text
相机采集
→ 找到最适合先抓的物体
→ 估计物体位姿
→ 计算抓取位姿
→ 机械臂规划无碰路径
→ 接近并抓取
→ 搬运并放置
→ 检查是否成功
→ 继续下一件
```

你提到的名称很可能是：

- **FoundationPose**：根据图像、深度和物体模型估计物体的 6D 位姿。
- **LingBot-Depth**：估计或优化深度信息。
- **SAM / SAM3**：把目标物体从图像中分割出来。

这些属于“眼睛和空间理解”。机械臂控制、IMC、IRMV_DUAL_ARM 等更接近“手和运动规划”。这些名称目前来自历史项目资料，实际在 S1 上部署了什么版本、接口是否可运行，后续必须从代码或机器人环境验证。

# 从零到 S1 拆垛学习计划

不按死板的周数走，按“能完成的里程碑”推进。每一步都要有一个可运行的小实验。

## 阶段 0：先理解拆垛任务

目标：知道系统到底要解决什么。

需要理解：

- 什么是拆垛、码垛、抓取、放置。
- 规则垛和杂乱垛有什么区别。
- 箱子、袋子、料箱等物体的抓取方式为什么不同。
- 单臂抓取和双臂协作的差别。
- 固定底座和移动底盘作业的差别。
- 为什么必须有失败检测和恢复。

第一个产出：

- 画出 S1 拆垛流程图。
- 明确一个最小任务，例如：
  - 固定位置放一个已知纸箱；
  - 使用单臂；
  - 从上方抓取；
  - 移到旁边固定放置点；
  - 暂时不移动底盘。

这是我们的第一版 MVP。先不要一开始就挑战完整货垛、双臂和移动底盘。

## 阶段 1：认识 S1 和 Galbot SDK

目标：能读懂最小 SDK 示例，知道机器人有哪些可控部件。

学习内容：

- Python 基础：变量、函数、类、列表、异常处理。
- Linux 基础：目录、终端、运行脚本、查看日志。
- SDK 初始化和关闭。
- S1 的设备组成：
  - 左右机械臂；
  - 夹爪；
  - 升降机构；
  - 头部和相机；
  - 移动底盘。
- 读取关节位置、控制状态和错误状态。
- 阻塞与非阻塞命令。
- 关节限位、速度和控制状态的含义。

实践顺序：

1. 本地阅读 SDK 示例。
2. 找出初始化、读状态、发命令和释放资源的代码。
3. 写一个不连接机器人的代码阅读笔记。
4. 获得明确授权后，才连接机器人读取状态。
5. 暂不执行运动。

通过标准：你能够指出一段 SDK 代码会影响机械臂、夹爪、升降机构还是底盘。

## 阶段 2：机械臂运动基础

目标：理解“让机械臂到达哪里”到底是什么意思。

必须掌握的概念：

- 关节空间：直接指定每个关节的角度。
- 笛卡尔空间：指定末端执行器的位置和方向。
- 末端执行器、工具中心点 TCP。
- 位姿：位置 \(x,y,z\) 加方向。
- 弧度、米、毫米以及单位错误。
- 正运动学 FK：关节角 → 末端位姿。
- 逆运动学 IK：末端位姿 → 关节角。
- 坐标系：
  - 世界/地图坐标系；
  - 机器人基座坐标系；
  - 相机坐标系；
  - 机械臂末端坐标系；
  - 物体坐标系。
- 奇异位形、关节限位、自碰撞和环境碰撞。

小实验：

1. 给定一组关节角，观察 FK 结果。
2. 给定一个末端位姿，调用 IK，只计算、不执行。
3. 检查 IK 是否有解、是否超限。
4. 在仿真或离线规划中生成一条轨迹。
5. 最后才考虑真机的单关节微小运动。

通过标准：你能解释“相机说物体在某处”为什么不能直接作为机械臂目标。

## 阶段 3：掌握最小抓取动作

目标：先不使用复杂视觉，完成一个已知目标的抓取动作链。

把一次抓取分解成：

1. 打开夹爪。
2. 到达预抓取位姿。
3. 沿安全方向接近。
4. 闭合夹爪。
5. 判断是否抓住。
6. 垂直抬升。
7. 搬运到放置区域。
8. 下降。
9. 松开夹爪。
10. 安全撤离。

需要学习：

- 预抓取位姿和抓取位姿。
- 接近方向。
- 抓取宽度和夹爪力度。
- 笔直末端运动与普通关节规划的区别。
- 抓取后为何需要先抬升再横向移动。
- 超时、规划失败、夹爪未抓住时怎么办。

通过标准：在仿真中或仅做离线轨迹检查时，完整生成一次 pick-and-place 动作。

## 阶段 4：学习运动规划系统

目标：弄清 Galbot SDK、IMC、IRMV_DUAL_ARM 各自负责什么。

需要验证的工作链可能是：

```text
目标抓取位姿
→ IRMV_DUAL_ARM / 上层接口
→ IMC 运动规划与控制
→ Galbot SDK
→ S1 硬件
```

这一结构目前仍是**待验证**，不能仅凭历史聊天认定。

学习内容：

- 机器人模型和关节组。
- IK 求解。
- 碰撞模型。
- 规划场景。
- 轨迹规划。
- 轨迹时间参数化。
- 规划与执行为什么要分开。
- 单臂与双臂规划的区别。

实践：

1. 从代码找到一个目标位姿的入口。
2. 跟踪它经过哪些模块。
3. 只规划，不执行。
4. 查看轨迹是否超限或发生碰撞。
5. 最后形成一张真实的软件调用关系图。

## 阶段 5：RGB-D 视觉基础

目标：从相机数据得到物体的三维位置。

学习内容：

- RGB 图像、深度图、相机内参。
- 像素坐标如何变成三维点。
- 深度缺失和噪声。
- 点云是什么。
- 平面检测：找到桌面或货垛表面。
- 目标分割：从图像中得到物体 mask。
- 物体包围框、中心和朝向。

推荐实践：

1. 读取一组离线 RGB-D 数据。
2. 查看同一像素的颜色和深度。
3. 把深度图转换成点云。
4. 分割桌面和单个箱子。
5. 得到箱子在相机坐标系中的三维位置。

这一步先使用离线数据，不要求机械臂运动。

## 阶段 6：FoundationPose、LingBot-Depth 等现有方案

目标：搞清 S1 当前到底有什么，而不是重新造一套。

需要调查：

- 相关代码是否真实存在。
- 是部署在 S1 本体、外部工作站还是历史目录。
- 输入是什么：RGB、原始深度、mask、CAD 模型？
- 输出是什么：物体位姿、点云还是抓取位姿？
- FoundationPose 的模型和版本。
- LingBot-Depth 是直接生成深度还是修复深度。
- 坐标系、单位、模型尺度。
- 是否已经连接到 IMC/双臂规划。
- 是否有可复现的离线样例。
- 是否有真实拆垛演示以及对应日志。

实践顺序：

1. 先运行一个离线样例。
2. 保存输入图、mask、深度和位姿结果。
3. 把预测位姿画回图像或点云。
4. 人工判断结果是否正确。
5. 重复测试不同角度、遮挡和光照。
6. 验证输出坐标系后再连接规划器。

重要提醒：如果目标只是规则纸箱，未必一开始就需要 FoundationPose。平面检测、点云包围盒和几何抓取可能更容易建立第一个闭环。FoundationPose 更适合需要物体模型和完整 6D 位姿的情况。

## 阶段 7：手眼标定与坐标变换

目标：把“相机看到的位置”正确转换成“机械臂能到的位置”。

这是拆垛里最关键、也最容易出错的一环。

学习内容：

- 相机外参。
- 手眼标定。
- 齐次变换矩阵。
- 相机坐标系 → 基座坐标系。
- 物体位姿 → 抓取位姿。
- 工具长度和夹爪 TCP 偏移。
- 时间同步以及机器人运动时相机数据滞后。

通过标准：

- 用一个已知位置的静态物体测试变换。
- 只计算目标点，不运动。
- 误差达到任务允许范围后，才进入真实接近实验。

## 阶段 8：完成单物体拆取闭环

目标：让系统自主完成一次最简单的抓取。

第一版条件应尽量简单：

- 固定底盘。
- 单臂。
- 单个已知箱子。
- 无严重遮挡。
- 从上方抓取。
- 固定放置位置。
- 低速运行。
- 每一步都允许人工确认。

成功标准：

- 能稳定检测物体。
- 位姿方向没有明显错误。
- 规划无碰撞。
- 能抓起并放下。
- 每一步有状态和日志。
- 失败时停止，不盲目继续。

## 阶段 9：从单物体升级到真正拆垛

目标：处理多个物体、遮挡和货垛约束。

新增问题：

- 应该先抓哪一个。
- 上层物体是否遮挡下层。
- 抽取一个箱子会不会导致货垛倒塌。
- 机械臂能否安全接近。
- 箱子之间是否贴得太紧。
- 抓取后是否真的离开货垛。
- 识别失败、滑落、空抓时如何重试。
- 是否需要升降机构、双臂或底盘调整位置。

推荐升级顺序：

1. 两个分开的箱子。
2. 两个上下堆叠的箱子。
3. 规则的 2×2 小货垛。
4. 多层规则货垛。
5. 有轻微位置偏差的货垛。
6. 遮挡和混乱场景。
7. 需要升降、双臂或移动底盘的场景。

# 我们的实际学习方式

每一课都采用这个循环：

```text
先讲一个概念
→ 阅读一小段真实代码
→ 预测代码结果
→ 离线或仿真运行
→ 检查输出
→ 记录结论和问题
→ 再决定是否进行真机实验
```

真机阶段不自动连接、不自动运动。每一次真实运动前，都要重新说明：

- 哪个设备会动；
- 运动方向和数值范围；
- 是否涉及左臂、右臂、夹爪、升降机构或底盘；
- 速度；
- 碰撞空间；
- 急停是否可用；
- 停止和恢复方法。

# 建议我们马上开始的第一课

第一课先做：

**“认识 S1 的控制层，并读懂一个只读取机械臂状态的 SDK 程序。”**

这一课不连接机器人、不运动机器人。我们会依次搞明白：

1. S1 有哪些设备组；
2. 一组机械臂关节数据代表什么；
3. SDK 程序如何初始化；
4. 如何读取状态；
5. 哪些语句只是读取，哪些语句会真的触发运动；
6. 如何避免再次把 `zero`、`home` 和“原始姿态”混为一谈。

总的学习主线可以概括为：

> **先会安全地读状态，再会计算运动；先在离线或仿真中规划，再做微小真机动作；先抓一个静止箱子，再做完整货垛。**

## 55. 助手

这两个字段可以先这样理解：

## `effort=0.000000`

`effort` 通常表示关节输出力矩或关节负载反馈。

但是，在你当前的 S1 + SDK 状态读取链路中，七个机械臂关节全部返回：

```text
effort=0.000000
```

这**不能解释为机械臂实际承受零力矩**。机械臂保持当前姿态时，电机通常仍需对抗重力。

本地 SDK 类型说明存在一个关键差异：

- `JointCommand.effort` 被注明为关节扭矩，单位 N·m；
- `JointState.effort` 没有注明单位或 S1 驱动映射；
- 对普通机械臂关节，SDK 说明控制命令主要使用 `position` 字段。

所以当前最稳妥的结论是：

> 这条状态链路中的 `effort` 很可能没有被底层驱动填充、没有开放估算值，或者使用 `0` 作为默认值。

目前应把它标记为“状态字段存在，但语义待验证”，不能用于判断机械臂有没有受力、是否碰撞或者抓取是否成功。

## `current=-0.008000`

`current` 很可能表示电机电流反馈，但当前 SDK 类型说明没有写明单位。

负号通常只表示：

- 电机电流方向；
- 电机输出力矩方向；
- 或驱动器定义的关节正负方向。

它不代表“负电流故障”，也不表示电机在发电。

如果单位最终确认是安培，那么：

```text
-0.008 A = -8 mA
```

但现在不能直接确认它就是安培，也不能通过一个电流值直接换算关节扭矩，因为还需要：

```text
电流
× 电机力矩常数
× 减速比
× 传动效率
× 驱动器内部缩放
= 关节输出扭矩
```

这些参数和字段缩放目前都没有确认。

## 为什么静止时电流不全是零

即使机械臂不动，控制器也可能持续输出电流来：

- 抵抗重力；
- 保持关节位置；
- 补偿摩擦；
- 修正微小位置误差。

你这次的速度值最大约为：

```text
0.000180 rad/s
```

非常接近零，可以认为采样时左臂基本静止。此时存在小的带符号 `current` 是合理现象。

## 4. 使用 `try/finally`

```python
try:
    ...
finally:
    ...
```

这是脚本里非常重要的安全结构。

> 无论读取成功，还是中途发生 Python 异常，最后都尽量释放 SDK 资源。

- 初始化 SDK；
- 连接机器人服务；
- 准备接收实时状态。

`bool(...)` 把返回结果转换为：

```python

False  # 初始化失败
```

如果失败：

```python

```

会立即抛出异常，不再读取后续数据。

## 7. 三个状态读取接口

### `get_joint_names`



主动关节就是由执行器控制、真正参与运动的关节。固定连接或非主动关节不会列出。

```python
    "left_arm_joint7",
```

### `get_joint_positions`

```python
robot.get_joint_positions(group, [])
```

两个参数分别是：

```text

指定关节名称列表
```

```python
robot.get_joint_states(group, [])
```

## 8. `enumerate` 是什么

```python
for index, name in enumerate(joint_names):
```

假设：


会打印：

索引从零开始，这是 Python 的基本规则。

## 9. `.6f` 是什么

```python

```

这是 Python 的格式化字符串。

`.6f` 表示：

- 按浮点数打印；
- 保留小数点后六位。

例如：

```python

```

输出为：

```text
0.778807
```

它只改变显示方式，不改变原始变量的数值。

## 10. 状态和名称怎样对应


## 11. 为什么 `position` 被读取了两遍

脚本先读取：

## SDK 中的几种控制层次

### 1. 单目标位置控制

```python
set_joint_positions(...)
```

特点：

- 输入目标角度；
- 用 `speed_rad_s` 限制最大速度；
- SDK 内部生成简单轨迹；
- 适合姿态切换和初学小幅实验；
- 不适合在循环中高频反复调用。

这是我们初学阶段使用的方法。

### 2. 高频关节位置指令

```python
set_joint_commands(
    joint_commands,
    joint_groups,
    joint_names,
    time_from_start_s,
)
```

适合高频控制或模型逐帧输出。

但对普通机械臂关节，本地 1.9.x 接口明确说明：

> `JointCommand` 中只有 `position` 生效，`velocity`、`effort/current` 等字段会被忽略。

也就是说，这不是直接填写：

```python
joint_cmd.velocity = 0.1
```

就能实现机械臂速度控制。它仍然主要发送位置，只是以较高频率连续更新位置目标。官方也把它描述为直接向底层控制器发送高频关节命令。[Galbot 官方 Python 示例](https://developer.galbot.com/docs/SDK/1.8.1/g1/en/examples_python/)

例如每 10 ms 更新一次位置：

```text
q(t)
q(t + 0.01)
q(t + 0.02)
...
```

这些位置点之间的变化形成实际速度。这种方法风险更高，需要自己保证：

- 控制周期稳定；
- 位置连续；
- 速度和加速度不跳变；
- 关节不超限；
- 通信中断时能够停止。

目前不适合拿真机练习。

### 3. 批量轨迹

```python
set_joint_commands_batch(trajectory)
```

一次提交多个带时间戳的轨迹点：

```text
0.0 s → q0
0.1 s → q1
0.2 s → q2
0.3 s → q3
```

速度由相邻位置和时间间隔共同决定：

\[
v \approx \frac{q_{i+1}-q_i}{t_{i+1}-t_i}
\]

适合：

- 平滑的多关节轨迹；
- VLA 或策略模型批量输出；
- 自定义轨迹跟踪。

它是非阻塞接口，提交成功不表示轨迹已经执行完成。

### 4. 执行完整轨迹

```python
execute_joint_trajectory(
    trajectory,
    is_blocking=True,
)
```

适合执行已经生成的 `Trajectory`。轨迹中可以包含多个关节位置和对应时间。

对抓取来说，通常更接近：

```text
规划器生成轨迹
→ 人工/程序检查
→ execute_joint_trajectory
```

而不是直接对单个关节连续调用 `set_joint_positions()`。

## 有没有真正的“纯速度控制”

在我们检查的 S1 1.9.x Python 接口中，没有确认存在类似下面这样的机械臂接口：

```python
set_arm_velocity([v1, v2, ..., v7])
```

`set_base_velocity()` 是底盘速度接口，不是机械臂接口。

因此当前可确认的是：

- `set_joint_positions()`：目标位置加最大速度限制；
- `set_joint_commands()`：高频位置目标；
- `set_joint_commands_batch()`：批量时间轨迹；
- `execute_joint_trajectory()`：执行完整轨迹；
- 没有确认机械臂开放独立、持续的关节速度模式。

## 对我们学习最合适的顺序

```text
set_joint_positions
→ 理解速度限制和阻塞
→ 离线生成多点轨迹
→ 计算相邻点速度
→ 学习 execute_joint_trajectory
→ 再研究 IMC 的 PTP/LIN
```

对于抓箱，最终更重要的是：

- PTP 到预抓位置；
- LIN 直线接近；
- LIN 直线抬升；
- 规划器控制速度、加速度、轨迹连续性和碰撞。

所以现在先把 `set_joint_positions()` 学清楚是合适的，但它只是机械臂控制的第一层，不是最终抓取方案。
