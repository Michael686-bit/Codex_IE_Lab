```text
人输入命令
  ↓
解析目标关节角
  ↓
初始化 Galbot SDK
  ↓
读取当前关节状态
  ↓
安全检查 / dry-run
  ↓
获取机械臂控制器
  ↓
发送七维绝对关节目标
  ↓
控制器生成并执行运动
  ↓
编码器反馈当前位置
  ↓
判断成功、超时或故障
  ↓
释放 SDK 资源
```

### 1. 人输入目标

例如：

```bash
test_move_wrist.py arms \
  --left '[q1,q2,q3,q4,q5,q6,q7]' \
  --speed 0.03 \
  --timeout 10
```

这里传入的是左臂七个关节的绝对目标角，单位都是弧度。

它不是：

```text
joint7 增加 0.05 rad
```

而是：

```text
让左臂全部七个关节到达这一组绝对角度
```

我们刚才的目标是：

```text
当前：
[1.009359, -0.683964, -1.114868, -2.333988, -1.322591, 0.034191, 0.959014]

目标：
[1.009371, -0.683988, -1.114868, -2.333964, -1.322579, 0.034167, 1.009014]
```

```text
q7：0.959014 → 1.009014 rad
```

### 2. 命令行解析

脚本通过 `argparse` 解析：

```python
args = build_parser().parse_args()
```

得到大致如下的数据：

```python
args.command = "arms"
args.left = [七个关节角]
args.speed = 0.03
args.timeout = 10
args.dry_run = True 或 False
```

`parse_arm_joints()` 负责检查：

- 输入是不是列表；
- 是否恰好包含七个数；
- 每个值能否转换成浮点数。

但它没有检查：

- 目标与当前值相差多大；
- 机械臂是否会碰撞；
- 目标是不是语义上的安全姿态。

### 3. 获取控制锁

如果不是 `state` 或 `--dry-run`，脚本先获取：

```text
/home/galbot/ie_lab/control.lock
```

对应代码：

```python
fcntl.flock(
    lock_file.fileno(),
    fcntl.LOCK_EX | fcntl.LOCK_NB,
)
```

作用是防止两个遵守同一锁机制的程序同时控制机器人。

但它不能阻止：

- 不使用这个锁的其他脚本；
- 生产程序或容器；
- 其他控制接口；
- 人工试教操作。

所以“成功获得锁”不等于整个机器人只有这一个控制源。

### 4. 初始化 SDK

程序创建机器人对象：

```python
robot = GalbotRobot()
robot.init()
```

初始化主要建立与 S1 状态和控制系统的通信，使程序能够：

- 读取关节状态；
- 查询控制器；
- 获取控制器；
- 发送运动目标；
- 接收执行状态。

`SDK 初始化成功` 只表示通信接口初始化成功，不表示：

- 机械臂一定允许运动；
- 电机已经处于正常使能状态；
- EtherCAT 没有故障；
- 当前姿态安全；
- 目标没有碰撞。

8 月 20 日就是 SDK 能初始化和读取状态，但运动仍返回 `FAULT`。

### 5. 读取当前关节角

这一步让操作者比较当前状态和目标状态。


获取控制器的意义是请求左臂 PVT 控制权限。


只说明获取控制器请求成功，仍不代表后面的运动一定成功。

### 8. 发送关节目标

核心调用是：

```python
status = robot.set_joint_positions(
    targets,
    groups,
    [],
    True,
    args.speed,
    args.timeout,
)
```

参数含义大致是：

```python
targets       # 七维绝对关节目标
groups        # 例如 ["left_arm"]
[]            # 不单独指定关节名，按整个关节组解释
True          # 阻塞等待执行结束
args.speed    # 最大关节速度
args.timeout  # 最长等待时间
```

对于当前例子，相当于：

```text
控制组：左机械臂
目标：七个绝对关节角
速度上限：0.03 rad/s
最长等待：10 s
阻塞：是
```

这里的“阻塞”表示 Python 程序停在这次调用处，直到：

- 到达目标；
- 执行失败；
- 发生故障；
- 或等待超时。

### 9. 底层执行与反馈

收到目标后，底层控制系统根据当前角度和目标角度生成运动过程，并持续读取编码器反馈。

对于 joint7，可以抽象为：

```text
当前：0.959014
目标：1.009014
误差：0.050000 rad
```

运动过程中误差逐渐减小：

```text
0.050 → 0.040 → 0.030 → 0.020 → 0.010 → 接近 0
```

当误差低于控制器阈值，并且轨迹完成时，SDK可能返回：

```text
ControlStatus.SUCCESS
```

如果设备状态异常，可能返回：

```text
ControlStatus.FAULT
```

如果规定时间内没有到达，则可能返回：

```text
timeout
```

### 10. 执行后再次读取状态

程序随后执行：

```python
after = robot.get_joint_positions(
    groups,
    [],
)
```

并打印：

```text
执行后： [...]
```

判断动作是否真实发生，需要同时比较：

```text
执行前位置
目标位置
执行后位置
SDK 返回状态
```

不能只看 `SUCCESS`。

例如真正成功应该接近：

```text
执行前 q7：0.959014
目标 q7：  1.009014
执行后 q7：约 1.009014
SDK：       SUCCESS
```

如果是：

```text
执行前 q7：0.959014
目标 q7：  1.009014
执行后 q7：0.959014
SDK：       FAULT
```

就说明没有发生可测得的运动。

### 11. 释放资源

无论成功还是失败，脚本最后都会执行：

```python
robot.request_shutdown()
robot.wait_for_shutdown()
robot.destroy()
```

然后释放控制锁。

这表示关闭当前 Python 程序建立的 SDK 通信资源，不表示：

- 关闭机器人；
-关闭电机；
- 恢复原姿态；
- 自动撤销已经完成的运动。

### 最重要的三个概念

第一，脚本发送的是绝对目标：

```text
q7 = 1.009014
```

不是相对命令：

```text
q7 += 0.05
```

相对变化是我们在程序外根据新鲜状态计算出来的。

第二，获取控制器和发送运动是两步：

```text
acquire_controller()
        ↓
set_joint_positions()
```

获取成功不等于运动成功。

第三，SDK成功不等于任务安全：

```text
数值目标到达
≠
没有碰撞
≠
目标姿态合理
≠
抓取任务成功
```

所以完整的安全控制闭环应该是：

```text
读取当前状态
→ 检查模式和报警
→ 根据当前状态生成小目标
→ 检查限位与碰撞
→ dry-run
→ 人工确认
→ 获取控制器
→ 低速执行
→ 读取执行后状态
→ 决定是否继续
```

我们现在已经完成到 `dry-run`，还没有进入获取控制器和真实执行阶段。

  /home/galbot/ie_lab/projects/chassis_env/workspace/test_move_wrist.py \

````markdown
### 闭合左夹爪

```bash
/home/galbot/ie_lab/bin/s1-python \
  /home/galbot/ie_lab/projects/chassis_env/workspace/test_move_wrist.py \
  gripper left close \
  --close-width 0.02 \

### 同时打开双夹爪

```bash
/home/galbot/ie_lab/bin/s1-python \
  /home/galbot/ie_lab/projects/chassis_env/workspace/test_move_wrist.py \
  gripper both open \
  --open-width 0.07 \
  --velocity 0.02 \
  --effort 10
```

夹爪参数：

| 参数 | 说明 |
|---|---|
| `left` | 左夹爪 |
| `right` | 右夹爪 |
| `both` | 左右夹爪 |
| `open` | 打开 |
| `close` | 闭合 |
| `--open-width` | 打开宽度，单位为米 |
| `--close-width` | 闭合宽度，单位为米 |
| `--velocity` | 夹爪速度，单位为 `m/s` |
| `--effort` | 夹爪 effort 参数，物理语义尚未标定 |
| `--timeout` | 双夹爪动作等待时间 |
| `--dry-run` | 只显示参数，不发送夹爪命令 |

## 安全注意事项

真实运动前必须确认：

1. 机器人处于正常 `WORKING_MODE`；
2. 屏幕没有 `ABNORMAL` 或其他报警；
3. 绿色试教按钮已经松开；
4. 机械臂和夹爪周围空间空旷；
5. 没有其他程序同时控制机器人；
6. 实体急停触手可及；
7. 机械臂目标来自最新状态，不使用旧快照；
8. 先执行 `state`，再执行 `--dry-run`；
9. 每次真实动作都需要单独确认；
10. 出现 `FAULT`、超时、异响或异常运动时立即停止，不自动重试。

`ControlStatus.SUCCESS` 只表示 SDK 命令执行成功，不代表目标姿态一定安全，也不代表抓取任务成功。

夹爪返回的 `effort=1000` 不能直接解释为 `1000 N`。
````
