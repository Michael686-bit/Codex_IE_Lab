
理由：

- Ubuntu 22.04 原生匹配 ROS 2 Humble。
- ROS 1 Noetic 原生匹配 Ubuntu 20.04，不建议硬装到 Ubuntu 22.04。
- Noetic 已于 2025 年 5 月 31 日停止官方维护，但现有项目仍可继续运行；Docker 更容易冻结依赖和复现环境。[ROS 官方说明](https://www.ros.org/blog/noetic-eol/)
- S1 的 URDF 本身不依赖 ROS 1 或 ROS 2，用 RViz2 显示完全没问题。

注意几个边界：

- 不要在同一个终端同时 `source /opt/ros/noetic/setup.bash` 和 `/opt/ros/humble/setup.bash`。
- 主机 `.bashrc` 只自动加载 Humble；Noetic 环境留在容器里。
- ROS 1 容器连接实体机器人时，通常需要：
  - `--network host`
  - 串口/USB 的 `--device`
  - 相机的 `/dev/video*`
  - ROS 1 GUI 的 X11 映射
- 两套系统需要互传 topic/service 时，才需要 `ros1_bridge`。它在 Ubuntu 22.04 上不是简单的开箱即用组件，官方说明 Jammy 环境通常需要源码构建，因此最好单独制作桥接容器。[ros1_bridge 官方说明](https://docs.ros.org/en/humble/p/ros1_bridge/index.html)
- Noetic 已停止安全更新，不要把容器的 ROS Master 或调试端口直接暴露到公网。

所以现在可以放心安装：

```bash
source <(wget -qO- http://fishros.com/install)
```

选择 **ROS 2 Humble 桌面版**。等 Humble/RViz2 配好后，再单独建立 Noetic Docker 环境。官方 ROS Docker 镜像由 OSRF 维护。[ROS Docker 镜像](https://hub.docker.com/_/ros)

- MJCF 已经有双臂、头部、升降柱、底盘执行器、质量/惯量和大量碰撞几何体，因此有实际使用价值。

- USD 已包含刚体、关节驱动、碰撞和完整 PBR 纹理，适合 Isaac Sim；相机/RGB-D 仍需根据真实 S1 标定进行配置。

我的建议是：

1. 继续用 RViz2 学清楚 joint1～joint7 的方向、影响范围和限位。

4. 实机先做只读状态和传感器采集；涉及运动时，先在 RViz/MuJoCo 检查目标、方向、限位和碰撞，再做低速、单关节、小幅度的实机验证。

- 查看当前关节角
- 获取相机数据

不建议直接跳到实机的内容：

- 未验证的全身零位或 home
- 多关节同时运动
- 升降柱恢复
- 双臂抓取
- 夹爪受力操作
- 底盘导航

仿真不能保证安全，但可以提前发现轴向、正负号、弧度/角度、关节顺序、限位和明显碰撞等低级错误。对 S1 这种双臂移动机器人，这一层非常值得保留。
