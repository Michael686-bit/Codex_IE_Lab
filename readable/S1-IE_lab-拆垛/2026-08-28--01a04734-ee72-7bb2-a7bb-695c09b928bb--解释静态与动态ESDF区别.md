## 1. 用户

这个静态的ESDF 和 后面判断不可达的 动态的 ESDF 有什么区别？ 两者都是怎么来的？

## 2. 助手（进展）

我先沿着项目里的术语和实现把两类 ESDF 对齐：重点确认“静态 ESDF”具体对应哪份地图/缓存，以及“动态 ESDF”在不可达判断时包含了哪些实时障碍。这样回答不会把一般概念和本项目实现混在一起。

## 3. 助手（进展）

目前能先确认一个关键点：项目里的 `check_path_reachability()` 明确是“静态地图预检”；后面日志中的动态部分更像导航运行时用实时点云构建/更新的局部障碍距离场。下面我再核对地图资产和那条 `evaluate at dyn map` 的原始记录，避免把“动态 ESDF”说成另一张永久地图。

## 4. 助手

先纠正一个容易混淆的地方：我们后面得到的“0.8 m、1.0 m、1.2 m 不可达”，仍然来自 `check_path_reachability()` 的静态地图检查，不是动态 ESDF。

当时 PNS 日志明确写了：

```text
evaluate at dyn map: 0
```

也就是“没有在动态地图上评估”。因此当前已确认的不可达边界，主要是静态 3D ESDF 导致的。

## 两类地图的区别

| | 静态 ESDF | 动态地图/动态 ESDF |
|---|---|---|
| 障碍来源 | 建图时采集的墙、柱子、固定设备、历史点云 | 当前 LiDAR 实时看到的人、箱子、临时设备等 |
| 生成时间 | 建图后离线生成并保存 | 机器人运行时持续生成、更新、衰减 |
| 保存形式 | 当前地图里有 `global_cloud_cleaned.esdf` | 通常存在内存中的局部/滚动地图，不一定长期保存 |
| 坐标范围 | 全局 `map` 坐标系，覆盖整个已建地图 | 机器人周围一定范围，随机器人移动 |
| 是否容易残留旧物体 | 会，建图时出现的东西可能永久留在地图里 | 通常有时间衰减，物体消失后应逐渐清除 |
| 主要用途 | 全局路径规划、目标姿态合法性、静态可达性预检 | 导航执行中的临时障碍检测、局部避障、急停 |
| 本次不可达是否由它造成 | 是 | 日志显示不是 |

## 静态 ESDF 怎么来的

当前真机地图目录里已经确认存在：

```text
global_cloud.pcd
global_cloud_cleaned.pcd
global_cloud_cleaned.esdf
map.pgm
map.yaml
```

大致生成过程是：

```text
建图时的多帧 LiDAR
    ↓ 根据建图位姿拼接
全局三维点云 global_cloud.pcd
    ↓ 去噪、裁剪、清理
global_cloud_cleaned.pcd
    ↓ 体素化，标记占据/自由空间
三维占据地图
    ↓ 欧氏距离变换
global_cloud_cleaned.esdf
```

ESDF 给空间中每个位置记录“到最近障碍物的距离”。PNS 把机器人表示成一组碰撞球，假设某个球：

- 球心位置为 \(c\)
- 球半径为 \(r\)
- ESDF 查询距离为 \(d(c)\)

一般可理解为：

```text
d(c) > r + 安全余量  → 有净空
d(c) ≤ r + 安全余量  → 碰撞或过近
```

我们那次已经查到：

```text
碰撞球：omni_chassis_base_link sphere 9
球半径：0.170 m
静态 ESDF 距离：约 0.145–0.163 m
```

因为距离小于球半径，所以目标姿态被判定为无效。

而且碰撞球中心高度大约是 `z=0.373 m`。这也解释了为什么二维 `map.pgm` 看起来是自由区，三维 ESDF 仍可能碰撞：二维地图没有完整表达这个高度上的三维障碍、旧点或噪声。

## 动态 ESDF 怎么来的

动态部分通常来自机器人当前的 LiDAR：

```text
前/后/底盘 LiDAR 实时点云
    ↓ 通过 TF 变换到统一坐标系
    ↓ 去除机器人本体、自带箱体区域、地面和异常点
    ↓ 多帧短时融合
局部动态占据体素
    ↓ 增量距离变换
局部动态距离场
```

它主要负责发现：

- 突然走来的人；
- 临时放下的箱子；
- 建图后新增的设备；
- 机器人抓着的箱子被传感器误认为外部障碍。

动态地图一般只覆盖机器人附近，并随时间更新。障碍离开后，相应体素应经过清除或衰减恢复为空闲。

不过需要严谨说明：目前我们只从 PNS 日志确认它区分 `dyn map` 与静态 ESDF；厂家动态地图究竟是不是一个完整独立的 ESDF、体素分辨率是多少、采用什么衰减算法，尚未从厂家源码或配置中完全核实，所以这些内部细节仍是“待验证”。

## “不可达”可能有两种来源

```text
目标/路径候选
      │
      ├─ 查询静态 ESDF
      │    墙、固定设备、历史点云、地图噪声
      │
      └─ 查询动态地图
           人、临时箱子、实时点云障碍
                ↓
       与机器人碰撞球比较
                ↓
          可达 / 不可达
```

对我们现在这组结果：

- `0.1–0.6 m`：静态预检全部可达；
- `0.8–1.2 m`：静态预检全部不可达；
- 日志 `evaluate at dyn map: 0`；
- 所以目前应优先调查静态 ESDF、碰撞球模型，以及地图—定位—ESDF的对齐，而不是实时动态障碍。
