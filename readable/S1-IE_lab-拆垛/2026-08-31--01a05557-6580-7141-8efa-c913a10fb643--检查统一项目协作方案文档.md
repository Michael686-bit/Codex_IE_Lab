### 统一证据标签

建议固定为六类：

- `DOCUMENTED_OFFICIAL`：官方资料记载，当前运行时尚未验证
- `OBSERVATION`：一次观察，不保证可重复
- `HYPOTHESIS / UNRESOLVED`：假设或未解决问题
- `SUPERSEDED`：已被后续证据取代

## 风险判断

可以修改，但风险取决于执行方式：

- 直接创建文件，然后运行 `git add .`：高风险。
- 先盘点、窄范围忽略、显式选择提交文件：低到中风险。
- 不涉及 SSH 或机器人，没有物理运动风险。

### 1. `.gitignore`：中风险

`.gitignore` 不会删除文件，只会让未跟踪文件不再出现在普通 Git 状态中。

风险在于旧方案的 [.gitignore](/home/lsy03/Lsy03_document/galbot_s1_SDK_learning/.gitignore:1) 规则较宽，会忽略所有 `*.log`、`*.pcd`、`build/`、`install/`、`log/`。如果原样复制到当前仓库，某些重要实验数据可能被“隐藏”，让人误以为它们已经备份。

当前仓库里既有生成物，也有重要证据，所以不能简单按扩展名全部忽略。

### 2. 首次基线：当前最高风险

目前约有 211 个文件、约 430 MB 内容可能成为提交候选，其中包括：

- 145 MB 的 ROS 构建日志
- 174 MB 的 `global_cloud_cleaned.pcd`
- 83 MB 的 `global_cloud_cleaned.esdf`
- 约 26 MB 的 ESDF `.pb/.npz` 捕获数据
- `build/`、`install/`、`log/`、`__pycache__/`
- `install/` 中指向本机绝对路径的符号链接

地图、点云、位姿和 ESDF 数据还可能包含实验室空间结构与实机状态信息，不适合默认进入将来可能公开的普通 Git 仓库。

一旦这些文件进入首次提交，后来再加 `.gitignore` 也不会把它们从历史中移除。

### 3. `CURRENT_STATE`：文件风险低，语义风险中等

最大的风险不是创建文件，而是写错“当前事实”。

旧工作区的 `CURRENT_STATE` 停在 8 月 15 日，仍写着 Stage 0 和“下一步进行完整机械臂运动”。它早于 torso 安全事故以及 8 月 27—28 日导航/ESDF 工作，绝不能直接复制。

新的状态页应明确区分：

- 状态截止日期
- 历史上验证过
- 当前仍然成立
- 当前未核验
- 8 月 28 日实际停点
- 下一步是否涉及新的机器人授权

否则未来 Agent 可能把过期姿态、网络可达性或任务方向当成当前事实。

### 4. 文档索引：风险较低

主要风险是产生两个入口：

```text
README → knowledge_base
```

和

```text
AGENTS → INDEX → CURRENT_STATE
```

如果不明确权威顺序，不同任务会读取不同上下文。索引也不能复制旧工作区的目录表，因为当前仓库没有完全相同的 IMC、perception、dual_arm 等结构。

### 5. 当前 `.git` 目录还有特殊风险

只读检查发现当前 `.git` 已约 288 MB，包含 Codex 管理的检查点引用，以及约 116 MiB 临时垃圾对象。

这意味着：

- 不要重新执行 `git init`
- 不要删除 `.git/objects`
- 不要在建立基线时顺手运行强制 `gc/prune`
- 不要用 reset/re-init 试图“清空重来”

这些 Git 对象不妨碍建立正常基线，但清理应作为单独任务，在确认 Codex 检查点不再需要后处理。

## 最安全的实施方式

1. 先决定地图、点云和 ESDF 捕获数据是否允许进入版本库；未决定前不纳入首次提交。
2. `.gitignore` 先只排除明确生成物：

   - `__pycache__/`、`*.pyc`
   - 当前 ROS 工作区的 `build/`、`install/`、`log/`
   - `.env`、密钥文件
   - `.agents/`、`.codex/` 本地状态

3. 暂时不要全局忽略所有 `*.log`、`*.pcd`、`*.pb` 或 `*.npz`。
4. 新建基于当前证据编写的 `CURRENT_STATE` 和索引，不复制旧文件正文。
5. 使用显式文件清单暂存，绝不使用 `git add .`。
6. 首次基线优先只包含：

   - `.gitignore`
   - `AGENTS.md`
   - `README.md`
   - `docs/`
   - 实验 README、源码和小型配置

7. 大型实机数据单独决定：私有存储、Git LFS，或只提交带来源和 SHA-256 的 manifest。
8. 首次提交应命名为类似：

   `建立 2026-08-31 基线，保存截至 2026-08-28 的现状`

   它只能证明 8 月 31 日文件的状态，不能伪造 8 月 20—28 日的逐日 Git 历史。

补充的好消息是：当前没有配置 Git remote，所以首次提交不会自动上传；也没有发现高置信度密钥、嵌套仓库或源码目录符号链接。

因此我的建议是：可以进行这四项修改，但应拆成“窄范围忽略规则 → 状态与索引 → 预览候选文件 → 小型文本/源码基线 → 大数据另行决策”，不要一次性全量提交。
