## 4. 助手

可以拿到关键数据，但要修正一个理解：`galbot_fusion_main` 和 NVIDIA nvblox 不是两个独立进程，nvblox 是嵌在 `galbot_fusion_main` 内部的库。因此目前没有已验证的“过滤前 topic”和“过滤后 topic”两个天然端口。

可观测位置如下：

| 位置 | 可获取数据 | 当前状态 | 能否直接判断过滤 |
|---|---|---|---|
| fusion 输入前 | 三路原始 LiDAR 点云 | SDK/DDS 可读 | 能看到箱体原始回波 |
| `add_bounding_box` 过滤后、进入 nvblox 前 | 内部 CUDA 点数组 | 暂未发现公开 channel | 这是最直接证据，但目前拿不到 |
| nvblox TSDF 输出 | `tsdf_pointcloud_serialized` 等调试出口 | 已确认存在，尚未完成实帧捕获验证 | 可以观察过滤后的融合表面 |
| nvblox ESDF 输出 | `esdf_pointcloud_serialized` / `EsdfGrid` | 已经成功捕获和解析 | 能看到 PNS/Motion 实际消费的最终距离场 |

真实内部链路更接近：

```text
三路 LiDAR 原始点
        ↓
时间戳、TF变换
        ↓
内置 1×1×3 m robot bbox
URDF convex-hull 自体过滤
SDK add_bounding_box 动态过滤框
离群点/时序体素过滤
        ↓
nvblox projective integrator
        ↓
TSDF / Occupancy / Color / Freespace
        ↓
局部 ESDF
        ↓
esdf_pointcloud_serialized
        ↓
PNS + Motion
```

其中已经通过当前生产二进制的符号和反汇编确认：

```text
add_bounding_box
 → galbot_fusion_add_box
 → SetPointsFilterBoxs
 → filterPointsWithBoxes CUDA kernel
 → TSDF / Occupancy / Color integration
 → ESDF
```

也就是说，`add_bounding_box()` 确实位于点云进入 nvblox 集成之前。详细证据记录在 [s1_add_bounding_box_runtime_analysis_20260831.md](../../assets/7b81546798fced5b--s1_add_bounding_box_runtime_analysis_20260831.md:19)。

但是有一个非常重要的限制：

> `add_bounding_box()` 只过滤登记之后的新输入点，不会自动删除登记之前已经进入 TSDF/ESDF 的旧体素。

所以即使过滤框已经生效，ESDF 中仍可能暂时或长期保留之前看到的箱体。当前 4317 箱子的日志正符合这个现象：过滤框登记成功，但旧箱体体素仍可能留在 nvblox 地图中。[现有探测记录](../../assets/3d8a998811ef0676--pns_payload_probe_20260831.md:100)

最现实的验证方案是同步抓取三层数据：

```text
A. 三路原始 LiDAR
   看过滤框区域内是否确实存在箱体回波

B. nvblox TSDF debug
   看这些回波有没有继续形成/强化融合表面

C. 最终 EsdfGrid
   看 PNS 查询的距离场是否逐帧变化
```

比较时必须同时保存：

- LiDAR、TSDF、ESDF 的时间戳；
- `map → base_link → LiDAR` TF；
- 当前动态过滤框的尺寸和7D位姿；
- PNS查询时间及碰撞球位置。

只比较“原始 LiDAR”和“ESDF”还不能完全证明 `add_bounding_box` 是否生效，因为中间还有自体过滤、时序过滤、TSDF历史累积和ESDF转换。

结论是：

- 三路过滤前原始点云：可以拿；
- nvblox最终ESDF：已经能拿，并已成功捕获；
- nvblox TSDF调试流：接口已发现，值得下一步捕获验证；
- `add_bounding_box` 后、nvblox集成前的精确中间点数组：当前没有公开接口，除非厂家提供专门debug出口或修改 fusion；
- 最可靠、又不修改厂家进程的方案，是做“原始LiDAR + TSDF + ESDF + TF”近同步被动采集，再在RViz中叠加过滤框对比。

下一步不应该先清 ESDF。`galbot_fusion_clear_esdf` 的范围和恢复语义尚未核实，可能改变导航碰撞地图。应先完成上述被动实时对照。
