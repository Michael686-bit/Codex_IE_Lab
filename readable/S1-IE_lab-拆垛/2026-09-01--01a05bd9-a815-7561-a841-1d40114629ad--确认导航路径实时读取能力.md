## 5. 助手

结论：按你现在这条命令和现有 CLI，RViz 不能实时显示规划器生成的导航路径。

原因是：

- `check_path_reachability()` 只返回“可达/不可达”的布尔值，不返回路径点。
- `navigate_to_goal_v2()` 只返回任务状态，不返回全局路径或局部轨迹。
- 当前 CLI 使用阻塞调用，且没有发布 ROS 2 的 `nav_msgs/Path`。
- 官方 SDK 1.9.0，以及你提供的 1.9.1 API 文档中，都没有发现 `get_planned_path()`、路径回调或实时路径订阅接口。
- `navigate_along_trajectory()` 是把轨迹输入给机器人，不是读取导航器规划出的轨迹。
- `get_navigation_target_status()` 也只有任务 ID、状态和消息，不包含路径。

因此，官方 SDK 提供“路径规划和导航能力”，但目前没有公开提供“实时读取规划路径”的 Python API。

可以实现的替代方案：

1. 实时实际轨迹
   导航时持续读取 `get_current_pose()`，发布为 `nav_msgs/Path`。RViz 可以实时看到机器人已经走过的轨迹，但这不是规划路径。

2. 显示输入参考轨迹
   如果改用 `navigate_along_trajectory()`，可同时把输入的 waypoints 发布到 RViz。不过内部规划器可能会平滑或调整它，所以它仍不等于机器人实际采用的规划路径。

3. 读取厂家内部规划话题
   理论上可以被动检查 S1 的 DDS 话题，看 `service_navigation_plan` 是否发布内部全局/局部路径，再桥接为 `nav_msgs/Path`。目前项目已确认 ESDF、TF、雷达等内部通道，但尚未确认存在可读取的规划路径话题，因此这部分是“待验证”，不能承诺一定能拿到。

现有实现证据见 [s1_navigation_cli.py](/home/lsy03/文档/ChatGPT/S1/experiments/20260827_s1_navigation/s1_navigation_cli.py:1040) 和 [SDK 导航调查报告](../../assets/f6378b5bcdb04289--s1_navigation_sdk_report_20260827.md:100)。
