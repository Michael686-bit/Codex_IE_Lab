   - tag：`4317`
   - 父坐标系：`left_arm_end_effector_mount_link`
   - 过滤框：`0.6 × 0.5 × 0.375`
   - 碰撞框：`0.4 × 0.3 × 0.175`
   - 位姿和 ignored links 也相同

用户输入口令期间，PNS attachment 接口有时间完成初始化。新版删除交互确认时，也把这段“隐含等待”删掉了。

6. 两次都出现相同的“1.9.1 可升级”提示，没有证据表明中间升级过 SDK。该提示本身也不表示当前已安装 1.9.1。

## 可以排除的方向

- 不是箱体尺寸、位姿、四元数或父 link 错误，否则更应返回 `INVALID_INPUT`。
- 不是 `add_bounding_box()` 失效；它成功后被回滚了。
- 不是 `--omni-plan false` 导致；独立的 `payload-register-4317` 不使用该参数。
- 不是前一次“静态路径不可达”直接导致；那次没有提交导航或切换控制器。
- 不像重复 tag，因为注册前后都查到 `bounding_boxes=[]`，且重复对象也不符合 `WAIT_INITIALIZED` 的官方语义。

当前逻辑没有识别或重试 `WAIT_INITIALIZED`，任何 attach 失败都会立即回滚。现有伪 SDK 测试也只模拟了成功和 `INVALID_INPUT`，没有模拟“前几次返回 `WAIT_INITIALIZED`、稍后成功”，因此测试通过也发现不了这个问题：[测试替身](/home/lsy03/文档/ChatGPT/S1/experiments/20260827_s1_navigation/test_s1_navigation_cli.py:165)。

## 核心修改

1. 为 `attach_box_to_link()` 增加有界重试：

```text
首次调用
├─ SUCCESS：登记成功
├─ WAIT_INITIALIZED：等待 0.25 秒后重试
└─ 其他错误：立即停止并回滚
```

建议参数：

```text
重试间隔：0.25 秒
最长等待：5 秒
最多约 21 次调用（含首次）
```

只重试 `WAIT_INITIALIZED`，不重试：

- `INVALID_INPUT`
- `COMM_ERR`
- 其他未知错误

这样不会掩盖真正的配置或通信故障。

2. 保持事务式注册：

```text
add_bounding_box
→ get_bounding_box 精确校验
→ attach_box_to_link 有界重试
→ 成功后保留登记
```

如果最终失败：

```text
remove_bounding_box
→ 再次 get_bounding_box
→ 确认 tag 4317 已消失
→ fail closed
```

不会发送底盘、机械臂、夹爪或升降运动。

3. 完善失败输出。

现在异常被顶层捕获后，只剩一条错误信息，前面的详细结果丢失。新版应保留：

```json
{
  "attach_box_to_link_attempts": [
    {
      "index": 1,
      "elapsed_s": 0.0,
      "return": [false, "WAIT_INITIALIZED"]
    },
    {
      "index": 2,
      "elapsed_s": 0.25,
      "return": [true, "SUCCESS"]
    }
  ],
  "rollback_attempted": false
}
```

若失败，还应输出：

- `add_bounding_box_return`
- `bounding_boxes_after_add`
- 每次 attach 结果
- `rollback_remove_bounding_box_return`
- `bounding_boxes_after_rollback`
- `filter_rollback_verified`

这样下一次无需先猜调用停在哪一步。

## 顺便修正一个状态顺序问题

当前自动注册发生在 `max-distance` 检查之前。此前已经出现过：

```text
add+attach 成功
→ 发现目标距离超过 max-distance
→ 导航拒绝
→ payload 登记仍然保留
```

新版应把不依赖 payload 的检查提前：

```text
参数合法性
→ 定位和当前位姿
→ max-distance 检查
→ 确认导航空闲
→ payload add+attach
→ 携带物状态下的三次可达性检查
→ 控制器切换和导航提交
```

静态可达性检查仍必须放在注册之后，否则规划器看不到携带箱体的碰撞外形。

如果 payload 已成功登记，但后续路径不可达，仍保留登记，不自动 detach；因为机器人还在抱箱，携带物模型继续存在才是更安全的状态。
