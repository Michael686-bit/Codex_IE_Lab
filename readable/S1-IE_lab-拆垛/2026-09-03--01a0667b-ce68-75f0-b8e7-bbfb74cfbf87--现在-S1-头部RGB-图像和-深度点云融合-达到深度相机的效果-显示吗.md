```text
左右头部 RGB → FOUNDATION_STEREO 稠密深度

二者融合     → 头部 RGB-D / 彩色点云
腕部 RGB-D   → 最终抓取精定位
```

### 为什么 LiDAR 投影不等于深度相机

此前实机被动观测到头部 LiDAR 约为：

- 10 Hz；
- 19,968 点/帧；
- 约 519 KB/帧；
- 存在 `head_lidar_base_link → 头部关节 → base_link` 动态 TF。

如果暂按 LiDAR 水平 360°、相机水平视场90°估算，进入相机视野的直接测量点约5,000个/帧：

- 对 `640×480`，只覆盖约1.6%像素；
- 对 `1280×720`，只覆盖约0.54%像素。

剩余像素只能通过双目、单目网络或插值补齐。补齐后的图可以很“好看”，但补出来的区域不是直接测量值，不能自动视为安全碰撞或精确抓取真值。

### 双目精度的理论参考

双目关系为：

\[
Z=\frac{fB}{d},\qquad
\sigma_Z\approx\frac{Z^2}{fB}\sigma_d
\]

误差会随距离平方增长。[OpenCV 双目原理](https://docs.opencv.org/3.4.6/dd/d53/tutorial_py_depthmap.html)

假设焦距 `f=700 px`、基线 `B=100 mm`、视差误差 `0.5 px`：

| 距离 | 理论深度误差 |
| ---: | ---: |
| 0.5 m | 约1.8 mm |
| 1.0 m | 约7.1 mm |
| 2.0 m | 约28.6 mm |
| 3.0 m | 约64 mm |
| 5.0 m | 约179 mm |

这只是理论随机误差，不包含标定、遮挡、无纹理纸箱、反光膜、曝光不同步和模型误差。S1 的真实 `f` 和基线尚未公开；右目投影矩阵读取后，可以通过：

```text
baseline = abs(P_right[3] / P_right[0])
```

算出本机基线并重算误差曲线。

作为深度相机量级参考，Orbbec Gemini 2 官方指标为 `1280×800@30 fps`、`0.15–10 m`、2 m处精度不超过2%，但测试条件有限制。[Gemini 2 官方规格](https://www.orbbec.com/products/structured-light-camera/gemini-2/) S1 官方目前没有公开同类精度、量程和帧率，因此不能直接宣称已经达到该指标。

### 对当前拆垛项目的建议

推荐职责划分：

1. 头部双目负责稠密场景深度。
2. 头部 LiDAR负责尺度校正、远距离结构和失败兜底。
3. LingBot/单目深度只负责补洞，不能独立决定绝对尺度。
4. 头部输出粗箱体位姿和观察位。
5. 到达观察位后，由腕部 RGB-D重新获取箱体6D位姿，再抓取。

建议验收线：

- 双目标定重投影 RMS：`≤0.5–1 px`；
- LiDAR-RGB 边缘投影：中位数 `≤2 px`；
- 运动时传感器时间差：目标 `≤5 ms`；
- 0.8 m 深度中位误差：`≤10 mm`；
- 1.5 m：`≤20 mm`；
- 2 m：`≤2%`；
- 箱体 ROI 有效深度率：`≥90%`；
- 粗箱体位姿：平移 RMSE `≤20 mm`、姿态 `≤2°`；
- 最终抓取前腕部复核：平移误差目标 `≤10–15 mm`。

当前导航融合采用5 cm体素，适合障碍物和规划，不足以代表精细抓取深度。

## 腕部与头部精度对比

| 维度 | 腕部 RGB-D | 头部双目/双目+LiDAR |
| --- | --- | --- |
| 典型距离 | 能靠近目标，通常0.4–0.8 m | 通常1–3 m |
| 深度精度 | 近距离通常更高 | 双目误差随距离平方增加 |
| 箱体像素数量 | 多，边缘和局部结构清楚 | 距离远，箱体像素明显减少 |
| 深度密度 | 原生稠密深度 | 双目可稠密；LiDAR投影很稀疏 |
| RGB-depth对齐 | 同一模组，SDK甚至使用同一 optical frame | 左右目需双目标定，LiDAR还需外参 |
| 坐标误差来源 | 手眼标定、腕部/TCP、关节时间戳 | 双目标定、颈部/升降TF、相机-LiDAR外参 |
| 遮挡 | 可能被夹爪遮挡，但可调整观察姿态 | 可能被双臂、箱体上层或货架遮挡 |
| 最适合 | 最终6D位姿和抓取 | 全局搜索、粗定位、导航观察位 |

SDK明确给腕部 RGB 和 depth 使用同一个 `*_arm_camera_color_optical_frame`，这对 RGB-D 对齐很有利。[官方 Python 示例与坐标系](https://developer.galbot.com/docs/SDK/1.9.1/s1/en/examples_python/)

## 为什么腕部通常更准

双目深度误差近似满足：

\[
\sigma_Z\propto\frac{Z^2}{fB}
\]

即使头部双目基线比腕部大，距离平方往往仍占主导。

举例，假设：

- 腕部观察距离0.6 m；
- 头部观察距离1.5 m；
- 头部基线是腕部的2倍；
- 两者像素焦距接近。

那么头部理论深度随机误差仍约是腕部的3.1倍；如果头部距离2 m，则约5.6倍。

目标在图像里的大小也有明显差异。假设焦距 `700 px`、箱体宽0.4 m：

| 距离 | 箱体图像宽度 |
| ---: | ---: |
| 0.6 m | 约467 px |
| 0.8 m | 约350 px |
| 1.5 m | 约187 px |
| 2.0 m | 约140 px |

腕部近看会给 SAM mask、箱体边缘、FoundationPose姿态轴更多像素，因此通常更适合抓取。

不过，如果让头部和腕部处在相同距离，且头部双目基线明显更大，头部纯深度精度不一定差。问题是实际机器人工作时，头部一般离目标更远。

## 当前腕部方案的一个重要注意点

目前生产链路是：

```text
右腕对齐 RGB-D
→ SAM3
→ LingBot-Depth
→ ROI
→ FoundationPose++
→ TCP补偿
→ 双臂目标
```

而最终目标还叠加了：

- 左 TCP：`[-35,-50,0] mm`
- 右 TCP：`[-35,+50,0] mm`
- 两侧目标 RPY 强制归零

所以已有成功抓取证明的是“整条腕部感知与人工标定链能够工作”，不能直接说明腕部相机本体已经达到10 mm精度。人工补偿可能正在消除相机、手眼标定、模型轴或夹爪几何的系统偏差。

## 我的建议

采用三级感知更稳妥：

1. 头部做全局发现
   找到货垛、箱体数量、候选目标、遮挡关系，并决定机器人观察位。

2. 头部双目+LiDAR做粗定位
   输出大约20–50 mm级目标即可，用于底盘和机械臂移动到观察区域，不直接生成最终抓取点。

3. 腕部 RGB-D做最终精定位
   在0.4–0.8 m左右重新采集，对箱体6D位姿和抓取边缘做最后确认。

建议初始门槛：

| 指标 | 头部粗定位 | 腕部最终定位 |
| --- | ---: | ---: |
| 平移误差中位数 | ≤30 mm | ≤10–15 mm |
| 平移误差P95 | ≤50 mm | ≤20 mm |
| 姿态误差 | ≤3° | ≤1–2° |
| 箱体ROI有效深度率 | ≥80% | ≥90% |
| RGB-depth时间差 | ≤20 ms | 运动场景目标≤5 ms |

另外可以考虑让左腕相机作为交叉验证：右腕得到位姿后，左腕从另一侧观察箱体；两者结果如果相差超过20–30 mm或2–3°，就拒绝进入抓取。

## 推荐的对比实验

不要直接比较最终抓取成功率，先分别测四个输出：

1. 腕部原始深度；
2. 腕部原始深度+LingBot；
3. 头部 `FOUNDATION_STEREO`；
4. 头部 stereo+LiDAR融合。

在同一个纸箱、同一标定板上，分别测试0.5、0.8、1.2、1.5、2 m，每个位置采20–50帧，统计：

- 深度 bias、MAE、RMSE和P95；
- 平面拟合残差；
- 有效深度率；
- 帧间抖动；
- RGB-depth时间差；
- 箱体6D位姿重复性。

官方说明相机配置和标定可从这些位置检查：

```text
/data/galbot/config/right_arm_camera.cfg
/data/galbot/config/left_arm_camera.cfg
/data/galbot/config/front_head_camera.cfg

/userdata/config/robot_config/eyehand_calib.toml
/userdata/config/robot_config/stereo_camera_intrinsic.toml
```

这些文件可以直接给出分辨率、FPS、手眼标定和头部双目参数线索。[官方相机排障说明](https://developer.galbot.com/docs/SDK/1.8.1/s1/en/troubleshooting/)

我的最终建议是：保留腕部作为抓取主传感器，增加头部作为提前感知和粗定位层。这样既能减少腕部为了“找箱子”而进行的大范围观察动作，又不会牺牲最后几厘米内的抓取精度。
