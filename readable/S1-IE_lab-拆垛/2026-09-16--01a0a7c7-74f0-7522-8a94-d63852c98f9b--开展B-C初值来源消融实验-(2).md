## 一、V5-2 + V5-3b 当前到底做了什么

当前程序的入口是：

- [v5_2_visibility.py](/home/lsy03/文档/ChatGPT/S1/experiments/20260907_bin_rim_pose/v5_2_visibility.py)
- [mesh_shell_fit.py](/home/lsy03/文档/ChatGPT/S1/experiments/20260907_bin_rim_pose/mesh_shell_fit.py)
- [default.json](../../assets/c39e6410976c3f74--default.json)

整体流程是：

```text
冻结 RGB-D Observation
        │
        ├── B：箱口候选
        ├── C：多平面侧壁候选
        └── M：mesh 粗初值
                │
        候选融合、去重、最多保留 12 个初值
                │
        V5-3b 可见壳体拟合
                │
        内外壁竞争、残差、覆盖率、触边门禁
                │
        accepted 或 rejected
```

输入包括：

- RGB
- LingBot 深度，单位为米
- 人工确认的 mask
- 相机内参 K
- `T_base_link_from_camera`
- 固定 4317 mesh 及表面角色

FDP 位姿不参与初始化。

### 1. B：箱口候选

B 主要利用 RGB 边缘和深度点：

1. 深度反投影到 base 坐标系。
2. 选取较高位置的边缘点。
3. 拟合箱口附近平面。
4. 在固定尺寸约束下拟合 400×300 mm 矩形。
5. 对多个 yaw 和平移初值运行矩形拟合。
6. 检查四条边的点数、覆盖率、残差。
7. 如果存在多个分数接近但位姿不同的矩形，保留竞争解释并拒绝。

这个分支提供的是箱口中心和方向线索。

### 2. C：多平面候选

C 使用深度点的局部几何：

1. 反投影 mask 内深度。
2. 估计局部法向。
3. 提取近似竖直的侧壁平面。
4. 组合相邻面、相对面和正交面。
5. 根据箱体固定尺寸检查面间距。
6. 根据有限高度范围检查箱体中心高度。
7. 保留主候选和竞争候选。

C 对侧壁比较清楚的视角有帮助，但容易受到筋条、内壁、外壁和邻箱平面的影响。

### 3. M：mesh 粗初值

M 不依赖 B 和 C，而是从观测点云估计：

1. 从 mask 内提取墙面点。
2. 体素化。
3. 用 XY 点的中位数估计中心。
4. 用 PCA 估计主方向和 yaw。
5. 在此基础上添加小扰动：
   - XY 方向约 ±2 cm；
   - yaw 约 ±3°；
   - 约 15 个候选。
6. 和 B/C 候选按中心 1 cm、yaw 1° 去重。
7. 最多保留 12 个初值。

这里要注意：当前 M 并没有使用你提供的外部粗位姿。它只相信当前观测点分布，所以遮挡时可能出现中心偏移和 180° 方向错误。

### 4. V5-3b 壳体拟合

对每个初值执行：

1. 将 mesh 点变换到该初始位姿。
2. 投影到 RGB 图像。
3. 根据视角余弦筛选可见表面。
4. 使用 2 像素 z-buffer 去掉被遮挡的模型点。
5. 只保留 `rim_flange`、`outer_shell`、`inner_shell` 角色。
6. 对观测点和模型点分别体素化。
7. 使用双向最近点残差：
   - 模型点到观测点；
   - 观测点到模型点。
8. 使用 SciPy `least_squares` 的 `soft_l1` 鲁棒优化。
9. 当前只优化 4 个自由度：

```text
x, y, z, yaw
```

roll 和 pitch 被固定为直立先验。

10. 对结果做门禁：
    - p90 残差；
    - 模型内点率；
    - 观测内点率；
    - mask 是否触边；
    - 主解和竞争初值是否接近；
    - outer＋rim 和 inner＋rim 是否都能解释观测。

因此，V5-3b 的 accepted 表示“当前几何和门限通过”，不能直接等价为真实精度或抓取可靠。

## 三、有粗位姿后，推荐怎样改

假设你的初值满足：

```text
平移误差：不超过约 20 cm
yaw 误差：不超过约 30°
箱体大致直立
箱体尺寸和 mesh 已知
```

推荐做一个新的 `V5-prior` 版本。

### 阶段 1：粗位姿验证

先把外部粗位姿变换到统一的 `base_link` 坐标系，检查：

- 是否在相机前方；
- 是否落在合理工作空间；
- 投影后是否和 mask 有重叠；
- 当前修正量是否超过允许范围；
- roll/pitch 是否超过直立假设。

这里需要使用：

```text
||Δtranslation|| ≤ 0.20 m
|Δyaw| ≤ 30°
```

作为搜索范围，而不是把粗位姿直接当成最终结果。

### 阶段 2：局部粗搜索

不能直接把粗位姿送进一次 ICP。

20 cm 和 30° 对当前箱体来说仍然比较大，直接局部最近点优化可能落入：

- 内壁解；
- 外壁解；
- 180° 对称解；
- 邻箱表面；
- 空间上接近但语义错误的表面。

建议围绕粗位姿做一个低成本的批量搜索，例如：

```text
平移：多个 5–10 cm 间隔的候选
yaw：粗采样 ±30°
z：沿高度先验和深度范围采样
```

每个候选只做快速评分：

- 投影 mask 重叠；
- 轮廓距离；
- 观测深度和渲染深度差；
- 可见表面覆盖率；
- 箱体尺寸约束；
- 法向一致性。

然后只保留前 3～5 个候选进入精细优化。

这个阶段特别适合 GPU，因为不同候选之间可以批量计算。

### 阶段 3：多尺度 4DoF 精修

对前 3～5 个候选进行：

1. 20 mm 体素层粗配准；
2. 10–12 mm 中等分辨率配准；
3. 5–8 mm 精细配准；
4. 每一级限制最大对应距离；
5. 使用 point-to-plane 或 depth-rendering 残差；
6. 使用 Huber/Cauchy/soft-L1 抑制箱内货物和离群点。

对于 4DoF，可以直接构造小规模 Gauss-Newton/Levenberg-Marquardt 更新：

```text
δ = [dx, dy, dz, d_yaw]
```

每次根据模型点法向建立 4 列 Jacobian，直接解一个很小的线性系统。这样可以避免当前 SciPy `least_squares` 的大量有限差分和重复 KD-tree 构建。

### 阶段 4：保留 V5-3b 的安全门禁

即使有粗位姿，也要继续保留：

- outer/inner 两种表面解释；
- best 与 second-best 的分数差；
- 双向残差；
- mask 覆盖率；
- 触边检查；
- 结果是否触碰搜索边界；
- 估计修正量是否超过 20 cm/30°。

如果出现以下情况，应触发 B/C 备用流程：

- 粗位姿投影和 mask 几乎没有重叠；
- 优化跑到搜索边界；
- 外壁和内壁得分接近；
- best/second-best 差距过小；
- 可见点数量不足；
- 深度残差明显高于基线。

这样可以实现：

```text
正常帧：粗位姿 → 快速配准
困难帧：粗位姿失败 → B/C 补算
```

这比正式删除 B/C 更稳妥。

## 四、哪个算法最适合当前项目

### 方案 A：有标签时，AprilTag/ChArUco＋PnP

如果允许在箱体上固定标记，这是最快、最确定的路线：

```text
检测 tag 四角
    ↓
PnP 求 tag 位姿
    ↓
乘以 tag 到箱体的标定变换
    ↓
得到箱体中心、yaw、抓取参考点
```

## 五、为什么不建议直接上“普通 ICP”

我们已经做过 V5-4 的 ICP A/B：

- 受约束 ICP 的 p90 残差中位数只变化约 −0.02 mm；
- 6/11 帧改善，5/11 帧变差；
- 侧壁法向对 z 方向支持不足；
- 直接全 mesh ICP 的 p90 中位数恶化约 +65.38 mm；
- 直接全 mesh ICP 出现较大的方向错误。

这说明普通 ICP 的问题不是“有没有 GPU”，而是：

- 初值和表面对应是否正确；
- 观测点是否真的来自目标外壁；
- z 方向是否可观测；
- 内壁和外壁是否混在一起；
- 是否存在 180° 对称。

GPU 只会让错误匹配更快。它不会自动解决语义表面和歧义问题。

## 六、GPU 优化建议

### 第一阶段：先做 CPU 结构优化

在上 GPU 前，建议先做这些：

1. 把外部粗位姿直接作为输入。
2. 正常帧跳过 B/C。
3. 初值数量从 12 降到 3–5 个。
4. 预缓存 mesh 点、法向、角色和局部采样。
5. 预缓存观测点和体素索引。
6. 避免每次残差计算都重新构建 reverse `cKDTree`。
7. 从有限差分 `least_squares` 改成 4DoF 的解析 Jacobian。
8. 将 mesh 采样减少到有语义的外壁、箱沿和内壁点。
9. 粗到细地减少优化迭代次数。
10. 大量数组计算使用 FP32，最终门禁和累计量可以保留 FP64。

当前 V5-3b 每个初值最多 120 次优化迭代，又要执行双向最近点和可见性相关计算，所以减少初值和迭代次数可能比直接换 GPU 更重要。

### 第二阶段：GPU 化最适合的部分

优先将以下部分迁移到 CUDA：

1. 批量位姿变换；
2. 模型点投影；
3. z-buffer 和图像边界判断；
4. mask/轮廓/深度评分；
5. 批量残差；
6. 分块最近邻或固定半径邻域查询；
7. 多个粗位姿候选的并行评分。

不要一开始把整个 Python 流程全部搬到 GPU。更合理的是：

```text
CPU：输入检查、候选管理、最终门禁
GPU：批量投影、评分、最近邻、Jacobian 累加
CPU/GPU：少量 4DoF 优化迭代
```

如果使用 CUDA 异步执行，计时必须等 GPU 完成后再停止；CUDA 的 kernel launch 和内存操作可能异步返回，需要用 event 或同步点保证计时正确。[CUDA Asynchronous Execution](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/asynchronous-execution.html)

### 第三阶段：重新做 Orin A/B

必须建立三组独立版本：

```text
CPU baseline：当前 V5-2 + V5-3b
CPU prior：先验引导 CPU 版本
GPU prior：先验引导 GPU 版本
```

每组在同一批 D01–D12 上比较：

- 算法时间；
- 容器总墙钟；
- 首次运行和预热后运行；
- CPU→GPU 传输时间；
- GPU kernel 时间；
- 状态和拒绝原因；
- 中心、yaw、箱口中心和短边点；
- best/second-best 分数；
- 独立参考误差。

只有当 GPU 版本同时满足：

```text
耗时下降
位姿变化在容差内
拒绝语义没有退化
没有新增可疑 accepted
```

才考虑接入正式流程。

## 最终建议

当前最推荐的开发顺序是：

1. 保留 V5-2 + V5-3b 作为回退基线。
2. 新增外部粗位姿输入。
3. 开发先验引导的 4DoF 粗搜索＋多尺度可见壳体优化。
4. 正常帧跳过 B/C，失败或歧义帧触发 B/C。
5. 先用 CPU 完成 D01–D12 和扰动初值实验。
6. 再将批量投影、z-buffer、评分和最近邻迁移到 CUDA。
7. 如果允许贴标签，优先做 AprilTag/ChArUco＋PnP 原型。
8. 继续使用独立标定板或测量结果验证真实精度；FDP 只能作为后端差异参考。

简而言之：

> 有 20 cm / 30° 粗位姿后，最合适的方向是“先验引导的可见壳体配准”，而不是直接使用普通 ICP，也不是立刻训练一个大型 6D 网络。

## 16. 助手

这段话基本正确，前提是：**箱体和任务允许把长轴两端视为等价。**

对理想无方向矩形，`90°` 与 `−90°` 相差 180°，中心和占据的几何区域相同。比较 yaw 时可以用：

```python
yaw_diff_deg = abs((yaw_a - yaw_b + 90) % 180 - 90)
```

这样差值范围是 `[0°, 90°]`，`90°` 和 `−90°` 的差为 `0°`。但要注意：

- 400×300 mm 的矩形，**相差 90°不等价**，会交换长短边。
- 相差 180°会交换长轴正负端，也就是两个短边抓取点的编号。
- 如果箱体有方向性结构，或左右机械臂绑定了特定箱体端面，就不能只靠这个对称差判断位姿等价，还要核对端面身份和抓取点分配。

| V5-R / R＋M | ROI 初值＋原 mesh 粗初值 |
