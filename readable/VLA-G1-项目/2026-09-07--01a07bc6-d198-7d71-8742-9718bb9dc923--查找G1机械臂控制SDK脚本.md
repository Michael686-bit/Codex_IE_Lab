## 官网 API 为什么可以控制机械臂

Galbot SDK 不是直接操作电机驱动，而是：

```text
Python 程序
   ↓
Galbot SDK
   ↓
G1 本机通信中间件 / 控制服务
   ↓
WBCS / 关节控制器
   ↓
电机与机械臂
```

官网文档说明，`GalbotRobot.init()` 会初始化硬件通信、中间件和传感器接口，并连接控制服务；G1 上的相关服务位于 `/data/galbot/bin/`。

因此 SDK 需要：

```text
/data/galbot/lib/galbot_sdk
/opt/galbot/galbot_sdk/linux-aarch64-gcc940/setup.sh
G1 本机控制服务
G1 本机配置和 URDF
```

相关文档位置见 [官网 API 文本](../../assets/e124cdcbceb88cfd--pasted-text.txt:1640)。

## 官网推荐的基本控制流程

### 1. 加载 SDK 环境

```bash
source /opt/galbot/galbot_sdk/linux-aarch64-gcc940/setup.sh
export PYTHONPATH="/data/galbot/lib:${PYTHONPATH:-}"
export GALBOT_CONFIG_DIR=/userdata/config/pw1
```

当前项目已经在 [run_g1_arm_smoke_test.sh](/home/lsy03/文档/ChatGPT/VLA%20G1%20项目/g1_arm_smoke_test/run_g1_arm_smoke_test.sh:5) 中做了这些事情。

### 2. 初始化机器人

```python
from galbot_sdk.g1 import GalbotRobot

robot = GalbotRobot()

if not robot.init():
    raise RuntimeError("SDK 初始化失败")

if not robot.is_running():
    raise RuntimeError("机器人控制系统未运行")
```

### 3. 查询关节和状态

```python
names = robot.get_joint_names(True, ["left_arm"])
states = robot.get_joint_states([], names)
```

官网要求显式确认关节名称和顺序。当前项目已经做了这部分检查，并确认 G1 左臂是：

```text
left_arm_joint1
...
left_arm_joint7
```

### 4. 确认控制器权限

官网提供了：

```python
robot.acquire_controller("left_arm_pvt_ctrl")
robot.get_active_controller("left_arm")
robot.start_controller("left_arm")
```

当前项目只检查活动控制器是否为 `left_arm_pvt_ctrl`，见 [g1_arm_smoke_test.py](/home/lsy03/文档/ChatGPT/VLA%20G1%20项目/g1_arm_smoke_test/g1_arm_smoke_test.py:730)，并没有主动调用：

```text
acquire_controller()
start_controller()
release_controller()
```

这属于当前项目需要进一步确认的地方：如果 G1 默认已经由 `left_arm_pvt_ctrl` 持有控制权，现有脚本可能可以工作；如果没有，就需要补充显式的控制器权限流程。

### 5. 发送关节命令

官网提供三种主要方式。

低频位置控制：

```python
status = robot.set_joint_positions(
    [target_position],
    [],
    ["left_arm_joint7"],
    True,
    0.03,
    20.0,
)
```

这就是当前项目实际使用的接口，见 [第 592 行](/home/lsy03/文档/ChatGPT/VLA%20G1%20项目/g1_arm_smoke_test/g1_arm_smoke_test.py:592)。适合单次姿态变化或低频关键帧。

高频流式控制：

```python
robot.set_joint_commands(
    joint_commands,
    joint_names=["left_arm_joint1", "...", "left_arm_joint7"],
)
```

官网明确建议：如果是 VLA 逐帧输出或实时遥操作，应使用 `set_joint_commands()` 或 `set_joint_commands_batch()`，而不是反复提交完整的 `set_joint_positions()`。见 [官网 API 文本](../../assets/e124cdcbceb88cfd--pasted-text.txt:817)。

轨迹控制：

```python
robot.execute_joint_trajectory(trajectory, is_blocking=True)
```

适合预先规划好的多路点轨迹。

### 6. 读取反馈并处理异常

控制后需要重新读取关节位置、速度和时间戳，检查是否到位。

异常情况下：

```python
robot.stop_trajectory_execution()
```

当前冒烟测试已经实现了这一步。

### 7. 释放和关闭 SDK

推荐完整关闭流程：

```python
robot.release_controller("left_arm")
robot.request_shutdown()
robot.wait_for_shutdown()
robot.destroy()
```

官网规定的关闭顺序是：

```text
request_shutdown()
→ wait_for_shutdown()
→ destroy()
```

当前项目已经实现了后三步，但没有显式 `release_controller()`。

## 当前还缺少什么

如果目标只是“安全地让某个关节动一下”，主要还缺：

1. 确认当前运行的 SDK 版本和官网 API 版本是否匹配。
2. 确认 `left_arm_pvt_ctrl` 是否需要显式 `acquire_controller()`。
3. 在 G1 上实际部署并运行 `g1_arm_smoke_test`。
4. 现场确认控制权限、急停和当前姿态。
5. 做第一次真实单关节动作验证。

如果目标是“GP001 实时控制 G1”，还缺：

1. G1 端持有长期 SDK 会话的控制程序。
2. 使用 `set_joint_commands()` 的高频关节命令发送。
3. 7 个关节的明确名称和顺序。
4. G1 端反馈闭环。
5. 网络身份认证。
6. 网络断开后的 G1 端停止策略。
7. 控制器获取、释放和进程退出清理。
8. GP001 与 G1 关节方向、单位和比例的真机标定。

当前 [g1_sdk_network_preview.py](/home/lsy03/文档/ChatGPT/VLA%20G1%20项目/teleoperation/g1_sdk_network_preview.py:1) 明确是“preview”，不会调用运动 API，所以它还不能控制真实机械臂。

## 代码应该放在哪里运行

建议采用这个模式：

```text
主机：
  编辑代码
  采集 GP001
  做单元测试
  通过 SSH 上传到 G1
       ↓
G1：
  source SDK 环境
  运行 GalbotRobot 控制程序
  调用真实关节控制 API
```

例如你在主机终端输入：

```bash
ssh <G1主机> 'cd /home/galbot/your_project && ./run_g1_arm_smoke_test.sh --execute'
```

虽然命令是在主机输入的，但 Python 程序实际运行在 G1 上。

当前开发主机之前没有：

```text
/data/galbot/lib/galbot_sdk
/opt/galbot/galbot_sdk/linux-aarch64-gcc940/setup.sh
```

所以在主机本地直接运行真实控制脚本会失败。之前的只读验证记录表明，G1 上曾经成功运行过 SDK 1.9.0，并读取到 `left_arm_pvt_ctrl` 和左臂 7 轴状态，见 [READ_ONLY_VALIDATION.md](/home/lsy03/文档/ChatGPT/VLA%20G1%20项目/robot_g1/READ_ONLY_VALIDATION.md:1)。

还要注意：之前读取到的 G1 当前姿态中，左臂第 1、5、6 关节接近或位于硬限位，因此目前只能优先考虑第 7 关节做极小动作，不能直接扩展到完整左臂。
