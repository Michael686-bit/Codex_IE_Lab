1. Galbot 原生方案最值得优先验证

Galbot SDK 的 `GalbotMotion` 已提供：

- `check_collision()`：检查机器人状态是否发生自碰撞或环境碰撞，支持批量状态；
- `motion_plan()`、`motion_plan_multi_waypoints()`：带碰撞检查的单链、多链和双臂轨迹规划；
- `add_obstacle()`：添加 box、sphere、cylinder、mesh、point cloud、depth image；
- `attach_target_object()`、`attach_tool()`：把夹爪、工具或抓取物加入碰撞模型；
- `safe_margin`：为环境障碍设置安全距离。

Galbot 官方说明也明确指出，环境障碍必须由用户手动加入，`galbotMotion` 当前不会自动同步导航系统的实时点云地图；移动障碍物需要删除后重新添加。[G1 SDK 1.9.0 碰撞示例](https://developer.galbot.com/docs/SDK/1.9.0/g1/en/examples_python/)、[G1 SDK 1.9.1 API](https://developer.galbot.com/docs/SDK/1.9.1/g1/en/api_python_reference/)

当前脚本走的是低层控制路径：

- [j7\_follow.py (line 437)](</home/lsy03/文档/ChatGPT/VLA G1 项目/teleoperation/j7_follow.py:437>) 使用 `publish_target()`；
- [j7\_follow.py (line 439)](</home/lsy03/文档/ChatGPT/VLA G1 项目/teleoperation/j7_follow.py:439>) 使用 `set_joint_positions()`；
- SDK 对 `publish_target()` 的说明是“只做基础结构校验”，没有碰撞规划；
- 项目文档也明确写着 `set_joint_positions()` 没有环境碰撞检测承诺。[g1\_arm\_smoke\_test/README.md (line 64)](<../../assets/d1560a47987e7d4f--README.md:64>)

因此，当前遥操作不能认为已经具备自碰撞或桌面避障保护。

2. G1 的 MoveIt 支持情况

Galbot 官方公开的 [galbot\_one\_golf\_description](https://github.com/GalaxyGeneralRobotics/galbot_one_golf_description) 提供 URDF、MJCF、USD 和碰撞网格，官方包本身主要是机器人描述和 RViz 显示。它的 `package.xml` 只声明了 `ament_cmake` 和 `xacro`，[CMakeLists.txt](https://raw.githubusercontent.com/GalaxyGeneralRobotics/galbot_one_golf_description/main/CMakeLists.txt) 也没有 MoveIt 配置或 `ros2_control` 控制器。

所以目前应判断为：

- **有条件使用 MoveIt 做离线模型、碰撞检查和规划；**
- **没有证据表明 G1 官方提供开箱即用的 MoveIt 真机控制链；**
- 若要真机执行，需要自己制作 `moveit_config`、SRDF、双臂规划组、控制器配置，并编写 MoveIt 到 Galbot SDK 的桥接层。

MoveIt Servo 很适合实时遥操作：接近自碰撞或环境碰撞时会减速，碰撞时可停止。[MoveIt Servo 官方说明](https://moveit.picknik.ai/main/doc/examples/realtime_servo/realtime_servo_tutorial.html) 但它需要完整的 `robot_description`、PlanningScene、关节状态输入和硬件控制接口。

当前项目也还没有安装 MoveIt 或 `ros2_control`；而且本项目的 RViz 模型会主动删除 collision geometry，[model.py (line 72)](</home/lsy03/文档/ChatGPT/VLA G1 项目/g1_rviz_sim/g1_rviz_sim/model.py:72>)，所以现有 RViz 仿真不能直接用于碰撞验证。
