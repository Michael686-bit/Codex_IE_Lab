### 迁移时最需要注意的点

1. **先准备容器运行时**
   安装 Docker、Compose 和 NVIDIA Container Toolkit，先验证容器内能看到 RTX PRO 5000。

2. **LingBot 不能只复制 Dockerfile**
   它依赖本地自定义基础镜像 `lingbot-vla-v2:4144e9c-infer`，以及外部模型目录和数据目录。需要导出/导入完整镜像，或在 Pro4000 上重建基础镜像。

3. **Blackwell 要重新做 CUDA smoke test**
   原环境是在 RTX 4090 上验证的。Pro4000 是 Blackwell、计算能力 12.0，Triton、FlashAttention、grouped-GEMM 等自定义 kernel 不能直接假定兼容；不要直接复用 4090 的编译缓存，需要在 Pro4000 上重新编译和验证。

4. **ACT/SmolVLA 和 Pi05 最适合作为第一批迁移对象**
   它们基于标准 PyTorch CUDA 12.8 镜像，版本锁定完整，48 GB 显存也比原来的 4090 更宽裕。

5. **真机控制应单独处理**
   Pro4000 目前更适合承担训练和推理。GP001/G1 控制还需要有线网络、串口设备，并确认现有 SDK 1.10.0 与项目记录的 PC SDK 1.9.1 是否兼容。

建议的迁移顺序是：
**Docker/NVIDIA 运行时 → ACT/SmolVLA smoke test → LingBot 基础镜像和当前训练模型 → Pi05 → RoboTwin → 真机控制环境。**

### 网络和 USB 怎么选

| 内容 | 推荐方式 |
|---|---|
| 代码、配置、几十 MB 的修改 | Git/SSH/rsync |
| 单个 checkpoint、日志、指标 | 网络 rsync |
| 首次 Docker 镜像 | USB 或移动 SSD |
| LingBot 基础模型 | USB/移动 SSD |
| 10 GB 以上数据集 | USB/移动 SSD |
| 后续新增数据和增量 checkpoint | 网络 rsync |
| 定期完整备份 | USB/移动 SSD |

当前 Pro4000 的数据盘有约 14 TB 可用空间，适合长期保存模型、数据和运行结果。

如果是 USB 3.x 移动 SSD：

- 持续速度 300 MB/s 以上：明显快于当前 Wi‑Fi
- 普通高速 U 盘 50–100 MB/s：通常仍比 Wi‑Fi 快
- USB 2.0 或低速 U 盘低于 30 MB/s：网络可能接近甚至更快

所以我的建议是：**不要用普通慢速 U 盘，最好用 USB 3.x 移动 SSD。**

### 实际迁移流程

1. 先通过 USB 搬运 Docker 镜像、基础模型和首批数据。
2. 在 Pro4000 上校验 SHA256。
3. 安装 Docker 和 NVIDIA Container Toolkit。
4. 先运行 PyTorch/CUDA/Blackwell smoke test。
5. 再运行 LingBot 单步加载和单步反向传播。
6. 通过后开始正式训练。
7. 后续代码、配置、日志和小 checkpoint 用 `rsync` 增量同步。

Docker 镜像不要复制 Docker 的内部存储目录，应该导出成归档文件，例如：

