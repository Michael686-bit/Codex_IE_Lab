你现在迷茫很正常：这个项目同时涉及机器学习、数据处理、机器人控制和部署。如果还没有理解这些环节的关系，就直接面对“换模型、调学习率、改 LoRA 参数”，很难知道每次修改究竟在解决什么问题。接下来最有价值的目标是：**能解释一次预测怎样产生，并判断一次失败更可能发生在哪个环节。**

**先围绕你自己的 G1 项目，建立一张完整的流程图。**

可以先记住这条链路：

**相机图像＋任务指令＋机器人状态 → 数据预处理 → 模型预测动作 → 动作还原与检查 → SDK 执行 → 获取新观测**

训练则是：用遥操记录的“观察—动作”样本，让模型学习在某种观察下应该输出什么动作。

这里有几个值得尽早弄懂的问题：

- 数据里的“动作”是关节角度、关节增量，还是末端位置？
- 训练标签记录的是下发目标，还是实际运动结果？
- 模型一次输出未来多步动作，控制程序实际执行几步？
- 训练时用的图像、单位、归一化方式，和部署时是否一致？
- 验证损失下降，为什么仍然可能抓不到瓶子？

能结合自己的代码回答这些问题，比现在掌握一堆模型名更有用。

**建议用下面这条学习路线，先安排 4～6 周。** 这只是起步节奏，不是要求你几周内掌握整个领域；如果 Python 还不熟，第一阶段可以多花时间。

| 阶段 | 学习重点 | 在你的项目里做什么 | 学会的标志 |
|---|---|---|---|
| 1. 看懂数据 | Python、数组和张量、维度、均值与标准差、基本画图 | 读取一个 episode，查看三路图像，画出关节和夹爪曲线 | 能解释一条样本中每个字段的含义、形状和单位 |
| 2. 看懂训练 | 训练/验证划分、损失、梯度、学习率、过拟合、归一化 | 跑一个很小的 PyTorch 教学实验，再读自己的训练日志 | 能解释训练损失下降但验证效果变差的原因 |
| 3. 看懂策略 | 模仿学习、VLA 输入输出、动作块、预训练、微调、LoRA | 沿一条真实样本追踪输入、模型输出和动作还原 | 能说清你当前模型究竟学什么、哪些参数被更新 |
| 4. 看懂部署与评估 | 关节空间、绝对/相对动作、控制频率、延迟、开环/闭环 | 先离线回放和只读预览，再安排有明确通过条件的真机实验 | 能区分数据、模型、输入输出适配和控制执行问题 |

数学按需补：先掌握向量、矩阵、角度单位、均值方差，以及“梯度决定参数调整方向”的直觉。Transformer、Flow Matching 的详细推导可以往后放。

**资料先限制在两套主线和一份概念阅读，避免收藏太多学不下去。**

1. **机器人学习主线：[Hugging Face Robotics Course](https://huggingface.co/learn/robotics-course/unit0/1)**
   官方课程涉及机器人基础、机器人学习和 LeRobot。先看介绍与基础章节，把术语对应到你的项目；不需要为了跟课另买一套机器人。

2. **训练基础：[PyTorch — Learn the Basics](https://docs.pytorch.org/tutorials/beginner/basics/intro.html)**
   按张量、数据加载、模型、自动求导、优化和保存模型的顺序学习。教学里的小模型很适合建立训练直觉，没有必要每次都用大模型做学习实验。

3. **理解 VLA：[RT-2 论文](https://arxiv.org/abs/2307.15818)**
   第一遍只看摘要、示意图和实验结论，回答“视觉、语言怎样和动作联系起来”。它用于建立概念，不是你当前 LingBot 代码的操作手册。

**学习工具保持简单：项目里的 Markdown 笔记＋可运行的小脚本或 Notebook＋Git 就够起步。**

我支持你建立“VLA 与 G1 真机实践笔记”，但建议明确分成四类：

| 笔记类型 | 记录什么 |
|---|---|
| 概念笔记 | 用自己的话解释概念，并举一个 G1 项目例子 |
| 代码地图 | 一个入口调用哪些模块，数据在哪里转换，关键张量是什么形状 |
| 实验记录 | 改了什么、为什么改、结果和证据在哪里 |
| 待解决问题 | 当前不理解什么，哪些判断还只是猜测 |

例如，一条实验记录可以只有：

```text
问题：模型是否会对瓶子位置变化作出正确响应？
假设：
固定条件：模型版本、指令、采样噪声等
本次改变：
评价方式：
观察结果：
结论与证据：
下一步：
```

尤其要把“我猜测”“离线证实”“真机证实”分开写。笔记的价值在于帮助你判断，不在于篇幅。

**和我对话时，建议采用“讲解—练习—复述—纠错”的方式。**

你可以直接这样要求我：

> 用我项目中的一个真实样本教我。每次只讲一个概念，先解释，再对应到代码，然后给我一个小练习。不要马上给答案，等我解释后再指出错误。最后整理经过验证的笔记。

这样你会逐渐拥有自己的判断能力。每次我提出调参建议，也应该说明：**观察到了什么问题、为什么这个修改可能有效、用什么实验判断它是否有效。**

针对你现在的情况，我建议**暂缓新增调参和模型分支，把现有结果保留下来；先完成“读懂一个 episode → 追踪一次预测 → 解释一份评估报告”这三个练习。** 不必暂停整个项目，也不用急着开始真机运动。

你的第一课就可以定为：**“G1 牛奶任务里，一条训练样本到底包含什么？模型看到什么，又被要求输出什么？”** 这是后续理解训练、调优和真机部署最扎实的起点。
