## 1. 用户

核心区别不是“模型大小”，而是它们在应用中扮演的角色不同：

- ACT：针对具体任务重新训练一个动作策略。
- SmolVLA：在通用视觉—语言—动作底座上，用 S1 数据微调。
- π0.5：更大的通用 VLA，需要更复杂的机器人映射和微调。
- LingBot‑VLA 2.0：面向双臂、腰、头、移动底盘的全身控制，需要做统一动作空间映射和后训练。
- π0.7：理论上更接近免任务训练的通用策略，但目前没有成熟公开入口，暂时不能作为可落地方案。

## 共同的应用流程

无论选哪一个，真正接到 S1 上都绕不开：

```text
S1 驱动与安全控制
      ↓
相机图像 + 关节/末端状态采集
      ↓
模型要求的数据格式与动作空间
      ↓
模型推理，生成一段未来动作
      ↓
动作反归一化、限速、限位、碰撞检查
      ↓
发送给 S1 的底层控制器
```

“模型不需要训练”不等于“接上机器人就能动”。至少仍需要完成：

- 相机、关节、夹爪、底盘的数据接口；
- 模型动作维度与 S1 控制接口的映射；
- 控制频率、坐标系和单位统一；
- 动作限幅、急停和安全状态机。

## 各模型的实际流程差异

| 模型 | 输入 | 数据准备 | 模型适配 | 任务切换方式 | S1 自定义任务是否训练 |
|---|---|---|---|---|---|
| ACT | 图像＋机器人状态 | 每个任务采集演示 | 通常从头训练任务策略 | 更换模型/checkpoint | **必须** |
| SmolVLA | 图像＋状态＋语言指令 | 演示轨迹＋每条轨迹的语言描述 | 微调 450M 预训练底座 | 用语言切换已训练过的任务 | **基本必须** |
| π0.5 | 多视角图像＋状态＋语言 | 演示、语言、动作映射、归一化统计 | 通常全参数微调 | 语言指令＋多任务策略 | **S1 上基本必须** |
| LingBot‑VLA 2.0 | 图像＋语言＋全身状态 | 演示、机器人配置、55 维统一动作映射、归一化统计 | 大模型后训练 | 语言＋统一全身策略 | **建议且通常必须** |
| π0.7 | 历史图像＋语言＋子任务＋视觉子目标＋元数据 | 官方大规模混合数据体系 | 当前无成熟公开适配流程 | 语言指导、子目标图、控制模式 | 当前无法自行验证 |

### 1. ACT：每个任务训练一个“小专家”

流程通常是：

```text
遥操作 S1 完成任务
→ 录制图像、关节状态和动作
→ 训练 ACT
→ 输出动作块
→ S1 执行
```

特点：

- 不依赖语言，任务描述对 ACT 可以省略。
- 通常一个模型对应一个任务或一组非常接近的任务。
- 新增“开抽屉”任务，一般需要采集开抽屉演示并重新训练。
- 优点是链路短、容易调试、推理快。
- 它学习的是“看到这种画面和状态时如何动作”，而不是通过语言理解任意新任务。

LeRobot 官方把 ACT 定位为适合入门的轻量模仿学习策略，约 80M 参数，通常使用几十条演示，并在单卡上训练数小时。[ACT 官方文档](https://huggingface.co/docs/lerobot/act)

训练判断：

- 使用别人完全相同的机器人、相机位置和任务 checkpoint：可以只推理。
- 换成 S1 或换任务：**必须重新训练，或至少继续训练**。
- 实际项目里可以把 ACT 看成“必训练模型”。

### 2. SmolVLA：语言条件下的轻量通用底座

流程是：

```text
用语言标注任务
＋
遥操作采集 S1 演示
→ LeRobot 数据集
→ 微调 smolvla_base
→ 输入“把红色方块放入盒子”
→ 输出动作块
```

它和 ACT 的关键区别：

- ACT 不真正理解任务语言；SmolVLA 把语言作为正式输入。
- ACT 更像一个任务一个策略；SmolVLA 可以把多个任务放入同一个数据集，用语言区分。
- SmolVLA 已经有视觉—语言—动作预训练，因此不是从零开始学，但仍然需要学习 S1 的身体和动作规律。

官方明确说明：`smolvla_base` 是基础模型，针对自己的机器人和环境需要微调；推荐约 50 个 episode 作为起点，示例中 25 个 episode 表现不足。[SmolVLA 官方文档](https://huggingface.co/docs/lerobot/smolvla)

训练判断：

- 只在官方支持的机器人和示例任务上复现：可能直接使用对应 checkpoint。
- S1 自定义任务：**需要微调**。
- 多个简单任务可以一次联合微调，不一定每个任务单独训练一个模型。
- 在这几款里，它是“VLA 能力”和“个人工作站可操作性”之间最平衡的。

### 3. π0.5：不只是训练，动作适配也更复杂

完整流程通常是：

```text
采集 S1 数据
→ 转换为 LeRobot 格式
→ 编写 S1 输入映射
→ 编写模型输出到 S1 动作的映射
→ 计算状态/动作归一化统计
→ 微调 π0.5
→ 启动模型推理服务器
→ S1 客户端通过网络请求动作
```

和 SmolVLA 相比，主要增加了：

- 更严格的 observation/action transforms；
- 关节位置、末端位姿、夹爪等动作语义对齐；
- normalization statistics；
- 模型服务器和机器人控制端分离部署；
- 更高的显存、环境和训练配置成本。

OpenPI 的官方流程就是“转换数据 → 定义输入输出映射及训练配置 → 计算归一化统计 → 微调 → 启动策略服务器”。公开的 π0.5‑DROID checkpoint 可以在 DROID 平台上推理或继续微调，但不能直接当成 S1 策略使用。[OpenPI 官方仓库](https://github.com/Physical-Intelligence/openpi)

需要特别修正表里的“LoRA 很紧”：

- 不是单纯显存紧张。
- OpenPI 官方表示，他们尝试过用 LoRA 降低 π0.5 微调成本，但暂未获得理想策略效果；其 PyTorch 实现目前也未正式支持 LoRA 训练。[π0.5 DROID 训练说明](https://github.com/Physical-Intelligence/openpi/blob/main/examples/droid/README_train.md)

因此在一张 4090 上：

- 推理：可以考虑。
- 官方标准全量微调：通常超出舒适范围。
- LoRA：可以作为工程实验，但目前不能视为成熟、可靠的正式路线。
- 更现实的是租用大显存 GPU 完成微调，4090 用于部署推理。

### 4. LingBot‑VLA 2.0：面向 S1 全身控制，但训练工程最重

它的流程比 π0.5 又多一层“统一身体表示”：

```text
S1 原始状态/动作
→ 编写 S1 Robot Config
→ 映射到 55 维统一状态/动作空间
→ 准备 LeRobot 数据
→ 计算归一化统计
→ 对 6B 底座做后训练
→ 部署策略服务器
→ 将 55 维输出还原为 S1 双臂/夹爪/腰/头/底盘命令
```

55 维统一表示涵盖：

- 双臂关节；
- 末端位姿；
- 夹爪或灵巧手；
- 腰部；
- 头部；
- 移动底盘。

因此它比 ACT、SmolVLA 更适合“移动＋双臂＋全身协同”的长任务，但接入工作不只是改几个关节名称。

官方已经公开：

- 6B 预训练权重；
- RoboTwin 后训练权重；
- 自定义数据、Robot Config、归一化统计和后训练流程；
- 4090D 上约 130 ms/次的推理测试。

官方报告也包含 Astribot S1 冰箱整理实验。[LingBot‑VLA 2.0 官方仓库](https://github.com/Robbyant/lingbot-vla-v2)

不过需要注意：**论文里在 S1 上做过实验，不代表公开底座可以免训练复现该实验**。当前公开仓库主要提供通用预训练和 RoboTwin 后训练权重；S1 实验所用的具体数据、配置和完整后训练 checkpoint 并不等同于公开的通用底座。

训练判断：

- 只验证模型能否加载并输出动作：不需要训练。
- 真正在自己的 S1、自己的相机布局和任务上运行：通常需要后训练。
- 单张 4090 更适合推理；6B 模型后训练一般需要更大显存或多卡方案。

### 5. π0.7：理论上最接近“不训练”，实际上目前不能落地

π0.7 的运行链路比普通 VLA 更像分层机器人系统：

```text
总任务
→ 高层策略生成当前子任务
→ 世界模型生成视觉子目标
→ π0.7 读取图像历史、语言、子目标、质量/速度元数据
→ 动作专家输出动作块
```

它不只接收一句任务语言，还可以接收：

- 子任务指令；
- 视觉子目标；
- 历史观测；
- 控制模式；
- 速度、质量等 episode metadata。

官方展示了无需针对具体任务微调的语言指导、组合泛化和跨机器人迁移能力。[π0.7 官方介绍](https://www.pi.website/blog/pi07)

但截至目前，公开 OpenPI 的可下载 checkpoint 和正式训练配置仍集中在 π0、π0‑FAST 和 π0.5，没有 π0.7 那样的公开训练—部署入口。因此：

- 从研究能力上说，它可能执行部分“无需任务微调”的任务。
- 从你的 S1 项目上说，目前没有公开权重和成熟工具链可供本地接入。
- 它现在既不能归为“需要自行训练”，也不能归为“可直接免训练使用”，更准确的状态是：**当前公开条件下不可实施**。

## 最终分类

### 在 S1 自定义任务上必须或基本必须训练

- ACT：必须训练，通常从任务数据开始。
- SmolVLA：必须微调预训练底座。
- π0.5：基本必须微调，而且需要复杂的输入输出映射。
- LingBot‑VLA 2.0：基本必须后训练，尤其是新任务、新相机布局或全身控制。

### 可以不训练的情况

只有以下有限情况：

- 运行随机输入或离线推理，验证环境是否装好；
- 使用与公开 checkpoint 完全匹配的机器人、相机、动作空间和任务；
- 仅复现官方仿真 benchmark；
- π0.7 官方内部支持的机器人上尝试零样本任务——但当前不属于公开可部署路线。

## 对 S1 最合理的路线

建议按下面顺序推进：

1. **ACT**：打通 S1 数据采集、动作映射、安全控制和闭环推理。
2. **SmolVLA**：复用同一套数据链路，加入语言标签，得到第一套正式 VLA。
3. **π0.5**：有更大训练资源后，研究跨任务和更强语言泛化。
4. **LingBot‑VLA 2.0**：在目标升级为双臂＋腰＋头＋底盘长流程任务后接入。
5. **π0.7**：等待公开权重、训练代码或官方访问渠道。

一句话概括：**ACT 是“从演示学一个动作技能”，SmolVLA 是“用语言组织多个技能”，π0.5 是“大规模通用 VLA 的适配”，LingBot 是“全身多形态 VLA 的后训练”，π0.7 则是“有高层规划和视觉子目标的通用系统，但目前还不是公开可实施方案”。**

## 2. 助手

建议现在**优先使用本地 S1 仿真**，不要把闲置 G1 当成 S1 的临时替代品。

原因不是 G1 不好，而是两者的身体结构、关节定义、动作空间、控制频率、相机位置和动力学差异很大。用 G1 采集的动作数据通常不能直接用于 S1；等 S1 空闲后，仍要重新做动作映射和数据采集。对 ACT、SmolVLA 这类依赖机器人本体数据的方案尤其如此。

### 推荐路线

1. 在 S1 仿真中打通完整闭环：

```text
遥操作/脚本生成演示
→ LeRobot 数据集
→ ACT 训练
→ 仿真闭环评测
→ SmolVLA 微调
```

2. 仿真接口从一开始就按真实 S1 设计：

- 使用与 S1 一致的关节顺序、单位和限位；
- 固定相机名称、分辨率和安装位姿；
- 统一控制频率与 action chunk；
- 把模型输出先交给独立的安全层；
- 将“仿真控制器”和“真机控制器”做成可替换适配器。

3. 为降低仿真到真机的差距，训练时随机化：

- 光照、纹理、物体位置；
- 相机位姿和延迟；
- 关节摩擦、控制延迟、动作噪声；
- 初始姿态及任务摆放。

4. S1 恢复后：

- 先低速空载验证关节映射；
- 采集少量真实 S1 数据；
- 用真机数据继续训练或微调；
- 不建议直接部署纯仿真策略执行接触任务。

### G1 可以做什么

G1 更适合用于验证与具体机器人无关的部分，例如：

- 数据采集程序和时间同步；
- 相机、语言指令、模型服务器通信；
- 急停、限速和状态机设计；
- 测试跨机器人统一接口；
- 专门研究跨本体迁移。

但如果在 G1 上训练策略，应将其视为一个**独立的 G1 实验分支**，不要默认其 checkpoint 或动作数据能迁移到 S1。

### 当前最合理的选择

```text
主线：S1 仿真 → ACT → SmolVLA → 少量 S1 真机数据微调
支线：G1 只验证通用软件链路或跨本体方案
```

如果只能二选一，我会选 **S1 本地仿真**。它产生的动作空间、接口设计和训练经验与最终目标一致；G1 虽然是真机，却很可能让你先解决一套之后无法直接复用的本体适配问题。

## 仿真对当前项目的价值

对你的“4317 箱体、H4 层、双臂拆垛”项目，Isaac Sim 很适合提前完成：

- 验证 S1 USD、关节名称、顺序、限位和坐标系；
- 验证双臂工作空间、预抓姿态和基本碰撞；
- 建立头部/腕部相机的数据接口；
- 生成 RGB、深度、点云、mask、6D 位姿真值；
- 调试 FoundationPose++ 前后的坐标变换；
- 调试 VLA 的输入、动作输出、限幅和状态机；
- 训练第一版 ACT/SmolVLA，验证整个训练部署链路；
- 重复制造不同箱体位置、光照和失败条件。

而以下内容不能仅凭仿真确认：

- GE103 实际夹持力、柔顺性、打滑和接触反馈；
- S1 绳驱机构的真实动力学；
- 箱体摩擦系数、形变、重心和负载摆动；
- 腕部相机真实标定误差、曝光和运动模糊；
- 深度相机在反光、遮挡、暗色表面上的空洞；
- SDK、网络、规划器和控制器的真实延迟。

所以，它非常有意义，但应建立成“最小可用仿真”，暂时不要追求整个 IE_lab 的完美复刻。

## 仿真数据能否用于真机

可以，不是只能在仿真中使用，但不同数据的迁移难度不同。

| 数据/能力 | 仿真价值 | 能否迁移真机 |
|---|---:|---|
| 关节名称、动作维度、坐标系 | 很高 | 可以直接复用接口设计 |
| FK/IK、工作空间、粗碰撞 | 很高 | 可以，但要用真机参数复核 |
| mask、目标框、6D 位姿真值 | 很高 | 适合训练感知模型 |
| RGB 图像 | 中等 | 需要外观随机化和真图微调 |
| 深度、点云几何 | 中高 | 需要加入噪声、空洞和标定误差 |
| ACT/SmolVLA 动作策略 | 中等 | 适合预训练，通常仍需真机微调 |
| 摩擦、夹持、箱体滑落 | 较低到中等 | 必须用真机校准 |
| 毫米级双臂接触精度 | 有限 | 不能由纯仿真证明 |

换句话说：

> 仿真最适合让策略“知道大致应该怎么做”，真机数据负责让策略“知道这台 S1 实际怎么做”。

## 相机和点云能仿真到多高精度

要区分两种精度。

### 1. 几何真值精度

这一项可以非常高。

Isaac Sim 能直接生成：

- RGB；
- 相机平面深度；
- 相机距离；
- 点云；
- 语义/实例分割；
- 法线；
- 运动向量；
- 2D/3D 边界框。

点云可以从深度和相机内参反投影得到，因此在仿真世界内部，箱体表面、相机位姿和点云坐标之间通常非常一致。[Isaac Sim 相机传感器文档](https://docs.isaacsim.omniverse.nvidia.com/latest/sensors/isaacsim_sensors_camera.html)

这种“过于干净”的数据很适合：

- 检查坐标变换；
- 训练分割、检测和姿态估计；
- 验证点云处理代码；
- 自动生成标签。

### 2. 真实传感器还原精度

默认情况下并不高，因为默认深度图通常接近理想真值。

Isaac Sim 可以进一步配置：

- 相机焦距、视场角、分辨率、畸变；
- 高斯噪声和 shot noise；
- 曝光、白平衡、颜色校正和 ISP；
- 立体或结构光深度传感器；
- 光照、材质、纹理和相机位置随机化。

官方也提供了深度传感器、ISP 和噪声处理接口。[深度传感器文档](https://docs.isaacsim.omniverse.nvidia.com/latest/sensors/isaacsim_sensors_camera_depth.html)

但以下现象仍很难完全复现：

- 反光或半透明箱体造成的错误深度；
- 近距离双臂遮挡；
- 自动曝光变化；
- 真实时间同步误差；
- 相机外参随振动产生的小幅漂移；
- 运动模糊、滚动快门；
- 深度飞点、多径和边缘空洞。

因此，仿真点云适合验证算法逻辑，却不能直接证明真机点云也能达到相同精度。

## 你的数据应该怎么采集

建议从一开始同时保留“策略需要的数据”和“调试需要的数据”。

每一帧建议记录：

```text
时间戳
任务语言，例如“抓取最上层 4317 箱体并放到卸货区”

观测：
- 头部 RGB
- 左腕 RGB
- 右腕 RGB
- 三路深度
- 可选点云
- 左右臂关节位置/速度
- 左右 TCP 位姿
- 夹爪状态
- 躯干与底盘状态

动作：
- 左 TCP 相对位姿增量
- 右 TCP 相对位姿增量
- 左右夹爪命令
- 可选躯干/底盘命令
- 实际执行后的关节目标

辅助真值：
- 箱体 6D 位姿
- mask
- 接触状态
- 抓取是否成功
- 当前任务阶段
```

对于 ACT 和 SmolVLA，标准输入通常还是 RGB、机器人状态和语言；深度、点云及物体真值可以作为感知链和调试信息保留，不需要一开始全部塞进 VLA。

动作空间建议优先采用：

```text
左右末端相对位姿 + 夹爪
            ↓
IMC/IK/安全控制层
            ↓
关节轨迹
```

这比让模型直接输出底层关节值更适合你的现有 IMC 架构，也更方便利用 Isaac Lab Mimic。官方说明 Mimic 主要依靠任务空间的末端动作来变换和扩充演示；关节动作需要先经 FK 转成任务空间。[Isaac Lab Mimic 文档](https://isaac-sim.github.io/IsaacLab/develop/source/overview/imitation-learning/teleop_imitation.html)

## 三种数据生成方式

### 1. 遥操作演示

可用：

- 键盘：用于最早验证；
- SpaceMouse：更适合平滑的末端控制；
- VR/XR：更适合双臂；
- 自己编写的双臂控制器。

Isaac Lab 会把演示保存成 HDF5。当前官方文档已经提供 Galbot 左臂夹爪堆叠任务的录制入口：

```text
IsaacContrib-Stack-Cube-Galbot-Left-Arm-Gripper-RmpFlow
```

这可以作为你接入 S1 的参考起点。[Isaac Teleop 官方文档](https://isaac-sim.github.io/IsaacLab/develop/source/features/isaac_teleop.html)

但它是左臂堆方块示例，并不是你的双臂拆垛工程。当前 Galbot 视觉遥操作示例也存在公开问题报告，因此应先验证所用 Isaac Lab 版本，不能默认整套功能已经稳定。[Isaac Lab Galbot 视觉任务问题](https://github.com/isaac-sim/IsaacLab/issues/6822)

### 2. 脚本或规划器生成

使用仿真中的箱体真值位姿，自动产生：

```text
预抓 → 接近 → 双臂夹持 → 抬升 → 移动 → 放置 → 撤离
```

优点是动作平滑、成功率高、生成速度快。缺点是策略可能只模仿理想规划器，缺少人的修正和异常恢复。

### 3. 少量演示加 Mimic 扩充

先采集少量高质量演示，再按以下阶段标注：

```text
接近
→ 双臂对齐
→ 夹紧
→ 抬升
→ 搬运
→ 放置
→ 松爪与撤离
```

Isaac Lab Mimic 可以改变箱体位置，并重新组合任务片段生成更多成功轨迹。官方明确支持多末端执行器，但双臂任务需要定义末端之间的阶段约束。[Isaac Lab Mimic 数据生成说明](https://isaac-sim.github.io/IsaacLab/develop/source/overview/imitation-learning/teleop_imitation.html)

## 必须做的随机化

仿真数据不能只使用一种固定画面。至少随机化：

- 箱体的 X/Y/偏航角和堆叠误差；
- 箱体尺寸、质量、重心和摩擦；
- 托盘及卸货台位置；
- 相机外参的小幅偏差；
- 光照方向、亮度和色温；
- 箱体、地面、托盘的纹理；
- RGB 噪声、曝光和模糊；
- 深度噪声、空洞、边缘飞点；
- 控制延迟和关节响应；
- 初始关节姿态。

Isaac Sim Replicator 原生支持对托盘、箱体、相机、灯光和材质进行随机化。[官方托盘随机化示例](https://docs.isaacsim.omniverse.nvidia.com/latest/replicator_tutorials/tutorial_replicator_ur10_palletizing.html)

随机范围必须来自真机测量。范围过小会过拟合仿真，范围过大则会生成不真实的数据。

## 最适合你的实施顺序

1. 运行官方 Galbot 单臂堆方块任务，确认 Isaac Lab、Galbot 模型、控制器和录制功能可用。
2. 对比官方 Isaac Lab Galbot 模型与你本地的 [S1 官方 USD](/home/lsy03/Lsy03_document/galbot_s1_SDK_learning/third_party/galbot_s1_description/usd/galbot_s1.usda)，核对关节、夹爪和模型版本。
3. 只建立“固定底盘＋双臂＋一个 4317 箱体＋腕部相机”的最小场景。
4. 先实现脚本抓取或遥操作成功，不急着训练。
5. 录制 10～20 条演示，检查时间同步、动作维度和回放。
6. 扩充箱体位置、光照、纹理和深度噪声，生成数百条仿真轨迹。
7. 转换为 LeRobotDataset，先训练 ACT 验证闭环。
8. S1 可用后，先采集静止 RGB-D 数据校准相机模型。
9. 再采集少量真实拆垛演示，对仿真预训练策略继续训练。
10. 真机只做低速、分阶段验证，不能直接运行纯仿真 checkpoint。

最终判断：**值得建立，但第一阶段的成功标准不是“仿真策略直接控制真机”，而是“仿真和真机共用同一套观测、动作、坐标系、数据格式和安全接口”。**做到这一点，即使纯仿真策略最后不能零样本迁移，前面的工程工作仍然不会浪费。

## 第一个验收目标


使用的官方任务是：
