# 四、当前技术路线共识

系统应采用分层架构，不让一个大模型包办全部功能：

用户指令
→ VLM/Agent 理解任务、选择目标、拆分步骤
→ 传统感知和几何模块计算物体位姿、抓取候选和工作位
→ 导航系统把机器人移动到操作区域
→ IK、碰撞检查、关节限位和可操作度检查
→ VLA 处理最后几十厘米的对准、接近、修正、夹紧和提起
→ 安全适配层检查动作
→ Galbot SDK/IMC 执行
→ 视觉或传感器验证结果

职责划分：

- VLM/Agent：语义理解、目标选择、技能编排；
- 传统导航：长距离移动、避障、到达工作站；
- 几何与运动学模块：可达性、IK、碰撞、抓取姿态、底盘工作位；
- VLA：局部、柔性的视觉闭环操作；
- 安全层：限速、限位、碰撞检查、超时、看门狗和急停。

不要让 VLM 直接凭视觉猜“底盘左移多少厘米”，也不要让未经安全检查的 VLA 动作直接控制真机。

# 五、如何判断是否已经处于可抓取位置

不要只判断机械臂“够不够得到”，而应综合评估：

- Reachability：抓取位姿是否可达；
- Visibility：目标和接触区域是否清楚可见；
- Collision margin：机械臂、环境和双臂之间是否有足够碰撞余量；
- Manipulability：是否远离奇异位形和关节极限；
- Grasp quality：抓取方向、接触面和稳定性是否合理。

基本流程：

目标检测与位姿估计
→ 生成候选抓取位姿
→ 检查 IK
→ 检查轨迹碰撞
→ 检查关节限位和可操作度
→ 检查视觉可见性
→ 评估抓取质量
→ 满足阈值则执行
→ 不满足则搜索新的底盘工作位并重新评估

应通过搜索多个候选底盘位姿，选择综合评分最高的位置，而不是由大模型随意给出运动距离。

# 六、单臂与双臂策略

单臂优先用于：

- 小而轻的物体；
- 单点夹持足够稳定的物体；
- 遮挡较少的场景；
- 第一阶段 VLA 实验。

双臂用于：

- 较宽、较重或需要托举的箱体；
- 单臂稳定性不足的情况；
- 需要左右两侧同步接触的操作。

第一版双臂系统不建议直接训练一个端到端双臂 VLA。优先采用：

物体位姿和尺寸
→ 生成左右抓取点
→ 双臂 IK
→ 同步轨迹规划
→ 同步接触和夹紧
→ 同步提起
→ 稳定性验证

双臂必须共享箱体目标，并维持左右末端相对于箱体以及彼此之间的约束。不要使用两个完全独立的 VLA 分别控制左右手。

后期具备足够双臂遥操作数据后，再考虑联合预测左右臂 action chunk 的双臂策略。

# 七、模型选择结论

目前建议的优先级：

1. ACT：工程基线；
2. SmolVLA：第一条正式 VLA 主线；
3. π0.5：第二阶段的大模型 VLA 研究；
4. LingBot-VLA 2.0：后期全身和双臂研究；
5. π0.7：等公开工具链和权重成熟后再评估。

模型定位：

## ACT

- 严格来说是视觉模仿学习策略，不是完整语言 VLA；
- 模型小、训练快、容易定位数据和控制问题；
- S1 自定义任务通常必须采集演示并训练；
- 适合先验证相机、状态、动作、数据集、训练和闭环部署。

## SmolVLA

- 输入可包含图像、机器人状态和语言；
- 可在一个数据集中使用语言区分多个简单任务；
- 在 S1 上仍然需要使用自己的数据微调；
- 适合 4090，是当前正式 VLA 主线。

## π0.5

- 需要完成 S1 observation/action 映射、归一化统计和数据转换；
- 适合采用主机策略服务器与机器人客户端分离的部署方式；
- 4090 更适合推理；
- 标准微调的资源和工程要求较高；
- 不要未经重新核实就把 LoRA 当成成熟可靠的正式训练路线。

## LingBot-VLA 2.0

- 更偏向双臂、腰、头和移动底盘的统一全身动作表示；
- 需要 Galbot S1 专用 Robot Config、动作映射、数据和后训练；
- 论文中的 Astribot S1 不是 Galbot S1；
- 公开权重不能直接控制 Galbot S1；
- 单卡 4090优先做加载、离线推理和接口研究，不作为第一条训练主线。

## π0.7

- 历史判断是公开训练与部署入口尚不成熟；
- 不能仅凭研究展示就假设可以在 Galbot S1 上直接使用；
- 该信息时效性较强，真正讨论部署时必须重新查询官方资料。

所有模型在 S1 上都绕不开：

相机与机器人状态采集
→ 数据格式转换
→ 动作空间映射
→ 模型训练或微调
→ 动作反归一化
→ 限速、限位、碰撞和超时检查
→ 真机执行
→ 成功与失败验证

“模型能直接推理”不等于“权重下载后就能直接控制 S1”。

# 八、推荐的第一个实验

第一项正式实验建议采用：

固定底盘、固定躯干、单臂、单个彩色方块取放到固定料盒。

第一版条件：

- 使用左臂和左夹爪；
- 底盘、升降柱和头部不参与控制；
- 一个颜色醒目的刚性方块；
- 一个固定托盘或料盒；
- 方块只在桌面有限区域内改变位置；
- 第一版以 RGB 和机器人状态为模型输入；
- 暂时不把深度或点云直接输入策略；
- 动作优先定义为末端相对位姿增量加夹爪命令；
- 动作经过 IMC/IK 与安全层后再执行。

建议阶段：

1. 机械臂移动到目标点；
2. 单方块抓取并抬升约 10cm；
3. 单方块完整取放；
4. 红蓝物体语言选择；
5. 不同物体放入不同容器；
6. 增加腕部相机、光照和位置变化；
7. 双臂抓箱并短距离抬升；
8. 抓取—导航—放置；
9. 完整拆垛。

数据起点：

- 先采集约 20 条高质量抓取抬升轨迹，验证录制和回放；
- 完整取放任务累计约 50～100 条成功轨迹；
- 覆盖不同初始位置；
- 保留约 20% 的未见初始条件用于测试；
- 语言选择任务可逐步扩展到约 150～300 条均衡轨迹。

每帧至少考虑记录：

- 时间戳；
- 场景 RGB；
- 腕部 RGB；
- 关节位置和速度；
- TCP 位姿；
- 夹爪状态；
- 模型动作；
- 实际发送给控制器的动作；
- episode、任务语言和成功标签。

深度、点云、物体真值、mask、接触状态等可以先作为调试和自动标注信息保存，不必立即作为 ACT/SmolVLA 输入。

# 九、仿真路线

Isaac Sim/Isaac Lab 对项目有意义，但定位是：

- 开发试验台；
- 接口验证环境；
- 数据生成与放大器；
- 感知和坐标变换调试工具；
- 动作与安全逻辑验证工具。

它不是可以完全代替真机的数字孪生。

推荐先运行官方 Galbot 左臂夹爪示例，再简化成单方块取放。历史讨论曾提到的官方任务名称为：

IsaacContrib-Stack-Cube-Galbot-Left-Arm-Gripper-RmpFlow

具体任务名称、Isaac Sim/Isaac Lab 版本和兼容关系属于时效性信息，实际安装前必须重新查官方文档，不要直接沿用旧版本建议。

仿真阶段建议依次验证：

1. Galbot 模型能稳定加载；
2. 关节名称、方向和限位正确；
3. 左臂可以控制；
4. 夹爪可以开合；
5. 方块接触正常；
6. 演示能够录制和回放；
7. 加入固定 RGB 相机；
8. 简化成单方块抓取；
9. 训练 ACT；
10. 再加入 SmolVLA、腕部相机、深度和随机化。

仿真数据可以用于：

- 验证接口、动作空间和坐标系；
- 训练基础视觉与动作能力；
- 生成 mask、6D 位姿和接触真值；
- 预训练 ACT/SmolVLA；
- 制造不同物体位置、光照和失败条件。

纯仿真无法可靠证明：

- 真实夹爪摩擦和夹持力；
- 箱体形变、滑落和重心变化；
- S1 实际动力学；
- 相机曝光、运动模糊和深度空洞；
- 网络、SDK和控制器真实延迟；
- 毫米级双臂接触精度。

正确路线是：

仿真打通接口和基本策略
→ 真机采集静态视觉数据并校准
→ 采集少量真机演示
→ 使用真机数据微调
→ 低速、分阶段部署

不要默认纯仿真 checkpoint 可以零样本安全控制真机。
