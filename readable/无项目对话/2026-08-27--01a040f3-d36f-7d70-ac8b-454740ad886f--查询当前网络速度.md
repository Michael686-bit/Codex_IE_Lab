## 1. 用户

有没有什么办法来查询一下现在的网速，因为现在我链接着实验室的wifi但是又有手机开了usb网络共享，我应该如何操作？

## 2. 助手

可以。你现在同时连着 Wi‑Fi 和 USB 网络共享，需要分别确认：

1. 系统当前默认走哪条网络；
2. 两条网络各自的实际网速。

如果你用的是 Linux，按下面操作。

### 1. 找出 Wi‑Fi 和 USB 网卡名称

```bash
ip -br addr
```

常见名称：

- Wi‑Fi：`wlan0`、`wlp2s0`
- USB 共享：`usb0`、`enx...`
- 有线网卡：`eth0`、`enp...`

也可以运行：

```bash
nmcli device status
```

### 2. 查看当前默认使用哪条网络

```bash
ip route | grep default
```

例如：

```text
default via 192.168.42.129 dev usb0 metric 100
default via 192.168.1.1 dev wlp2s0 metric 600
```

`metric` 越小，优先级越高。上面的情况表示系统优先通过 `usb0`，也就是手机 USB 网络共享。

查看访问公网时实际选择的网卡：

```bash
ip route get 1.1.1.1
```

输出中的 `dev xxx` 就是当前上网所用网卡。

### 3. 分别测试两条线路的网速

先安装 Ookla Speedtest，或者使用发行版提供的 `speedtest-cli`。然后尝试绑定网卡对应的本地 IP：

```bash
speedtest --source WiFi本地IP
speedtest --source USB本地IP
```

本地 IP 可以从 `ip -br addr` 中看到。例如：

```bash
speedtest --source 192.168.1.105
speedtest --source 192.168.42.20
```

如果使用的是 Python 版：

```bash
speedtest-cli --source 192.168.1.105
speedtest-cli --source 192.168.42.20
```

测试时最好一次只保留一条线路，以免系统路由导致结果不准确。最稳妥的办法是：

```bash
nmcli device disconnect usb0
# 测试实验室 Wi‑Fi

nmcli device connect usb0
nmcli device disconnect wlp2s0
# 测试手机 USB 共享

nmcli device connect wlp2s0
```

把其中网卡名换成你的实际名称。

### 4. 临时选择优先线路

让实验室 Wi‑Fi 优先：

```bash
sudo ip route replace default via WiFi网关 dev WiFi网卡 metric 50
```

让 USB 网络优先：

```bash
sudo ip route replace default via USB网关 dev USB网卡 metric 50
```

不过这种修改通常重连后失效。更适合使用 NetworkManager 永久设置：

```bash
nmcli connection show
nmcli connection modify "WiFi连接名称" ipv4.route-metric 100
nmcli connection modify "USB连接名称" ipv4.route-metric 200
nmcli connection up "WiFi连接名称"
```

数值较小的连接优先。

如果只是想快速判断，我建议依次运行这三个命令：

```bash
nmcli device status
ip route get 1.1.1.1
ip -br addr
```

它们能告诉你两个网卡叫什么、当前实际上走哪一个，以及各自的 IP 地址。

## 3. 用户

如果我想让codex桌面版优先走我的usb网络共享，因为实验室的robot网络是不通的无法使用codex，使用数量较小的链接优先是否有效？

## 4. 助手（进展）

我会用 Codex/OpenAI 产品说明核对桌面版的联网行为，再给你一个不会误伤实验室局域网访问的路由方案。这里关键是“只让 Codex 走 USB”与“所有公网流量优先走 USB”是两种不同配置。

## 5. 助手

有效——如果你说的是路由的 `metric` 数值，越小优先级越高。不过这会让所有公网流量优先走 USB，并非只影响 Codex。

你的场景更推荐：

- 实验室 `robot` Wi‑Fi：只访问实验室局域网；
- 手机 USB：承担默认公网流量，包括 Codex；
- 局域网仍会自动走 Wi‑Fi，因为局域网路由比默认路由更具体。

先查看连接名称：

```bash
nmcli -f NAME,TYPE,DEVICE connection show --active
```

假设连接名称分别是 `robot` 和 `USB tethering`，可以执行：

```bash
sudo nmcli connection modify "USB tethering" \
  ipv4.never-default no ipv4.route-metric 50 \
  ipv6.never-default no ipv6.route-metric 50

sudo nmcli connection modify "robot" \
  ipv4.never-default yes \
  ipv6.never-default yes
```

然后重新激活连接：

```bash
sudo nmcli connection down "robot"
sudo nmcli connection up "robot"

sudo nmcli connection down "USB tethering"
sudo nmcli connection up "USB tethering"
```

注意：远程连接机器时不要直接执行断网命令。

验证公网是否走 USB：

```bash
ip route get 1.1.1.1
```

输出应包含 USB 网卡，例如：

```text
1.1.1.1 via 192.168.42.129 dev enx123456...
```

再确认实验室地址仍走 Wi‑Fi：

```bash
ip route get 实验室设备IP
```

这里应显示 Wi‑Fi 网卡，例如 `wlp...`。

如果你只想调整优先级、不彻底禁止 robot 成为默认网络，也可以设置：

```bash
sudo nmcli connection modify "USB tethering" ipv4.route-metric 50 ipv6.route-metric 50
sudo nmcli connection modify "robot" ipv4.route-metric 600 ipv6.route-metric 600
```

但对于“robot 明确不能联网”的情况，`robot` 设置 `never-default yes` 更稳，避免断开、重连或 IPv6 时 Codex又误走 Wi‑Fi。修改后最好完全退出并重新打开 Codex，让已有网络连接重新建立。Codex 桌面版目前没有常规的“指定网卡”选项，因此通过系统路由处理最合适。
