## GitHub 私仓怎么存最合适

建议建立一个单独的私仓，例如：

```text
codex-chat-archive/
├── README.md
├── catalog/
│   ├── projects.yml
│   └── threads.csv
├── readable/
│   ├── s1/
│   │   └── 2026-09-05--分析ICP替代箱体6D流程.md
│   ├── vla-g1/
│   ├── synthnova/
│   └── projectless/
├── checksums/
└── tools/
    └── export-and-redact.py
```

每条 Markdown 建议只保留：

- 标题、日期、项目名、归档状态；
- 用户问题；
- 助手最终答复；
- 必要的结果摘要和文件链接。

默认删除：

- system/developer 指令和推理过程；
- 工具调用原始输出、终端日志和完整 diff；
- 密码、API Key、OAuth Token、SSH 私钥；
- 内网 IP、用户名、绝对路径等敏感信息；
- 不必要的附件。

绝不能提交，即使仓库是私有的：

```text
~/.codex/auth.json
*.sqlite*
未脱敏的 *.jsonl
shell_snapshots/
logs_*.sqlite*
Cookies
Login Data
.env*
*.pem
*.key
SSH 私钥
```

本机整个 `~/.codex` 约 1.2 GB，对话及核心状态约 192 MB，其中包含登录令牌、命令输出、补丁、附件引用和项目路径。私仓不是端到端加密保险箱。

## 推荐的“双份备份”

1. 可检索版本：脱敏 Markdown 放 GitHub 私仓。另一台电脑克隆后，可以直接阅读、搜索，也可以让 Codex读取这些资料。

2. 完整版本：原始 JSONL、数据库和附件先在本地用 GPG/age 加密，再把密文放到私有云盘或 GitHub Release。密文用于灾难恢复，但不能在线搜索。

需要注意：Markdown 能保存和调取知识，但不能在另一台电脑上恢复成原来的原生 Codex 侧边栏对话。若要继续原对话，官方支持的办法是 [Remote/SSH 或主机间 handoff](https://learn.chatgpt.com/docs/remote-connections)；Codex Cloud 则适合今后从 GitHub/GitLab 创建新的云端任务，并不是旧本地对话的一键导入工具。[Codex 云端说明](https://learn.chatgpt.com/zh-Hans/docs/cloud)
