## 1. 用户

不必须使用 SynthNova 容器或仿真软件。

实际链路是：

```text
GP001 → USB 串口 /dev/ttyACM0 → 协议解析程序 → 主臂角度和时间戳
                                      ↓
                              SynthNova 只是数据使用方
```

真正必需的是：

- Linux 能识别 `/dev/ttyACM0`
- 程序有串口读写权限
- 有 GP001 协议解析器，例如 `remote_control_lite`
- 知道时间戳和关节字段的定义

SynthNova 容器只是已经准备好了驱动、依赖、授权环境和示例，因此目前最方便。若在宿主机安装并授权 `remote_control_lite`，同样可以直接读取：

```python
import queue
from remote_control_lite import GalbotDriver, QueueSink

sink = QueueSink(maxsize=16)
driver = GalbotDriver(robot="golf", port="/dev/ttyACM0")
driver.attach_sink(sink)

with driver:
    while True:
        frame = sink.get(timeout=1.0)
        print("timestamp:", frame["timestamp"])
        print("left arm:", frame["joint_states"]["left_arm"]["position"])
        print("right arm:", frame["joint_states"]["right_arm"]["position"])
```

但如果宿主机没有 `remote_control_lite`，只有直接读取串口的 Python 库，也只能拿到二进制原始数据；还需要厂商提供的通信协议才能正确解析，不能随便猜波特率或数据格式。

另外，当前输出中的 `timestamp` 很可能是设备或数据流的相对时间，不一定是电脑的日期时间。做数采同步时，建议同时记录电脑接收时刻 `time.monotonic_ns()`。

## 29. 助手

`usermod -aG dialout lsy03` 是把用户 `lsy03` 加入 Linux 的串口设备组 `dialout`。

原因是当前设备权限为：

```text
/dev/ttyACM0  root:dialout  0660
```

只有 root 和 `dialout` 组成员能读写，而 `lsy03` 当前不在该组。

参数含义：

- `-G dialout`：加入附加组 `dialout`
- `-a`：追加，不删除你现有的其他用户组
- 不会安装 SynthNova、修改密码或赋予完整 root 权限

安全影响是：以后以 `lsy03` 运行的程序都可以访问归属 `dialout` 的串口设备。可用以下命令撤销：

```bash
sudo gpasswd -d lsy03 dialout
```

目前这项修改没有成功执行，所以系统没有变化。

如果只想做一次测试，也可改用针对当前 `/dev/ttyACM0` 的临时 ACL，设备重插后自动失效；如果以后长期读取 GP001，加入 `dialout` 是 Linux 上更常见的做法。

串口打开、协议解析和日志写入全部运行在宿主机，没有使用 `docker exec`。不过本次授权值是从现有容器元数据中临时注入内存的；如果要求连 Docker 元数据也完全不依赖，还需把当前有效的 ENCMGR 凭据安全配置到宿主机。交付脚本里原有的旧凭据已经失效。

新登录的终端会自动获得 `dialout` 权限；当前旧终端可用 `newgrp dialout` 刷新组权限。
